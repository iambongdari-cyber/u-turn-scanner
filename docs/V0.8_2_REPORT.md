## 2. `sector_flow.ts` 설명

### 2-1. `scoreSector(s: SectorGroupRaw): number`
사용자 명세 §3 그대로:

```ts
let score = 0;

// 20일 수익률 (최대 35)
if (sector_20d_return) score += min(35, max(0, sector_20d_return * 0.7));

// 시장 대비 상대강도 (최대 30)
if (market_relative_strength) score += min(30, max(0, market_relative_strength * 0.5));

// 거래대금 합계 (최대 20) — leaders + followers + opportunities
const totalValue = allStocks.reduce(sum + value_20d_eok);
score += min(20, totalValue / 50);

// 후보 종목 수 (최대 15)
score += min(15, allStocks.length * 3);

// 추격 위험 감점
if (chase_risk.length > 0) score -= 15;

return clamp(0, 100);
```

### 2-2. `judgeSectorFlow()` 메인 흐름
1. 입력 `sectors_strong[]` 점수 정렬 → 상위 3 개 = `topThree`
2. 주도 업종 선정 (사용자 명세 §4):
   - TOP 1 + score ≥ 70 + 후보 종목 ≥ 3 + 거래대금 합계 ≥ 50억
   - 만족 시 `leadingSector` 설정, 미만족 시 `null`
3. TOP 3 업종마다 대장주 추출 (leaders 우선, 비면 fallback)
4. narrative 자동 생성

### 2-3. 대장주 추출 — TRUE_LEADER vs QUASI_LEADER

```ts
function extractLeaders(s, label): LeaderStock[] {
  const leaders = (s.leaders ?? []).map(m => ({ raw: m, source: 'TRUE_LEADER' }));

  // leaders 비어있으면 followers + opportunities 에서 leadership ≥ 60 fallback
  const pool = leaders.length > 0
    ? leaders
    : [...s.followers, ...s.opportunities].map(m => ({ raw: m, source: 'QUASI_LEADER' }));

  // QUASI_LEADER 는 leadership 60 이상만 통과
  return pool
    .map(p => ({ ...p, leadershipScore: scoreLeaderStock(p.raw) }))
    .filter(p => p.source === 'TRUE_LEADER' || p.leadershipScore >= 60)
    .sort((a, b) => b.leadershipScore - a.leadershipScore)
    .slice(0, 3);
}
```

호스트 데이터는 leaders 가 모두 비어있는 상태가 발견됐기 때문에, QUASI_LEADER fallback 으로 자연스럽게 후보를 보충.

## 3. `sector_names.ts` 설명

### 3-1. 매핑 전략 (사용자 명세 §5)

```ts
export const SECTOR_NAME_MAP: Record<string, string> = {
  '반도체': '반도체',
  '자동차': '자동차',
  '금융': '금융',
  // ... 시장에서 자주 쓰는 30 개 등록
};

export function getSectorLabel(sector): string {
  if (!sector) return '업종명 확인 필요';
  const mapped = SECTOR_NAME_MAP[sector];
  if (mapped) return mapped;
  if (/^\d+$/.test(sector)) return `업종 코드 ${sector}`;  // 숫자 코드 보수적
  return sector;  // 한국어 등 비매핑 텍스트는 그대로
}
```

### 3-2. 호스트 데이터 대응
호스트 사이드카에서 sector 값이 `"14"`, `"33"`, `"32"` 같은 숫자 코드. 사용자가 정확한 매핑을 확정하기 전까지는 `"업종 코드 14"` 로 보수적 표시. **잘못된 업종명 추정 금지** (사용자 명세 §5).

향후 사용자가 매핑을 확인하면:
```ts
'14': '의류·신발',  // 예시 — 사용자 검증 후 등록
```
같은 형식으로 `SECTOR_NAME_MAP` 에 추가하면 즉시 화면에 한국어 노출.

### 3-3. `isSectorUnmapped()`
숫자 코드인데 매핑 미등록 → `true`. UI 안내 "※ 업종 데이터가 충분하지 않거나 매핑이 미등록되어 보수적으로 표시합니다." 노출에 활용.

## 4. 대장주 판단 방식

### 4-1. 우선순위
1. **TRUE_LEADER**: `sectors_strong[].leaders[]` 의 종목 그대로 (사이드카가 이미 대장주로 판단함)
2. **QUASI_LEADER fallback**: leaders 비어있으면 `followers + opportunities` 중 leadership 점수 ≥ 60

### 4-2. `scoreLeaderStock()` 가중치 (사용자 명세 §6)

| 조건 | 가점/감점 |
|---|---|
| `value_20d_eok ≥ 100` | +30 |
| `value_20d_eok ≥ 50` | +20 |
| `value_20d_eok < 50` | +10 |
| `return_20d 5~30` (적정 상승) | +25 |
| `return_20d > 30` (과열) | +10 |
| `above_ma60 === true` | +15 |
| `near_high_pct ≥ 80` | +15 |
| **`disparity_pct ≥ 20`** (추격 위험) | **-25** |

→ 거래대금이 가장 큰 비중. 적정 상승은 보너스, 과열은 페널티. 추격 위험은 큰 감점.

### 4-3. 호스트 데이터 시나리오
- sector "14" (return 81.4 / rel 85.9) — leaders 0, followers 1 (노브랜드 — leadership 점수 약 50 ~ 60)
- noble brand 의 leadership 60 미만이면 QUASI_LEADER 도 통과 못함 → 대장주 0건 → "오늘 업종별 대장주를 특정하기 어렵습니다."
