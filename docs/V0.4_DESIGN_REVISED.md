## 2. 3분류 명칭 변경안

| # | 신규 명칭 | 의미 | 호스트 매핑 | 호스트 수량 |
|---|---|---|---|---|
| ① | **바닥 U턴 후보** | 크게 하락 → 바닥권에서 U턴 5조건 충족 | `scan_dump.candidates_bottom[]` | 340개 |
| ② | **현재 주도주** | 시장에서 강한 흐름, 거래대금 유지 → **시장 흐름 확인용** | `sector_dump.sectors_strong[].leaders[]` | 2개 (부족 안내) |

### 명칭 변경 이유
- **"바닥 U턴 후보"**: U-Turn Scanner 의 핵심. "반등"보다 "U턴"이 도구의 정체성과 일치.
- **"후발 강세 후보"**: "다음 주도주"는 새 테마 발굴 의미가 있어 오해 소지. 본 카테고리는 **현재 강한 섹터 안의 후발주** 만을 의미.

## 3. 바닥 U턴 5조건 표시 설계

### 3-1. 코드 식별 결과 (read-only)

`scan_dump.candidates_bottom[].checks` 에 **7개 키**가 이미 존재 (스크립트 read-only 확인):

| 키 | 의미 | scan_dump 표시 가능 |
|---|---|---|
| `uturn_ok` | 60일 중 ma60 아래 머문 일수 ≥ 임계 (충분히 하락 + 바닥 머무름) | ✓ |
| `above_ma60` | 종가가 60일선 위로 회복 | ✓ |
| `value_recovering` | 거래대금 회복 (value_ratio ≥ 임계) | ✓ |
| `value_ok` | 평균 거래대금 절대 임계 충족 | ✓ |
| `ma60_rising` | 60일선 자체가 상승 추세 | ✓ |
| `lagging_ok` | 후행 지표 (일목 등) 충족 | ✓ (참고용) |
| `cloud_red` | 일목 양운 | ✓ (참고용) |

→ **`run_scan.py` 무수정** + **사이드카 JSON 무변경** 으로 5조건 표시 가능.

### 3-2. 사용자 명세 "U턴 5조건" → 코드 7개 중 5개 선별

| # | 사용자 명세 표현 | 코드 매핑 | 초보자 표시 라벨 |
|---|---|---|---|
| 1 | 충분한 하락 | `uturn_ok` | "충분한 하락 + 바닥 머무름" |
| 2 | 바닥권 횡보 | (포함) `uturn_ok` 의 일부 — `days_below_ma60_60d ≥ 임계` | (1번과 통합) |
| 3 | 거래량 증가 | `value_recovering` (value_ratio ≥ 1.5) | "거래량 회복" |
| 4 | 거래대금 증가 | `value_ok` (절대 거래대금 임계) | "거래대금 임계 충족" |
| 5 | 이평선 회복 | `above_ma60` AND/OR `ma60_rising` | "60일선 위로 회복" |

#### 보완: 5조건 매핑 (helper 함수로 깔끔하게)
```ts
// app/_lib/beginner.ts 안에 정의 (코드 작업 시점)
type UTurnCheck = 'DROP_AND_BASE' | 'MA60_RECOVER' | 'VOLUME_RECOVER' | 'VALUE_LEVEL_OK' | 'MA60_RISING';

interface UTurnConditions {
  total: 5;
  checks: Array<{
    key: UTurnCheck;
    label: string;      // 사용자 노출용
    met: boolean;
    note?: string;      // 미충족 시 짧은 사유
  }>;
  met_count: number;    // 5 중 충족 개수
}

function evaluateUTurnConditions(scan: ScanCandidate): UTurnConditions {
  return {
    total: 5,
    checks: [
      { key: 'DROP_AND_BASE',     label: '충분한 하락 + 바닥 머무름',  met: !!scan.checks?.uturn_ok },
      { key: 'MA60_RECOVER',      label: '60일선 위로 회복',           met: !!scan.checks?.above_ma60 },
      { key: 'VOLUME_RECOVER',    label: '거래량 회복',                 met: !!scan.checks?.value_recovering },
      { key: 'VALUE_LEVEL_OK',    label: '거래대금 임계 충족',          met: !!scan.checks?.value_ok },
      { key: 'MA60_RISING',       label: '60일선 추세 상향',            met: !!scan.checks?.ma60_rising },
    ],
    met_count: ['uturn_ok','above_ma60','value_recovering','value_ok','ma60_rising']
      .filter(k => !!scan.checks?.[k as keyof typeof scan.checks]).length,
  };
}
```

## 4. 현재 주도주 역할 재정의

### 4-1. 의미 전환
| 기존 v0.4 1차 설계 | 보완안 |
|---|---|
| "신규 매수 검토" 뉘앙스 (보유 권유에 가까움) | **"시장 흐름 확인" 위주** |

### 4-2. 사용자 노출 카드 설명 (사용자 명세 그대로)
> "현재 시장에서 강한 흐름을 보이는 종목입니다. 다만 이미 많이 오른 경우 신규 진입보다 **시장 방향 확인용**으로 보는 것이 안전합니다."

### 4-3. 카드 안 강조 추가
| 위치 | 문구 |
|---|---|
| 카테고리 헤더 | "🏆 현재 주도주 — **시장 흐름 확인용**" |
| 카드 안 (이미 많이 오른 경우 disparity > 15%) | "⚠️ 이미 많이 올라 추격 매수 주의 — 시장 방향만 참고" |
| AI 행동 매핑 (보완) | disparity ≤ 15% → **보유** / 15~20% → **관찰** / >20% (chase_risk) → **일부매도 검토** / **신규 진입은 모든 경우에서 비추천** (안내 노출) |

### 4-4. 초보자 행동 가이드 (현재 주도주용)
```
□ 신규 매수보다 시장 방향 확인용
□ 보유 중이면 추세 유지 점검
□ 이미 많이 올랐다면 분할 차익 검토
□ 추격매수 금지
```

## 5. 후발 강세 후보 정의

### 5-1. 정확한 정의
- **현재 주도 섹터(`sector_dump.sectors_strong[]`) 안의 후발주**
- 주도주를 따라가지만 아직 전고점 도달 전인 종목
- **"새로운 주도 테마 발굴"이 아님** (그건 v0.5+ "신규 주도주 후보" 별도 과제)

### 5-2. 매핑 (보완)
- 1차: `sector_dump.sectors_strong[].followers[]`
- 2차 보강: 같은 섹터의 `opportunities[]` 중 `near_high_pct ≥ 70%` 인 종목 (정렬에서 후순위)

### 5-3. 카드 설명 (사용자 명세 그대로)
> "현재 강한 섹터 안에서 아직 상대적으로 덜 오른 종목입니다. 거래량이 늘고 있어 후발 수급 가능성을 관찰할 수 있습니다. 단, 주도주를 따라가지 못하면 힘이 약해질 수 있습니다."

### 5-4. AI 행동 매핑 (보완)
| 상태 | 행동 |
|---|---|
| followers + 거래량 회복 | **관찰** |
| followers + `near_high_pct ≥ 90%` | **분할매수 검토** |
| 주도주 약화 시 | **관찰 → 검토 재평가** |

## 6. 신규 주도주 후보를 v0.5+ 로 분리하는 이유

### 6-1. 정의의 차이
| 항목 | 후발 강세 후보 (v0.4) | 신규 주도주 후보 (v0.5+ 연구) |
|---|---|---|
| 데이터 출처 | 현재 강한 섹터 내 종목만 | 섹터 무관 |
| 신호 | 동일 섹터 동조 | 새 테마 발생 (자금 이동 감지) |
| 분석 난이도 | 낮음 (기존 사이드카로 가능) | 높음 (뉴스 / 검색량 / 미디어 반응 필요) |
| 사이드카 충분성 | 충분 (sectors_strong) | **부족** (현재 사이드카에 미디어/뉴스 지수 부재) |
| 구현 위험 | 낮음 | 중상 (외부 데이터 fetch 필요) |

### 6-2. v0.5+ 별도 연구 과제 로드맵
**v0.5+ 신규 주도주 후보 연구 (사용자 명세 그대로)**
- 새로운 업종/테마 거래대금 증가
- 같은 테마 내 여러 종목 동시 상승
- 뉴스/검색/미디어 반응 증가
- 기존 주도 섹터와 다른 자금 이동 감지

→ 별도 보고서 (`docs/V0.5_NEW_LEADER_RESEARCH.md`) 작성 예정. v0.4에서는 **구현하지 않음**.

## 8. 초보자 행동 가이드 설계

### 8-1. AI 행동별 체크리스트 (사용자 명세 그대로)

| AI 행동 | 초보자 행동 체크리스트 |
|---|---|
| **관찰** | □ 오늘 매수하지 않음 / □ 관심종목 등록 / □ 3일 후 다시 확인 |
| **분할매수 검토** | □ 투자금 일부만 검토 / □ 몰빵 금지 / □ 손절 기준 먼저 설정 |
| **보유** | □ 추가매수 서두르지 않기 / □ 추세 유지 확인 / □ 주말에 다시 점검 |
| **일부매도 검토** | □ 일부 차익실현 검토 / □ 남은 수량 추세 확인 |
| **매도 검토** | □ 보유 이유 재점검 / □ 손실 확대 방지 우선 |
| **제외** | □ 관심종목 해제 / □ 다른 후보로 시선 이동 |

### 8-2. 카드 표시 위치
"왜 뽑혔나?" 다음, "주의 문구" 위.

### 8-3. UI 디자인
- 체크박스는 **시각적 (interactive 가능 — `<input type="checkbox">` 단순 폼)**
- 체크 상태는 **localStorage 저장** (사용자 진행 상황 기억)
- 체크 상태는 가상 관심종목/매수 기록과 무관 (단순 체크리스트)

### 8-4. 헬퍼 함수
```ts
// app/_lib/beginner.ts
function buildBeginnerChecklist(action: ActionRecommend): string[] {
  switch (action) {
    case 'WATCH':         return ['오늘 매수하지 않음', '관심종목 등록', '3일 후 다시 확인'];
    case 'BUY_SPLIT':     return ['투자금 일부만 검토', '몰빵 금지', '손절 기준 먼저 설정'];
    case 'HOLD':          return ['추가매수 서두르지 않기', '추세 유지 확인', '주말에 다시 점검'];
    case 'PARTIAL_SELL':  return ['일부 차익실현 검토', '남은 수량 추세 확인'];
    case 'SELL':          return ['보유 이유 재점검', '손실 확대 방지 우선'];
    case 'EXCLUDE':       return ['관심종목 해제', '다른 후보로 시선 이동'];
  }
}
```

## 14. 주의사항

### 14-1. 자동매매 / 실제 주문 절대 금지 (사용자 명세 절대 보호)
- 키움 API 호출 0건
- Supabase write 0건 (v0.4 단계)
- 모든 가상 매매 기능은 **localStorage 클라이언트 측만** — 실제 매매와 분리 명확
- 가상 매수 버튼 안내: "이 기록은 실제 매매가 아닙니다. U턴 스캐너 판단을 검증하기 위한 모의 기록입니다."

### 14-2. 매수 추천 표현 절대 금지
- "분할매수 검토", "보유" 등 행동 제안은 **참고 의견** 명시
- "최종 판단은 사용자 본인" 항상 동반
- 위험도 '높음' 카드는 "관찰 우선" 강조

### 14-3. 카드 안 안전 안내 3중 노출 (v0.4 1차 설계 §10-2 그대로)
1. 화면 헤더: "초보자 모드는 매수/매도 추천이 아닙니다."
2. 카드 안: "이 의견은 자동 분석 결과이며 실제 투자 판단은 사용자가 최종 결정해야 합니다."
3. 가상 버튼 옆: "이 기록은 실제 매매가 아닙니다."

### 14-4. localStorage 한계 명시
- 카드 안에 작게: "가상 기록은 이 브라우저에만 저장됩니다. 브라우저 변경 시 사라질 수 있습니다."
- v0.5+ 영구 저장 옵션 검토 예정

### 14-5. U턴 5조건의 임계값
- `uturn_ok`, `value_recovering`, `value_ok` 등의 임계값은 `run_scan.py` 가 결정 (보호 파일).
- 본 헬퍼는 **이미 계산된 boolean 값만 표시** — 임계값 변경 0건.

### 14-6. 카테고리 중복 회피
- 같은 종목이 ② 현재 주도주 (leaders) 와 ③ 후발 강세 후보 (followers) 양쪽에 잡힐 가능성 → followers 정렬에서 leaders 중복 제외 (간단한 Set)
- 같은 종목이 ① 바닥 U턴 후보 (candidates_bottom) 와 ② 현재 주도주 (leaders) 양쪽에 잡힐 가능성 → ② 우선 (강한 신호 우선)
- 우선순위: ② → ③ → ① (이미 강한 신호가 있으면 그쪽 카테고리)

### 14-7. 호스트 데이터 부족 케이스 (사용자 안내 강화)
- ② 현재 주도주 = 2개 (오늘) → "오늘 강한 주도주 후보 부족" 안내 + 가능한 만큼 표시
- 카테고리별 0건 → "오늘 해당 후보 부족 — 다른 카테고리 또는 내일 다시 확인"

### 14-8. SSR/CSR 경계
- `VirtualWatchButton` / `VirtualBuyButton` / `BeginnerChecklist` 는 `'use client'`
- 카드 본체 (`CategoryCard`)는 서버 컴포넌트로 두고, 인터랙티브 부분만 client 컴포넌트로 분리
- localStorage 접근은 `useEffect` 안에서만 (SSR 안전)
