## 3. 오늘의 AI 추천 관찰 종목 1개 설계 ("오늘 딱 하나만 본다면?")

### 3-1. 위치
초보자 모드 화면 **놓친 리포트 박스 다음**, 3 카테고리 섹션 위.

### 3-2. 선정 로직 — 안전 우선

```ts
function pickTodayTopOne(
  pool: {
    bottom: CategoryRow[];   // 바닥 U턴 후보 (≤3)
    leader: CategoryRow[];    // 현재 주도주 (≤3)
    follower: CategoryRow[];  // 후발 강세 후보 (≤3)
  },
): CategoryRow | null {
  // 1순위: 현재 주도주 중 위험도 '낮음' (안전 최우선)
  const safeLeader = pool.leader.find(r => r.risk === 'LOW');
  if (safeLeader) return safeLeader;

  // 2순위: 후발 강세 후보 중 위험도 '낮음' (없으면 '보통')
  const safeFollower = pool.follower.find(r => r.risk === 'LOW')
                    ?? pool.follower.find(r => r.risk === 'MEDIUM');
  if (safeFollower) return safeFollower;

  // 3순위: 바닥 U턴 후보 중 U턴 5조건 충족도 가장 높은 종목 (5/5 우선)
  const bottomByConditions = [...pool.bottom].sort(
    (a, b) => (b.uturn_conditions?.met_count ?? 0) - (a.uturn_conditions?.met_count ?? 0)
  );
  if (bottomByConditions[0]) return bottomByConditions[0];

  return null;
}
```

#### 우선순위 정당화
| 순위 | 카테고리 | 이유 |
|---|---|---|
| 1 | 현재 주도주 (위험도 낮음) | 시장 흐름 확인용 — 가장 안전. 신규 매수 권유 아님. |
| 2 | 후발 강세 후보 (위험도 낮~보통) | 주도주 따라가는 종목 — 진입 여유 있음 |
| 3 | 바닥 U턴 후보 (5조건 최다 충족) | 가장 위험하지만 5조건 충족도 높을수록 신호 명확 |

## 5. 사용자 확인일 저장 (localStorage)

### 5-1. localStorage key
```
uturn_last_viewed_report_date
```
값 형식: `YYYY-MM-DD` (ISO 날짜)

### 5-2. 갱신 시점
| 트리거 | 동작 |
|---|---|
| 사용자가 `/beginner` 진입 | **갱신 안 함** (사용자 명세는 "들어오거나 누르면"이지만, 자동 갱신 시 놓친 리포트 박스가 안 보임 — 사용자 의식적 누름이 더 명확) |
| **"확인 완료" 버튼 클릭** | **localStorage 값을 오늘 날짜로 갱신** |

> **설계 결정**: 사용자 명세는 "들어오거나 누르면"이지만, **누를 때만 갱신**하는 게 안전. 자동 갱신 시 "들어왔을 뿐인데 어제 리포트가 사라짐" 사용자 혼란 가능. 보고서에 명시.

### 5-3. 헬퍼 함수
```ts
// app/_lib/virtual_storage.ts (1차 보완에서 신규)
function readLastViewedDate(): string | null;
function saveLastViewedDate(date: string): void;
```

서버에서는 cookie/header 미사용 — 서버 컴포넌트는 last viewed date 를 **모르고 시작**.
client 컴포넌트 `<MissedReportsBox />` 가 useEffect 안에서 localStorage 읽어 prop 으로 전달.

### 5-4. SSR/CSR 경계 처리
```tsx
// 서버 컴포넌트: 모든 daily 스냅샷 요약을 미리 계산
// 클라이언트 컴포넌트: localStorage 읽고 필터링 → "놓친" 만 표시
```

→ 모든 날짜의 요약을 미리 서버에서 계산하고, 클라이언트는 localStorage 의 `lastViewedDate` 와 비교해 표시만.

- 버튼 표시가 "✓ 오늘 확인 완료됨 ([오늘 날짜])" 으로 변경
- 페이지 새로고침 시 놓친 리포트 박스 미렌더 (마지막 확인일 = 오늘)

### 6-4. 헬퍼 함수
```ts
// app/_lib/virtual_storage.ts
function markTodayAsViewed(): void {
  const todayKst = todayKstISO();
  localStorage.setItem('uturn_last_viewed_report_date', todayKst);
}

function todayKstISO(): string {
  const now = new Date();
  const kst = new Date(now.getTime() + 9 * 60 * 60 * 1000);
  return kst.toISOString().slice(0, 10);
}
```

- 누른 직후 2초간 "✓ 저장됨" 텍스트 변경
- 그 후 "확인 완료됨 ([오늘])" 으로 유지

## 10. 주의사항

### 10-1. 자동매매 / 실제 주문 절대 금지 (사용자 명세 절대 보호)
- 키움 API 호출 0건
- Supabase write 0건 (v0.4 단계)
- 모든 가상 기능 (관심종목 / 매수 / 확인일) = **localStorage 클라이언트 측만**
- GPT 복사 기능은 **단순 문서화** — 실제 매매 트리거 0건

### 10-2. 마크다운 복사 보안
- 클립보드 접근은 `'use client'` + `navigator.clipboard.writeText` 만
- 사용자가 명시적으로 버튼을 눌러야 동작 (자동 복사 0건)
- 마크다운에 민감 정보 (DB credentials 등) 포함 0건

### 10-3. 안전 안내 4중 노출 (1차 보완 §10-2 + 본 보완)
1. 화면 헤더: "초보자 모드는 매수/매도 추천이 아닙니다."
2. 카드 안: "이 의견은 자동 분석 결과..."
3. 가상 버튼 옆: "이 기록은 실제 매매가 아닙니다."
4. **GPT 마크다운 꼬리표**: "이 리포트는 자동 분석 결과... 최종 판단은 사용자 본인이 합니다."

### 10-4. localStorage 한계 명시
- 카드 안 작은 글씨: "가상 기록·확인일은 이 브라우저에만 저장됩니다."
- 다중 디바이스 사용자는 v0.5 Supabase 활성화 안내

### 10-5. SSR 안전
- `localStorage` 접근은 모두 client 컴포넌트 + `useEffect` 안
- 서버 컴포넌트는 모든 가능한 요약을 미리 계산 → 클라이언트가 필터링만

### 10-6. 놓친 리포트 graceful
- daily 폴더 부재 → 박스 자체 미렌더
- 첫 사용 (lastViewedDate = null) → "오늘이 첫 사용입니다" 안내
- 마지막 확인일 = 오늘 → 박스 미렌더
- 한쪽 데이터(scan or sector)만 있는 날 → 가능한 만큼 + 안내

### 10-7. 오늘 1픽 graceful
- 모든 카테고리 부족 → "오늘 추천할 종목이 부족합니다" + 3 카테고리 섹션은 표시
- 위험도 '낮음' 0건 → '보통' 폴백 → '높음' 폴백 (이때는 강조 안내)

### 10-8. 데이터 신선도
- daily 폴더 파일이 오래된 경우 (예: 1주 전) → 사용자가 의식적으로 archive 실행 안내
- v0.3-4 의 SidecarFreshnessBox 와 연계 가능 (홈에서 이미 표시 중)
