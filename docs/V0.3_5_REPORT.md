# U-Turn Scanner — v0.3-5 홈 "오늘의 핵심 변화 요약" 보고서

> **작성 기준일:** 2026-06-03
> **선행 커밋:** v0.3-4 `515cfbe`
> **목표:** 홈 화면(`/`)에서 사용자가 **10초 안에 오늘 U턴 스캐너 상태**를 파악할 수 있도록, 기존 사이드카 JSON 집계만으로 "오늘의 핵심 변화 요약" 카드를 추가한다. **분석 로직 변경은 없다.** 사이드카 JSON 구조도 그대로 유지한다.

---

## 1. 작업 목적

v0.3-2~v0.3-4에서 사이드카 데이터의 자동 생성·화면 라벨링·최신 상태 안내까지 완성됐지만, 사용자가 홈에 들어왔을 때 여전히 다음을 알기 위해 **여러 화면을 들어가 봐야** 했다:

- 오늘 바닥/U턴 후보가 몇 개인가?
- U턴 확인 단계 종목이 있는가?
- 추격 위험 종목이 많은 날인가?
- 강한 섹터/약한 섹터는 무엇인가?
- 뉴스 위험(CRITICAL) 종목이 섞여 있는가?

v0.3-5는 이 정보를 **홈 한 화면에 카드 한 장으로 요약**한다. 표시는 사이드카에 **이미 계산된 값만** 가져와 보여주는 방식이라, 분석 로직·DB·JSON 구조에는 영향이 없다.

## 2. 수정 파일

## 3. 화면 변경 내용 (상세)

### 3-1. `app/_lib/sidecar.ts` — 추가된 공개 API

**타입:**
- `SectorBrief = { name, return20d, relStrength }` — 섹터 한 줄 표시용
- `HomeSummaryCounts = { bottomCandidates, uTurnAttempt, uTurnConfirmed, trendCandidate, chaseRiskStrong, criticalInBottom }`
- `HomeSummary = { hasScan, hasSector, hasAny, baseDate, marketFlow, counts, strongSectorsTop3, weakSectorsTop3, bullets }`

**함수:**
- `buildHomeSummary()` — `scan_dump_latest.json` + `sector_dump_latest.json`을 `Promise.all`로 읽어 집계.
- `summarizeTodaySignals({counts, marketFlow, strong, weak})` — 자동 생성 bullet 7종 규칙:
  1. 시장 흐름(강세/약세/중립) → 한 줄
  2. U턴 확인 ≥1 → "확인 후보 N개 — 확인 필요" / U턴 시도 ≥1 / 바닥 관찰 ≥1 (우선순위)
  3. 추격 위험 ≥10 / ≥1 — "신규 진입 시 추격 위험 주의"
  4. 뉴스 위험 ≥1 — "공시·뉴스 확인 필요"
  5. 강한 섹터 TOP3 한 줄
  6. 약한 섹터 TOP3 한 줄 — "보유자 대응 / 조건 부족 관점"
  7. 모든 신호 0개 fallback — "강조할 신호 잡히지 않음"

**사이드카 키 사용 — 새 키 요구 0건:**
- `scan_dump.summary.n_candidates_bottom` (이미 존재)
- `scan_dump.summary.n_chase_risk_strong` (이미 존재)
- `scan_dump.summary.n_critical_in_bottom` (이미 존재)
- `scan_dump.summary.stage_counts['U턴 시도' / 'U턴 확인' / '추세전환 후보' / '바닥 관찰']` (이미 존재)
- `scan_dump.market.flow` (이미 존재)
- `scan_dump.base_date` (이미 존재)
- `sector_dump.market_flow` (이미 존재)
- `sector_dump.sectors_strong[].{sector, sector_20d_return, market_relative_strength}` (이미 존재)
- `sector_dump.sectors_weak[].{sector, sector_20d_return, market_relative_strength}` (이미 존재)
