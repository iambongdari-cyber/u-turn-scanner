# U-Turn Scanner — v0.3-11 홈 변화 카드 "선정 이유" 추가 보고서

> **작성 기준일:** 2026-06-04
> **선행 단계:** v0.3-10 홈 "오늘의 변화 핵심 요약" 박스 (4 카드 + 현재단계) — 커밋 `002f368`
> **목표:** 홈 `ChangeHighlightBox` 안 4 카드 각각에 **"선정 이유"** 한 줄(작은 회색 보조 텍스트)을 추가해, 사용자가 "왜 이 종목이 여기에 떴는지"를 즉시 이해할 수 있게 한다. 분석 로직·DB·TOP10 산식·기존 JSON 구조·`/changes` 화면 모두 무변경.

## 1. 작업 목적

v0.3-10에서 홈 박스에 4 종목(대표 신규진입 / 최대 순위상승 / 최대 순위하락 / 최대 점수상승)이 표시되지만, 사용자가:
- "왜 이 종목이 '대표 신규진입'으로 뽑혔지?"
- "이 종목 어떻게 '최대 순위상승' 1위가 됐지?"

를 떠올리려면 v0.3-9 `/changes` 화면이나 v0.3-7~v0.3-8 v0.3-9 보고서를 다시 봐야 했다. v0.3-11은 카드 본문 하단에 **선정 기준을 한 줄로 명시**해 즉시 이해 가능하게 한다.

## 2. 사용자 명세 표현 정확 일치

사용자가 지정한 4개 문구를 그대로 사용:

| 카드 | 선정 이유 문구 |
|---|---|
| 🆕 대표 신규진입 | **"신규진입 종목 중 최고 점수"** |
| ⬆ 최대 순위상승 | **"후보 순위 개선폭 1위"** |
| ⬇ 최대 순위하락 | **"후보 순위 하락폭 1위"** |
| 📈 최대 점수상승 | **"스캐너 점수 상승폭 1위"** |

표시 형식: 카드 하단에 작은 회색 텍스트 + "선정 이유: " 접두어
```
선정 이유: 신규진입 종목 중 최고 점수
```

## 4. 화면 표시 디자인

### 카드 본문 구조 (정상 분기, row 존재 시)
```
[icon] 라벨 (작은 굵은 글씨)
종목명 + 티커 (sm 굵음, hover 밑줄)
메트릭 (11px tabular-nums)
현재단계 <단계명> (11px)           ← v0.3-10
선정 이유: <문구> (10px 회색)       ← v0.3-11 신규
```

### 시각 위계 (글자 크기로 우선순위 표현)
- 종목명: **text-sm font-semibold** (가장 큼, 클릭 대상)
- 메트릭: text-[11px] tabular-nums (숫자 강조)
- 현재단계: text-[11px]
- **선정 이유**: text-[10px] leading-snug text-slate-500 (가장 작음, 보조)

이 위계로 카드 높이가 과하게 커지지 않으며, 종목명·메트릭이 여전히 시선의 중심.

### row가 null인 경우 (해당 없음)
- 카드 헤더(아이콘 + 라벨) 유지
- 본문 "해당 없음"
- **선정 이유 라인은 표시하지 않음** — 의미적으로 "이 종목이 뽑힌 이유"인데 종목이 없으므로 자연스럽게 생략

## 7. 검증 결과

### 7-1. 호스트 적용 확인 (Read 도구)
4 `<MiniHighlight>` 호출 모두 `reason` prop 정확 전달 확인:
```tsx
reason="신규진입 종목 중 최고 점수"   // 대표 신규진입
reason="후보 순위 개선폭 1위"           // 최대 순위상승

reason="스캐너 점수 상승폭 1위"         // 최대 점수상승
```

`MiniHighlight` 시그니처에 `reason: string` 추가 확인.
본문에 `{reason && (<div ...>선정 이유: {reason}</div>)}` 정상 배치.

### 7-2. graceful
- `row == null` → "해당 없음" + 선정 이유 라인 미렌더 (의미적 일관성)
- `reason` 빈 문자열 → 라인 미렌더 (조건부 렌더링)
- 박스 자체가 부재 분기(`/changes`로 이동만 안내)일 때는 MiniHighlight 미사용 — 선정 이유도 노출 안 됨
