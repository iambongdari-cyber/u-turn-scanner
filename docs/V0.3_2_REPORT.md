## 6. WARN-only 실패 처리 방식

기존 WARN 단계(종목 마스터·백테스트·알림 생성)와 **완전히 동일한 패턴**.

### `[7/11] scan_dump` 분기 (라인 88~97)
```bat
echo [7/11] scan_dump sidecar...
"%PY%" scripts\scan_dump.py
if errorlevel 1 (
    echo.
    echo [WARN] scan_dump sidecar failed. Continue to sector_dump.
    echo   [7] scan_dump sidecar: failed-continue>>"%LOGFILE%"
) else (
    echo   [7] scan_dump sidecar: ok>>"%LOGFILE%"
)
echo.
```

### `[8/11] sector_dump` 분기 (라인 99~108)
```bat
echo [8/11] sector_dump sidecar...
"%PY%" scripts\sector_dump.py
if errorlevel 1 (
    echo.
    echo [WARN] sector_dump sidecar failed. Continue to backtest.
    echo   [8] sector_dump sidecar: failed-continue>>"%LOGFILE%"
) else (
    echo   [8] sector_dump sidecar: ok>>"%LOGFILE%"
)
echo.
```

### 핵심 보증
- **`goto :end` 호출 0건** — 사이드카 실패가 절대 전체 배치를 멈추지 않음
- 자동 grep으로 확인: `[7/11]~[9/11]` 구간에 `goto :end` 매칭 0건 ✓
- 두 사이드카 실패해도 `[9/11]` 백테스트 → `[10/11]` 알림 → `[11/11]` 웹서버 모두 정상 진행
- 화면(`/bottom-watch`·`/leaders`·`/kiwoom-helper`·`/journal`)은 이미 JSON 부재/파싱 실패 graceful 처리 구현됨(v0.2-2/3/4)

## 7. CRLF 확인 결과 (중요 — 사용자 PC 검증 필수)

| 검사 | 결과 |
|------|------|
| 작업 전 백업 (호스트, 검증 완료) | **138 CRLF**, lone LF 0, 4,444 B ✓ |

| 작업 후 호스트 파일 CRLF 수 | **사용자 PC에서 직접 검증 필요** (작업 환경의 mount가 stale 상태로 정확한 측정 불가) |

> **클로드 측 정직한 보고:** Edit 도구는 일반적으로 파일 기존 라인 엔딩(CRLF)을 보존합니다. 그러나 이번 작업 환경에서 Linux 샌드박스 mount가 Edit 이후 호스트 변경분을 즉시 동기화하지 않아, 클로드가 직접 바이트 단위로 CRLF 비율을 측정할 수 없습니다. **반드시 사용자 PC에서 정규화 + 검증을 실행해 주세요.**

### 사용자 PC에서 정규화·검증 (필수 절차 — 이중 안전망)
```bat
REM 1) 정규화 (Edit 도구가 어떤 라인 엔딩을 썼든 강제로 CRLF로 통일)
.venv\Scripts\python.exe -c "d=open('run_daily.bat','rb').read().replace(b'\r\n',b'\n').replace(b'\n',b'\r\n'); open('run_daily.bat','wb').write(d)"

REM 2) CRLF 검증 (lone LF가 0이어야 함)
.venv\Scripts\python.exe -c "d=open('run_daily.bat','rb').read(); crlf=d.count(b'\r\n'); lf=d.count(b'\n'); print('bytes:', len(d), 'CRLF:', crlf, 'lone LF:', lf-crlf)"
```
기대: `lone LF: 0` (CRLF 수는 ~161 부근일 것 — 정확한 숫자보다 **lone LF 0이 핵심**)

### 정규화가 실패할 경우 (lone LF > 0이 남는 경우)
1. `copy /Y run_daily.bat.before_v0.3 run_daily.bat` (원본 복원)
2. 클로드에 재요청

- 웹서버 미기동
- 금지 표현 추가 발견

### 롤백 방법 (3가지, 빠른 순)

**방법 1 — Git restore (가장 빠름)**
```bat
git restore run_daily.bat
```

**방법 2 — 백업 파일 복원 (커밋 전 가능)**

```bat

```

### 롤백 후 안전 상태
- `run_daily.bat`은 9단계 흐름으로 복귀
- 사용자가 사이드카만 다시 돌리고 싶으면 `run_sidecar.bat` 더블클릭(독립 배치 그대로 유지)
