## 2. 배경 — 현재 중복 발생 가능 사례

### 2-1. 현재 (v0.3-15) 정책
- **5 카드 내부** (`pickHomeKeyChanges`): 각 픽이 독립 (서로 중복 회피 없음)
- **3 카드 내부** (`pickHomeSecondLook`): `used` 집합으로 ①→②→③ 순서 중복 회피
- **5 카드 ↔ 3 카드 간**: **중복 회피 없음 (현재 = A안)**

### 2-2. 호스트 2026-06-04 vs 2026-06-02 분석
**오늘 8 종목 우연히 모두 다름**:
| 영역 | 종목 |
|---|---|
| 5 카드 | 동진쎄미켐 / 나노씨엠에스 / 이노메트리 / 마음AI / 엔젤로보틱스 |
| 3 카드 | NAVER / 평화산업 / 유진테크 |

그러나 **잠재 중복 시나리오 매우 흔함**:

| 시나리오 | 5 카드 | 3 카드 | 발생 빈도 추정 |
|---|---|---|---|
| **SCORE_UP 1위가 TOP10** | 📈 점수상승 | ① 강세 지속 | 매우 잦음 (점수 1위가 보통 상위권) |
| **RANK_UP 1위가 점수도 상승** | ⬆ 순위상승 | ② 다방면 개선 | 잦음 |
| **NEW 1위가 TOP10** | 🆕 신규진입 | ① 강세 지속 | 드묾 (NEW는 보통 신규라 순위 후순위) |
| **NEW 1위가 U턴 시도** | 🆕 신규진입 | ③ U턴 시도 강화 | 가끔 |
| **RANK_UP 1위가 U턴 시도** | ⬆ 순위상승 | ③ U턴 시도 강화 | 가끔 |

호스트 데이터 시뮬레이션 — 모든 5 카드 1위 종목의 3 후보 기준 부합 여부:
```
동진쎄미켐 (NEW 1위)   : 3 후보 기준 미부합 (바닥 관찰)
나노씨엠에스 (UP 1위)  : 3 후보 기준 미부합 (score_delta=0)
이노메트리 (DOWN 1위)  : 3 후보 기준 미부합
마음AI (SCORE 1위)    : 3 후보 기준 미부합 (today_rank=49, 바닥 관찰)
엔젤로보틱스 (DEPART)  : 3 후보 기준 미부합 (이탈)
```

→ **오늘은 우연히 안 겹쳤지만, 다른 날짜에서는 흔히 발생할 패턴**.

### 2-3. 후보 풀 크기 (호스트 기준)
| 후보 | 필터 충족 종목 수 |
|---|---|
| ① CONSISTENT (TOP10 + 점수↑) | **4개** (가장 작음 — B안에서 가장 위험) |
| ② MOMENTUM (rank↑ + score↑) | 14개 |
| ③ UTURN (U턴 시도 + score↑) | 9개 (NAVER 회피 후 유진테크) |

→ ① 후보 풀이 작아 B안 적용 시 "해당 없음" 발생 가능성 가장 높음.

## 3. A / B / C 안 비교

### A안 — 중복 허용
- **로직**: 5 카드와 3 카드 각자 독립적으로 1위 선택
- **현재 v0.3-15 동작 = A안**
- **장점**:
  - 강한 신호 종목이 강조됨 ("이 종목 신호 여러 개 있음")
  - 후보 풀 작은 ①도 항상 채워짐
- **단점**:
  - 같은 종목이 두 곳에 노출 → 정보 중복
  - 다양한 종목 노출 기회 감소
- **사용자가 인지하는 메시지**: "강한 신호 = 같은 종목 반복 노출"

### B안 — 완전 중복 제거 (**추천**)
- **로직**: 5 카드 ticker 5개를 `excludeTickers` 집합으로 3 카드 픽에 미리 전달, 픽 단계에서 제외
- **장점**:
  - **다양한 종목 노출** → 사용자가 더 많은 후보 관찰 가능
  - 정보 중복 해소, 시선 효율적
  - 코드 변경 최소 (excludeTickers 파라미터 추가)
- **단점**:
  - 후보 풀 작은 ①에서 "해당 없음" 자주 발생 가능
  - 강한 신호 종목이 5 카드만 강조되고 3 카드에 못 나옴 (관점에 따라 단점)
- **사용자가 인지하는 메시지**: "5 카드와 다른 후보 = 다양성 + 새로운 시선"

### C안 — 부분 중복 허용 (배지)
- **로직**: 중복 허용하되 "중복 신호" 배지 부착 (예: "📈 SCORE_UP과 동일")
- **장점**:
  - 강한 신호 강조 + 다양성 중간 지점
  - 사용자가 "이 종목은 신호 2개 동시" 즉시 인지
- **단점**:
  - **구현 복잡** — 어느 5 카드와 겹치는지 추적 + 배지 UI + 안내 문구
  - 추가 UI 학습 필요
  - 카드 디자인 변경

### 비교표

| 항목 | A안 (허용) | **B안 (제거)** | C안 (배지) |
|---|---|---|---|
| 정보 다양성 | 낮음 | **높음** | 중 |
| 강한 신호 강조 | **강** | 약 | 중 |
| 구현 복잡도 | 0 (현재) | **낮음** (1~2줄 추가) | 중상 (배지 UI 필요) |
| 사용자 인지 부담 | 낮음 (중복 자명) | **낮음** ("다양한 후보") | 중 ("중복 신호 학습 필요") |
| 후보 풀 부족 위험 | 0 | **있음 (①가 위험)** | 0 |
| 사용자 1차 선호 | - | **✅** | - |

## 4. 추천안 — **B안 + 후보 부족 시 B-1 (해당 없음)**

### 4-1. 핵심 정책
**5 카드에 노출된 ticker 는 3 카드에서 완전 제외. 후보 풀이 부족하면 해당 카드에 "해당 없음" 표시.**

### 4-2. 추천 근거
1. **사용자 1차 선호**: B안
2. **다양성 우선**: 홈 화면에서 더 많은 종목 노출이 정보 가치 큼
3. **시각 효율**: 같은 종목이 두 곳에 안 나오면 사용자 시선 분산 감소
4. **구현 단순**: `excludeTickers` 파라미터 1개 추가 — 약 5~10줄 변경
5. **graceful**: "해당 없음"은 v0.3-15 이미 구현된 동작 — 추가 UI 작업 0

### 4-3. 후보 부족 시 옵션 비교 (B-1 vs B-2 vs B-3)

| 옵션 | 동작 | 장점 | 단점 |
|---|---|---|---|
| **B-1 (추천)** | "해당 없음" 표시 | 단순, 명확, 사용자가 "오늘 신호 부족" 인지 | 빈 카드 발생 |
| B-2 | 5 카드 중복 허용 fallback ("중복 신호" 배지) | 항상 채워짐 | C안과 유사 — UI 복잡도 ↑ |
| B-3 | 다른 기준으로 fallback (예: TOP10 → TOP20) | 항상 채워짐 | 기준 일관성 깨짐, "왜 TOP20인지" 설명 필요 |

#### B-1 추천 이유
- v0.3-15 이미 `row == null` 분기에서 "해당 없음" 자연스럽게 표시
- 사용자가 명확하게 "오늘 이 기준에 해당 종목 없음" 인지 → 부족 신호 자체가 정보
- 코드 변경 0줄 (graceful 그대로)

#### 3 카드 모두 "해당 없음"일 때
- v0.3-15에 이미 `allEmpty` 체크 → 영역 자체 미렌더
- 이 동작 그대로 유지 — 영역이 사라지면 사용자는 5 카드만 보게 됨 (자연스러움)

## 5. 추천안 선정 로직 (의사 코드)

```ts
// 1) 5 카드 픽 (기존 그대로)
const keyPicks = pickHomeKeyChanges(changeDump?.changes);

// 2) 5 카드에 노출된 ticker 5개를 excludeTickers 집합으로 모음
const excludeTickers = new Set<string>(
  [
    keyPicks.topNew?.ticker,
    keyPicks.topRankUp?.ticker,
    keyPicks.topRankDown?.ticker,
    keyPicks.topScoreUp?.ticker,
    keyPicks.topDeparted?.ticker,
  ].filter((t): t is string => !!t)
);

// 3) 3 카드 픽 — excludeTickers 를 픽 단계에서 미리 제외 + 내부 중복 회피
const secondLookPicks = pickHomeSecondLook(changeDump?.changes, excludeTickers);
```

### 5-1. `pickHomeSecondLook` 시그니처 확장
```ts
function pickHomeSecondLook(
  rows: ChangeRowLite[] | undefined,
  excludeTickers: Set<string> = new Set(),  // ← v0.3-16 신규
): HomeSecondLookPicks
```

### 5-2. 픽 로직 수정 (의사 코드)
```ts
// ① CONSISTENT
const consistent = rows
  .filter(r =>
    !excludeTickers.has(r.ticker)        // ← v0.3-16 추가
    && r.today_rank!=null && r.today_rank<=10
    && r.score_delta!=null && r.score_delta>0
  )
  .sort((a,b) => b.score_delta - a.score_delta)[0] ?? null;

// 내부 중복 회피 (v0.3-15 그대로)
const used = new Set<string>(excludeTickers);  // ← v0.3-16: 시작값을 excludeTickers 로
if (consistent) used.add(consistent.ticker);

// ② MOMENTUM
const momentum = rows
  .filter(r =>
    !used.has(r.ticker)                  // ← 5 카드 ticker + ① ticker 모두 회피
    && r.rank_delta!=null && r.rank_delta<0
    && r.score_delta!=null && r.score_delta>0
  )
  .sort(...)[0] ?? null;
if (momentum) used.add(momentum.ticker);

// ③ UTURN
const uturn = rows
  .filter(r =>
    !used.has(r.ticker)                  // ← 5 카드 + ① + ② ticker 모두 회피
    && r.today_stage === 'U턴 시도'
    && r.score_delta!=null && r.score_delta>0
  )
  .sort(...)[0] ?? null;
```

## 6. 후보 부족 시 처리 (B-1 상세)

### 6-1. 단일 카드 부족
| 시나리오 | 표시 |
|---|---|
| `consistent === null` 후 단독 | ① 카드 "해당 없음" + ②③ 정상 |
| `momentum === null` | ② 카드 "해당 없음" + ①③ 정상 |
| `uturn === null` | ③ 카드 "해당 없음" + ①② 정상 |

각 카드는 v0.3-15에서 이미 `row == null` → "해당 없음" 처리 구현됨.

### 6-2. 다중 카드 부족
| 부족 수 | 동작 | 사용자 인지 |
|---|---|---|
| 1개 부족 | 영역 표시 + 1 카드 "해당 없음" | 부분적 정보 부족 |
| 2개 부족 | 영역 표시 + 2 카드 "해당 없음" | 신호 부족 명확 |
| **3개 부족** | **영역 자체 미렌더** (v0.3-15 `allEmpty` 동작) | 5 카드만 보임 |

### 6-3. "해당 없음" vs "중복으로 제외" 메시지 — 검토
사용자가 "해당 없음" 만 보면 "왜?"를 모를 수 있음. 두 가지 옵션:

#### 옵션 ⓐ — 단순 "해당 없음" (1차 추천)
- 장점: 단순, 변경 0줄
- 단점: 사용자가 이유를 모름

#### 옵션 ⓑ — 사유 명시 "해당 없음 (위 5 카드 중복 또는 신호 부족)"
- 장점: 사용자 인지 명확
- 단점: 약간 장황

→ **옵션 ⓐ 1차**, 사용자 피드백 후 ⓑ 검토.
