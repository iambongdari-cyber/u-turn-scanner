## 3. 대표 이탈 선정 기준 비교

호스트 데이터로 옵션 3종을 시뮬레이션해 비교한다.

### 옵션 A — `yesterday_rank` 오름차순 (직전 가장 높았던 순위)
```
 1. rank= 12  score=37.0  455900 엔젤로보틱스         직전단계=바닥 관찰
 2. rank= 41  score=38.0  170030 현대공업
 3. rank= 53  score=27.0  402030 코난테크놀로지
 4. rank= 65  score=43.0  381620 제닉스로보틱스
 5. rank= 70  score=41.0  022100 포스코DX
```

**의미**: "어제 12위였던 종목이 오늘 후보권에서 빠짐!" — 강력한 변화 신호.

### 옵션 B — `yesterday_score` 내림차순 (직전 가장 높은 점수, NEW 와 대칭)
```
 1. score=72.0  rank=188  273640 와이엠텍
 2. score=70.0  rank=418  123010 알엔티엑스
 3. score=63.0  rank=346  004590 한국가구
 4. score=61.0  rank= 96  119830 아이텍
 5. score=59.3  rank=410  330730 스톤브릿지벤처스
```

**의미**: "직전 점수 72점이었던 종목이 빠짐". 그러나 직전 188위·418위 등 **후보 끝부분** 종목이 잡혀 "어차피 약한 후보였잖아" 인상.

### 옵션 C — 복합 (score 내림차순 + rank 오름차순 tie-breaker)
호스트 데이터에서는 옵션 B 와 동일 결과(점수 동률 적음).

### 비교표
| 항목 | 옵션 A (rank) | 옵션 B (score) | 옵션 C (복합) |
|---|---|---|---|
| 선정 종목의 임팩트 | **강** (직전 12위 빠짐) | 중 (직전 188위 빠짐) | 중 |
| NEW 카드와의 대칭 | 비대칭 (의미상 자연스러움 — 아래 참조) | 대칭 | 부분 대칭 |
| 사용자 직관 | "어제 강했던 종목이 빠짐!" 즉시 인지 | "직전 점수 최고였던 게 빠짐" 두 단계 인지 | 옵션 B 와 유사 |
| 구현 복잡도 | 낮음 | 낮음 | 낮음 |
| 호스트 데이터 결과 자연스러움 | **자연스러움** | 약함 (끝부분 종목) | 약함 |

### 추천: **옵션 A**

#### 비대칭 정당화
NEW 와 DEPARTED는 의미적으로 대칭처럼 보이지만 시점 의미가 다르다:
- **NEW**: "**오늘** 후보에 새로 들어옴" → **today** 정보(점수)가 핵심
- **DEPARTED**: "**직전 스냅샷** 후보에서 빠짐" → **yesterday** 정보(순위)가 핵심

→ NEW = `today_score` 최고, DEPARTED = `yesterday_rank` 최저는 비대칭이 아니라 **각 사건의 자연스러운 정보 축**을 따른다.

## 4. DEPARTED 카드 디자인 명세

### 4-1. 시각 요소
| 요소 | 값 | 비고 |
|---|---|---|
| 아이콘 | 🚪 | v0.3-8 이탈 TOP10 / v0.3-9 QuickCard 와 일관 |
| 라벨 | "대표 이탈" | 카드 헤더 |
| 색 tone | `slate` (회색) | "제거된" 느낌, NEW의 emerald 와 시각 구분 |
| 헤더 클래스 | `border-slate-300 bg-slate-50 text-slate-800` | QuickCard 이탈 TOP10 톤 일관 |

### 4-2. 카드 본문 표시 (다른 카드 4 종과 일관 형식)
| 라인 | 내용 |
|---|---|
| 종목명 + 티커 | `Link href="/stocks/<ticker>"` |
| 메트릭 | `직전 순위 N · 직전 점수 N.N` (yesterday_rank · yesterday_score) |
| **직전단계** (※ 다른 카드는 "현재단계") | `yesterday_stage` 표시 |
| 선정 이유 | "직전 스냅샷에서 후보 자리가 가장 높았던 종목" |

### 4-3. `today_stage` 문제
- DEPARTED row 의 `today_stage` 는 **None** (오늘 후보권 빠짐 → stage 부재)
- 다른 카드는 `row.today_stage` 표시 → DEPARTED 만 `yesterday_stage` 로 대체 필요
- 구현 시 `MiniHighlight` 에 stage 소스 선택용 prop 추가 (예: `stageSource: 'today' | 'yesterday'`) 또는 라벨 prop (`stageLabel: '현재단계' | '직전단계'`) 1개 추가

### 4-4. 안내 문구 (v0.3-11 reason 패턴 일관)
사용자에게 노출될 한 줄:
> "선정 이유: **직전 스냅샷 순위 최고**"

또는 더 명확하게:
> "선정 이유: **직전 스냅샷에서 가장 높은 순위였던 종목**"

### 4-5. detailHref
```ts
detailHref="/changes?focus=out"
```
v0.3-12 에서 `normalizeFocus` 가 이미 `out` 인식, v0.3-13 에서 `focus-out` id 가 QuickTopCards 이탈 TOP10 에 부착됨 → **추가 인프라 작업 0건**.

## 5. 5 칸 레이아웃 방안

### 5-1. 현재 (4 칸)
```tsx
<div className="grid grid-cols-1 gap-2 sm:grid-cols-2 lg:grid-cols-4">
```
- 모바일: 1열 (4칸 세로)
- sm(640+): 2x2
- lg(1024+): 1행 4열

### 5-2. 방안 A — 단순 (1차 추천)
```tsx
<div className="grid grid-cols-1 gap-2 sm:grid-cols-2 lg:grid-cols-5">
```
| breakpoint | 배치 | 카드당 너비(대략) |
|---|---|---|
| 모바일 (default) | 1행 1열, 5행 세로 | 100% |
| sm (640+) | 2 열 → 3 행 (마지막 단독) | 약 320px |
| lg (1024+) | **1 행 5 열** | 약 200px |

**장점**: 코드 한 줄 변경(`lg:grid-cols-4` → `lg:grid-cols-5`). 단순.
**우려**: lg 1024px 에서 카드당 200px → 종목명 한글 7자 + 메트릭 표시까지 가능하나 빠듯할 수 있음.

### 5-3. 방안 B — 단계형 (2차 추천)
```tsx
<div className="grid grid-cols-1 gap-2 sm:grid-cols-2 md:grid-cols-3 xl:grid-cols-5">
```
| breakpoint | 배치 |
|---|---|
| 모바일 | 1열 (5행) |
| sm (640+) | 2 열 (3 행, 마지막 단독) |
| md (768+) | 3 열 (2 행, 마지막 단독) |
| lg (1024~1279) | **3 열 유지** (md 와 동일) |
| xl (1280+) | **1 행 5 열** |

**장점**: 모든 breakpoint 에서 카드당 너비 여유. lg 구간(1024~1279)에서 5 열로 좁아지는 부담 없음.
**우려**: lg 구간 사용자(가장 흔한 노트북 화면) 가 5 카드를 한눈에 못 봄 → 두 번 시선 이동 필요.

### 5-4. 방안 비교
| 항목 | 방안 A (단순) | 방안 B (단계형) |
|---|---|---|
| 코드 변경 | 1 줄 | 1 줄 |
| 모바일 가독성 | 동일 | 동일 |
| sm/md 가독성 | sm 이후 즉시 2 열 | sm → 2 열 → md → 3 열 |
| **lg 한눈에 5 카드** | ✅ Yes | ❌ No (xl 부터) |
| lg 카드당 너비 | 좁음 (200px) | 넉넉 (240px+) |
| 1차 추천 | ✅ | (대안) |

### 5-5. 추천: **방안 A (단순)** 1차안
이유:
1. 사용자가 "5 카드를 한눈에 본다" 가 핵심 목적 — lg 부터 즉시 1 행 가능
2. 200px / 카드는 종목명(한글 7자 ≈ 100~120px) + 메트릭(50~70px) 수용 가능
3. 코드 한 줄 변경
4. 검증 후 너무 좁다고 판단되면 v0.3-15 에서 방안 B 로 전환 (롤백 비용 1 줄)

방안 B 는 lg 사용자(노트북) 가 5 칸을 한눈에 못 보는 게 사용성 손실 — 방안 A 1차 시도 후 피드백 기반 결정.
