## 3. `scan_dump.py` 기능 요약

### import 사용 대상 (수정 없음)
```python
from run_scan import (
    analyze, fetch_all_prices, fetch_market_index_data,
    fetch_news_risks, fetch_stocks, GOLDEN_WINDOW,
)
```
- `fetch_all_prices(use_cache=True)` — 1·2차 성능 개선의 캐시 그대로 재사용

### 처리 흐름
1. 종목 마스터·시장 지수·뉴스 리스크 로드
2. 일봉 캐시 사용 로드
3. **섹터 20일 평균 수익률을 사이드카 내부에서 계산**(run_scan과 동일 산식, 표본 3+ 섹터만)
4. 종목별 `analyze(...sector_20d_return=...)` 호출 → run_scan과 동일한 `final_grade`/score 산출
5. 단계 라벨링 + 분류

### 단계 라벨링 규칙
| 조건 | 라벨 |
|------|------|
| 골든크로스 미발생 + `cond_uturn_ok` + `cond_above_ma60` | **바닥 관찰** |
| 골든크로스 0~1일 전 | **U턴 시도** |
| 골든크로스 2~5일 전 | **U턴 확인** |
| 골든크로스 6일+ 전 | **추세전환 후보** |
| 그 외 | (라벨 없음) |

### 바닥 U턴 후보 강화(단순 낙폭 종목 배제)
- `cond_uturn_ok` 충족 + (거래대금 회복(`value_ratio ≥ 1.2`) **또는** 60일선 상승 시작 **또는** 종가 60일선 위)
- 각 후보에 근거 라벨(`evidence`) 함께 출력:
  - "U턴 검증 충족(60일 중 아래 N일)"
  - "거래대금 회복 (X.X배)"
  - "20일 평균 거래대금 충족"
  - "60일선 상승 중"
  - "후행스팬 정상"
  - "일목 양운"
  - "종가 60일선 위"

### 추격 위험 강화
- `final_grade == 'CHASE_RISK'` 종목 중 다음 사유 1개 이상:
  - 이격 +25% 이상(큰 폭) / +20% 이상
  - 60일 고가 근접(상승여력 < 5%)
  - 손익비 < 0.5

### 출력
- 경로: `logs/sidecar/scan_dump_latest.json` (덮어쓰기)
- 옵션: `--report-type {daily,weekly}` (기본 daily, 윈도우 5)

## 4. `sector_dump.py` 기능 요약

### import 사용 대상 (수정 없음)
```python
from run_scan import (
    fetch_all_prices, fetch_market_index_data, fetch_stocks,
    MIN_AVG_VALUE_20,
)
```

### 처리 흐름
1. 종목별 지표 산출(20일 수익률 / 20일 평균거래대금 / 60일 고가 위치 / 60일선 위 / 이격도)
   - 거래대금은 `trade_value`가 NULL이면 `close×volume` 근사(run_scan과 동일 규칙)
2. 섹터별 평균 수익률 → 시장 평균 대비 상대강도
3. 강한 섹터 상위 N개(`--top-sectors`, 기본 8) / 약한 섹터 동수
4. 섹터 안 종목 분류

### 분류 규칙 (우선순위 적용)
| 조건 | 라벨 |
|------|------|
| 이격 +20% 이상(우선) | **추격 위험** |
| 60일선 위 + 전고점 ≥90% + 거래대금 ≥10억 + 이격 <20% | **진짜 주도주 후보** |
| 60일선 위 + 전고점 70~90% + 거래대금 ≥5억 | **후발주 관찰** |
| 60일선 위 + 거래대금 ≥10억 | **기회 후보** |
| 60일선 위(그 외) | **보유자 대응** |
| 60일선 아래 | **조건 부족** |

### 출력
- 경로: `logs/sidecar/sector_dump_latest.json` (덮어쓰기)
- 옵션: `--top-sectors N`(기본 8), `--min-stocks N`(기본 5)

## 부록. 사용자 PC 검증 권장 순서

제 작업 환경에서는 네트워크 제약으로 Supabase에 접속할 수 없어 단독 실행 검증은 사용자 PC가 권위 있는 확인이다.

cmd(프로젝트 폴더)에서:
```bat
REM 1) 문법 검사
.venv\Scripts\python.exe -m py_compile scripts\scan_dump.py scripts\sector_dump.py

REM 2) 사이드카 단독 실행
.venv\Scripts\python.exe scripts\scan_dump.py
.venv\Scripts\python.exe scripts\sector_dump.py

REM 3) JSON 파일 생성 확인
dir logs\sidecar\

REM 4) DB 행수 변화 0 확인 (선택)
.venv\Scripts\python.exe scripts\check_db.py
```

확인 포인트:
1. py_compile 둘 다 조용히 끝나면 통과
2. scan_dump 끝에 `✓ JSON 저장: ...\logs\sidecar\scan_dump_latest.json` + 후보 수 출력
3. sector_dump 끝에 `✓ JSON 저장: ...\logs\sidecar\sector_dump_latest.json` + 강한 섹터 수 출력
4. `dir logs\sidecar\`에 두 파일 보이면 ✓
5. check_db 결과의 테이블 행수가 사이드카 실행 전후 동일

문제 없음 확인 시 — 사이드카 2개 파일만 콕 집어 커밋 권장(노이즈 제외):
