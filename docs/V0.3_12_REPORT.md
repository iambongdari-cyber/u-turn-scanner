# U-Turn Scanner — v0.3-12 홈 변화 카드 → /changes?focus= 링크 연결 보고서

> **작성 기준일:** 2026-06-05
> **선행 단계:** v0.3-11 홈 변화 카드 "선정 이유" 추가
> **목표:** 홈 `ChangeHighlightBox` 4 카드를 클릭하면 `/changes?focus=<키>` 로 이동하고, `/changes` 화면이 해당 카드를 `ring` 강조하도록 UI 링크만 연결한다. 산식·JSON·DB·`run_daily.bat` 모두 무변경.

## 1. focus 키 매핑 결정

사용자 명세는 4 focus 키(`new` / `out` / `up` / `sector`)를 제시했지만, 현재 홈 카드 4종(v0.3-10/11)은 **신규진입 / 순위상승 / 순위하락 / 점수상승** 으로 구성되어 있어 `out`(이탈)과 `sector`(섹터변화) 카드는 홈에 없다. "UI 연결만 진행"이라는 명세를 존중해 카드 구성은 변경하지 않고, focus 키를 다음과 같이 매핑한다:

### 홈 카드 → focus 매핑
| 홈 카드 | focus 키 | 비고 |
|---|---|---|
| 🆕 대표 신규진입 | `new` | 사용자 명세 일치 |
| ⬆ 최대 순위상승 | `up` | 사용자 명세 일치 |
| ⬇ 최대 순위하락 | `down` | 자연스러운 확장 (사용자 명세에 없지만 의미 일치) |
| 📈 최대 점수상승 | `score` | 자연스러운 확장 (사용자 명세에 없지만 의미 일치) |

### `/changes` 페이지가 인식하는 전체 focus 키
사용자 명세에 있는 `out`(이탈)·`sector`(섹터변화)도 페이지 인식만 추가 — 향후 다른 위치(예: `/changes` 내부 카드 자체 링크)에서 동일 패턴 사용 가능.

| focus 키 | 강조 대상 카드 |
|---|---|
| `new` | KeyChangeHighlights 의 `NEW` + QuickTopCards 의 `NEW` |
| `out` | QuickTopCards 의 `DEPARTED` |
| `up` | KeyChangeHighlights 의 `RANK_UP` + QuickTopCards 의 `RANK_UP` |
| `down` | KeyChangeHighlights 의 `RANK_DOWN` + QuickTopCards 의 `RANK_DOWN` |
| `score` | KeyChangeHighlights 의 `SCORE_UP` |
| `sector` | (현재 강조 대상 없음 — 향후 섹터 변화 전용 카드 추가 시 사용) |

> v0.3-12 범위: 홈 4 카드만 직접 `?focus=` 링크. `out`/`sector`는 페이지가 받기만 함 (강조 매핑 준비 완료).

## 2. 변경 파일

| `docs/V0.3_12_REPORT.md` | 본 보고서 신규 |

## 3. 동작 흐름

### 홈에서 진입
1. 사용자가 홈 `ChangeHighlightBox` 의 카드 헤더(`🆕 대표 신규진입 →` 등)를 클릭
2. 브라우저가 `/changes?focus=new` 등으로 이동
3. `/changes` 서버 컴포넌트가 `searchParams.focus` 읽음 → `normalizeFocus` 로 화이트리스트 검증
4. 매칭되는 `HighlightCard`/`QuickCard` 에 `focused=true` → `ring-2 ring-indigo-400 ring-offset-1` 적용
5. 사용자는 어느 카드가 강조되어 있는지 즉시 인지

### 종목명 클릭은 그대로 `/stocks/[ticker]`
카드 헤더(라벨)만 `Link`로 만들었고 종목명 `Link`는 그대로 유지 — nested anchor 없음, HTML 사양 준수.

### 화살표 인디케이터
카드 헤더 우측에 작은 `→` 추가 → "이 카드는 클릭 가능"임을 시각적으로 알림.
