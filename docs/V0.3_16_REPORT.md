## 1. 작업 목적

v0.3-15까지 5 카드와 3 카드가 독립 픽이라 같은 종목이 양쪽에 노출될 수 있었다. 특히 잠재 빈도가 높은 시나리오:
- SCORE_UP 1위가 TOP10 → 📈 ↔ ① 강세 지속 (매우 잦음)
- RANK_UP 1위가 점수도 상승 → ⬆ ↔ ② 다방면 개선 (잦음)
- NEW 1위가 U턴 시도 → 🆕 ↔ ③ U턴 시도 강화 (가끔)

v0.3-16은 5 카드 ticker 를 미리 모아 3 카드 픽 단계에서 제외. **5 카드 = 대표 사건, 3 카드 = 대표 사건에 안 나온 추가 확인 후보** 라는 의미 분리.

## 3. `app/page.tsx` 변경 상세 (3 곳)

### 3-1. `pickHomeSecondLook` 시그니처 확장 + 필터 추가
```ts
function pickHomeSecondLook(
  rows: ChangeRowLite[] | undefined,
  excludeTickers: Set<string> = new Set(),   // v0.3-16 신규 (기본값으로 하위 호환)

```
- 기본값 `new Set()` 으로 **하위 호환 유지** — `excludeTickers` 인자 없이 호출하면 v0.3-15 동작.

### 3-2. 3 후보 filter 에 `!excludeTickers.has(r.ticker)` 추가
```ts
// ① CONSISTENT
.filter((r) =>
  !excludeTickers.has(r.ticker)                              // v0.3-16
  && typeof r.today_rank === 'number' && r.today_rank <= 10
  && typeof r.score_delta === 'number' && r.score_delta > 0,
)
```
- ②/③도 동일 패턴 — 단 `used` 가 이미 excludeTickers 를 포함하므로 별도 추가 안 함 (③ 코드에서는 `!used.has(...)` 한 줄로 처리).

### 3-3. `used` 초기값을 `excludeTickers` 로
```ts
// v0.3-16: used 초기값 = excludeTickers (5 카드 + 내부 회피 누적)
const used = new Set<string>(excludeTickers);
if (consistent) used.add(consistent.ticker);
```
- ②/③ 픽에서 `!used.has(...)` 한 줄로 **5 카드 + ①/② 누적** 모두 자동 회피.

### 3-4. `Home()` 본문에 `excludeTickers` 생성 + 호출 인자 추가
```tsx
// v0.3-16: 5 카드에 이미 노출된 종목 ticker 5개를 모아 excludeTickers 로 만든다.
// → 3 카드 픽에서 미리 제외해 같은 종목이 두 영역에 동시 노출되는 것을 막는다.
const excludeTickers = new Set<string>(
  [
    keyPicks.topNew?.ticker,
    keyPicks.topRankUp?.ticker,
    keyPicks.topRankDown?.ticker,
    keyPicks.topScoreUp?.ticker,
    keyPicks.topDeparted?.ticker,
  ].filter((t): t is string => !!t),   // TypeScript 타입 가드로 null 제거
);

const secondLookPicks = pickHomeSecondLook(changeDump?.changes, excludeTickers);
```
