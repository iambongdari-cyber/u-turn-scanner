# U-Turn Scanner — v0.3-4 사이드카 최신 상태 안내 UX 보강 보고서

> **작성 기준일:** 2026-06-03
> **선행 커밋:** v0.3-3 `577f770`
> **목표:** 화면을 볼 때 사용자가 "지금 보고 있는 사이드카가 오늘 데이터인지·누락인지·오래된지·재실행이 필요한지"를 한눈에 알 수 있도록 안내 UX를 보강한다. **분석 로직 변경은 없다.** 데이터 최신성/신뢰성 확인용 표시만 추가한다.

## 1. 작업 목적

v0.3-2에서 `run_daily.bat`이 사이드카 2종(`scan_dump_latest.json`, `sector_dump_latest.json`)을 매일 자동 생성하지만:

- 사용자는 지금 보고 있는 화면의 사이드카가 **오늘 생성된 최신**인지 모름
- 어제 파일을 그대로 보고 있어도 화면은 정상으로 보임
- 파일이 누락/파싱 실패 시에도 단순 "missing/error" 안내만 있어, **무엇을 해야 하는지** 불명확
- "run_daily.bat 재실행" 안내가 화면 어디에도 명확히 없음

v0.3-4는 다음 4가지를 한눈에 보여준다:
1. 이 사이드카 데이터가 오늘 생성된 최신 데이터인지
2. `scan_dump_latest.json` / `sector_dump_latest.json` 파일이 존재하는지
3. 파일이 오래됐거나 누락되었는지
4. `run_daily.bat`를 다시 실행해야 하는 상태인지

표시 위치는 **홈(`/`) 상단, `/bottom-watch` 헤더 직후, `/leaders` 헤더 직후** 3곳.

## 3. 화면별 변경 내용 (상세)

### 3-1. `app/_lib/sidecar.ts`

**추가된 공개 API:**
- 타입:
  - `SidecarKind = 'scan' | 'sector'`
  - `SidecarFileStatus`: `{ kind, fileName, pathLabel, exists, modifiedAtIso, modifiedDateKst, todayKst, ageHours, isToday, isStale, parseError, status, message }`. `status`는 `'ok' | 'missing' | 'stale' | 'error'`.
  - `SidecarFreshness`: 두 파일 종합 상태. `{ scan, sector, allOk, anyMissing, anyStale, anyError, needsRerun, bannerLevel, headline, detail }`. `bannerLevel`은 `'ok' | 'warn' | 'error'`.
- 함수:
  - `getSidecarFileStatuses(now?: Date)`: `{ scan, sector }` 동시 stat + JSON 파싱 검증.
  - `summarizeSidecarFreshness(scan, sector)`: 종합 헤드라인/디테일/배너 톤 자동 산출.
  - `formatSidecarTime(d)`: KST `YYYY-MM-DD HH:mm KST` 표기.

**내부 로직(요약):**
- `stat(file)` 실패 → `status: 'missing'`, message: "…이(가) 없습니다. run_daily.bat 실행 후 다시 확인하세요."
- 파일은 있으나 `JSON.parse` 실패 → `status: 'error'`, "파일은 있으나 읽기 실패."
- mtime의 KST 날짜가 오늘이 아니거나 24시간 이상 경과 → `status: 'stale'`, "오늘 생성된 파일이 아닙니다 — 생성일 …. 최신 분석을 보려면 run_daily.bat를 다시 실행하세요."
- 그 외 → `status: 'ok'`, "…최신 (생성 시각)."

**KST 처리:** `getTime() + 9*60*60*1000`으로 UTC ms를 KST 보정한 뒤 `toISOString().slice(0,10)`으로 날짜 추출. 별도 라이브러리 미사용.

**JSON 구조 무변경:** `readFile`/`JSON.parse`만 호출하고 키 접근 없음. 따라서 사이드카 JSON 스펙 변경 0건.

### 3-2. `app/page.tsx` (홈)

기존 SearchForm 위에 `SidecarFreshnessBox` 추가. 박스 내부 구성:
- **헤더 한 줄**: `✅/⚠️/❌ 사이드카 최신 상태 — <headline>` (ok/warn/error 톤 자동).
- **디테일 한 줄**: `summarizeSidecarFreshness().detail`.
- **2분할 행**: scan/sector 각 파일별 `SidecarStatusRow`
  - 라벨: "바닥 후보 사이드카" / "섹터 사이드카"
  - 우상단 배지: "오늘 최신" (emerald) / "오래된 파일" (amber) / "읽기 실패" / "파일 없음" (red)
  - 경로 코드: `logs/sidecar/<file>`
  - 생성 시각 + 경과 시간(시간 단위, 소수 1)
  - missing/stale/error 시 상세 message 한 줄
- **재실행 안내 한 줄**(needsRerun일 때만): "👉 **run_daily.bat** 재실행 후 다시 확인하세요. (사이드카 단독 재생성은 **run_sidecar.bat**도 가능)"
- **꼬리표**: "이 박스는 분석 결과가 아니라 데이터 최신성 확인용입니다."

### 3-3. `app/bottom-watch/page.tsx`

- import에 `getSidecarFileStatuses`, `SidecarFileStatus` 추가.
- `BottomWatchPage` 첫 줄에서 `loadDump()`와 `getSidecarFileStatuses()`를 `Promise.all`로 동시 호출.
- **헤더 직후**에 `<SidecarStatusBox s={scanStatus} fallbackLabel="bottom-watch" />` 삽입.
  - ok이면 한 줄 보조 표시: "✅ scan sidecar 최신 · 생성 YYYY-MM-DD HH:mm KST — 데이터 최신성 확인용 표시 (분석 결과 아님)"
  - missing/error/stale은 강조 박스(타이틀 · 배지 · 경로 코드 · 한 줄 안내 · 재실행 가이드 · 꼬리표).
- **missing 분기**(scan_dump_latest.json 자체가 없을 때): 기존 missing 안내 위에 동일 상태 박스 + "**누락된 상태 — run_daily.bat 재실행 후 다시 확인**" 한 줄 강화.
- **parse_error 분기**: "**파일은 있으나 읽기 실패** — run_daily.bat 또는 run_sidecar.bat 다시 실행" 안내.
- 기존 단계별 카드/거래대금/이격 표시는 무변경.

### 3-4. `app/leaders/page.tsx`

- `LeadersPage` 첫 줄에서 `loadDump()` + `getSidecarFileStatuses()` 동시 호출.
