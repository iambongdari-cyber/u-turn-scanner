# U-Turn Scanner — v0.2 전체 사용감 점검 보고서

> **작성 기준일:** 2026-06-02
> **기준 커밋:** v0.2-4 완료 `134a79f` (GitHub push 완료)
> **목적:** v0.1 + v0.2 전체 흐름이 실제 사용에 적합한지 코드 수정 없이 평가. v0.2.1(문구/UX 보정) 또는 v0.3(`run_daily.bat` 사이드카 통합) 진행 여부를 결정하기 위한 의사결정 문서.
> **성격:** 평가 전용, 코드·DB·환경설정 무수정.

## 0. 평가 기준

사용자가 원하는 핵심 방향을 다음 5가지로 정리하고, 각 화면이 이 기준에 얼마나 부합하는지 본다.

1. **바닥에서 올라오는 종목으로 큰 기회**를 찾고 싶다
2. 지금 당장의 **시장 기회도 놓치고 싶지 않다**
3. 키움 자동감시주문은 **참고표를 보고 사용자가 직접 입력**한다
4. **자동매매는 하지 않는다**
5. 매일 **감시 등록·체결·미체결·복기를 기록**하고 싶다

표현 원칙(허용/금지)도 모든 화면이 준수해야 한다.

## 2. 현재 화면 흐름 평가

### 2-1. 홈 화면

홈에는 현재 **3개 그룹**이 있다.
1. 기존 링크(파란색): 최근 리포트 / 과거 리포트 / 백테스트 / 알림
2. **기회·위험 점검판 (v0.1)** (녹색): 시장 지도 / 기회 포착판 / 키움 참고표 / 매매일지 초안
3. **사이드카 분석 (v0.2)** (보라색): 바닥 U턴 후보 / 주도주·후발주

| 평가 항목 | 결과 |
|----------|------|
| 보기 좋게 배치 | △ — 그룹 라벨로 구분돼 있고 색상이 달라 식별 가능. 그러나 링크가 총 10개라 첫 진입 시 다소 많다. |
| 다음에 무엇을 눌러야 할지 직관적 | △ — "오늘 처음 켰을 때 어디부터?"의 자연 순서가 텍스트로 드러나지 않는다. 사용자가 v0.1/v0.2 의미를 알아야 한다. |

**총평:** "버전 그룹"으로 묶여 있어 **개발자 관점**의 정리에 가깝다. 사용자 관점의 **하루 흐름**("아침에 시장 지도 → 오늘의 후보 → 키움 참고 → 일지")으로 재배치하면 더 직관적이다.

### 2-2. `/market` — 오늘의 시장 지도

| 평가 항목 | 결과 |
|----------|------|
| 시장 흐름을 먼저 보는 화면으로 적절 | ✅ 단순·집중. KOSPI/KOSDAQ만 보여 부담이 없다. |
| 10초 안에 이해 | ✅ 시장 흐름 라벨(강세/중립/약세) + 두 지수 카드만 있어 한눈에 파악 가능. |
| 매매 권유 인상 | 없음 ✅ |

**총평:** v0.2의 **자연스러운 진입점**으로 매우 적절하다. 추가 보정 필요성 낮음.

### 2-3. `/opportunities` — 오늘의 기회 포착판

| 평가 항목 | 결과 |
|----------|------|
| 기회 후보 / 추격 위험 / 조건 부족 구분 | ✅ 색상·이모지로 명확히 분리됨. |
| TOP10과 혼동되지 않는지 | ⚠️ — 동일 `scan_results`를 보는데 그룹 기준이 다를 뿐이라 사용자는 둘의 차이를 모를 수 있다. |
| 매매 권유 인상 | 없음 ✅ |

**총평:** 데이터는 같은 `scan_results`다. `/reports/[id]`가 "TOP10 표"라면 `/opportunities`는 "등급별 카드"다. **두 화면이 같은 데이터의 다른 시각**임을 화면 어디서도 명시하지 않아 혼동 여지가 있다.

### 2-4. `/bottom-watch` — 바닥 U턴 후보 (v0.2 핵심)

| 평가 항목 | 결과 |
|----------|------|
| 바닥 관찰 / U턴 시도 / U턴 확인 / 추세전환 후보 | ✅ 4단계가 골든크로스 경과 일수로 명확히 정의돼 있고, 섹션 헤더 아래 설명도 있다. |
| 후보 수가 너무 많아 실사용이 어려운가 | ⚠️ **위험 있음.** "바닥 관찰"·"추세전환 후보"는 시장 상황에 따라 수십 개가 될 수 있다. 상한 없이 전부 카드로 출력. |
| "많이 빠진 종목 추천"처럼 보이는가 | ✅ 하단 안내 박스 + 카드 evidence 칩으로 "단순 낙폭 아님"이 잘 표현됨. |
| evidence 근거 라벨이 충분히 도움이 되는가 | ✅ "U턴 검증 충족(60일 중 아래 N일)", "거래대금 회복 (X.X배)", "후행스팬 정상" 등 구체적이라 좋다. |

**총평:** 콘셉트와 표현은 잘 정리됐다. 다만 **카드 수 상한이 없어** "추세전환 후보" 섹션이 60~80개까지 늘어날 수 있고, 그러면 사용자가 어디부터 봐야 할지 막막해진다.

### 2-5. `/leaders` — 주도주·후발주 (v0.2 핵심)

| 평가 항목 | 결과 |
|----------|------|
| 강한 섹터 카드가 보기 좋은가 | ✅ 섹터 헤더에 20일 수익률·상대강도·분류별 카운트가 한 줄에 정리. |
| 4 분류 구분 | ✅ 🥇/🥈/🎯/⚠️ 이모지·색상으로 직관적. |
| 약한 섹터 보조 보기 위치 | ✅ `<details>` 접힘으로 처리되어 강조 정도 적절. |
| "오늘 살 종목 추천"처럼 보이는가 | ⚠️ "🥇 진짜 주도주 후보"는 v0.2 화면 중 **가장 강한 추천 신호 인상**을 줄 수 있다. 안내 박스가 하단에 있어 카드를 먼저 보고 안내를 나중에 보는 동선이 된다. |
| 후보 수 | ⚠️ 강한 섹터 8개 × 각 4분류 × 10개 = **최대 320개 카드**. 실전에서는 80~150개 표시될 가능성 큼. |

**총평:** UI는 잘 짜였지만 **"진짜 주도주 후보" 라벨이 화면에서 가장 강한 시각 자극**을 만든다. 사용자가 자제력 있게 본다면 문제 없지만, 휙 보고 "이걸 사야겠다"로 해석할 위험은 다른 화면보다 크다. 상단 경고를 더 보강하면 좋다.

### 2-6. `/kiwoom-helper` — 키움 자동감시 참고표 (v0.1 + v0.2-4 보강)

| 평가 항목 | 결과 |
|----------|------|
| 실제 입력 전에 보기 편한가 | ✅ 표 구조라 종목별 5개 가격을 한눈에 볼 수 있다. |
| v0.2 라벨이 도움이 되는가 | ✅ 분류 셀에 단계+분류+뉴스 위험이 스택되어 의사결정 보조에 좋다. |
| 가격 라벨이 안전한가 | ✅ 돌파 확인가/눌림 1차·2차/위험 기준가/추격 주의가 — 모두 중립적이고 표 아래 의미 설명까지 있다. |
| 매수 추천표처럼 보이는가 | △ — 상단 노란 경고 박스로 강하게 방어하고 있다. 단, **표 자체가 가격 컬럼 5개를 가지고 있어** 인쇄·캡처해서 다른 곳에 옮기면 경고가 빠지고 가격만 남을 위험이 있다. |
| 사이드카 보강 컨텍스트 카드 | ✅ 표 아래에 별도 섹션으로 evidence/조심할 점이 분리돼 좋다. |

**총평:** 화면 자체로는 안전하다. **위험 시나리오는 화면 밖**(인쇄·캡처·재공유). 표에 가격이 5개 있는 것 자체가 자동감시주문 입력 흐름의 본질이라 줄이긴 어렵다.

### 2-7. `/journal` — 매매일지 초안 (v0.1 + v0.2-4 보강)

| 평가 항목 | 결과 |
|----------|------|
| 복기용 도움 | ✅ 종목별 메모 + 스캔 컨텍스트 + 일지 초안 박스 → 한 페이지에서 복기 가능. |
| "오늘 분류 / 확인 근거 / 조심할 점 / 다음 복기 때 볼 것" 흐름 | ✅ 자연스럽다. 사이드카 라벨이 자동으로 채워져 작성 부담이 적다. |
| 기존 자유 메모와 충돌 | △ — 자유 메모와 일지 초안 박스가 동시 존재. 일지 초안은 **자동 생성**, 자유 메모는 **사용자 입력**. 역할이 다르지만 사용자가 어디에 무엇을 적을지 가이드가 약하다. |

**총평:** 보강이 잘 됐다. 자유 메모와 일지 초안 박스의 **역할 분리 안내**가 한 줄 들어가면 더 자연스럽다.

## 3. 실사용에 좋은 점

1. **표현 원칙 일관성** — 9개 화면 모두 같은 라벨 어휘(진짜 주도주 후보 / 후발주 관찰 / 기회 후보 / 추격 위험 / 조건 부족 / 보유자 대응 / 바닥 관찰 / U턴 시도 / U턴 확인 / 추세전환 후보)를 쓰고 있어 익숙해지면 빠르게 읽힌다.
2. **graceful 처리** — 사이드카 JSON이 없거나 깨져도 모든 화면이 정상 동작한다. v0.1 사용자 경험이 100% 유지된다.
3. **데이터 안전성** — DB write 0건, 신규 테이블 0개. 잘못 돌려도 기존 데이터를 해칠 수 없는 구조.
4. **단계 라벨의 자연스러움** — 바닥 관찰 → U턴 시도 → U턴 확인 → 추세전환 후보 흐름은 시간 축에 따른 진행을 직관적으로 보여준다.
5. **evidence 근거 칩** — "U턴 검증 충족(60일 중 아래 22일)", "거래대금 회복 (2.3배)" 같은 구체적 근거가 라벨 옆에 붙어 있어 "왜 그렇게 분류됐는지"를 알 수 있다.
6. **약한 섹터 접힘 처리** — `/leaders`에서 약한 섹터를 `<details>`로 숨긴 것은 "지금 봐야 할 것"과 "참고용"의 시각적 분리가 잘 됐다.

## 4. 헷갈릴 수 있는 점

1. **`/opportunities`와 `/reports/[id]`의 관계가 불분명** — 같은 `scan_results`를 보는 두 화면이지만 차별점 안내가 없다.
2. **홈 메뉴가 "버전(v0.1/v0.2)" 기준으로 묶임** — 사용자의 자연 흐름("오늘 처음 켰을 때 → 마지막 일지 작성까지")으로 묶이지 않아 어디부터 눌러야 할지 직관성이 약하다.
3. **카드 수 상한 없음** — `/leaders`, `/bottom-watch`는 후보가 많을 때 모든 카드를 다 보여준다. 스크롤 길이가 길어진다.
4. **`/journal`의 자유 메모와 일지 초안 박스 역할 분리 안내 부족** — 둘 다 메모처럼 보이지만 한쪽은 자동, 다른 쪽은 수동이다.
5. **사이드카 라벨 출처 안내 부족** — `/kiwoom-helper`·`/journal`의 v0.2 보강 라벨이 사이드카 JSON에서 왔다는 사실을 화면 안에서 명시하지 않는다. 사용자가 라벨이 어디서 생긴지 모를 수 있다.

## 6. 후보 수가 너무 많은 화면과 개선 방향

| 화면 | 현재 최대 노출 | 개선 방향 |
|------|---------------|-----------|
| `/leaders` | 강한 섹터 8 × 4분류 × 10 = **320 카드(이론상)**. 실측 80~150 추정. | 각 분류 섹션을 **기본 5개 + "더 보기"** 로 접고, 종목 정렬은 (전고점 근접도·거래대금) 기준 상위 우선. |
| `/bottom-watch` | "추세전환 후보" 섹션이 시장 강세 시 **수십~100+ 카드**. | 단계별 **기본 10개 + "더 보기"**. 정렬은 days_below_ma60 큰 순 + 거래대금 회복 큰 순. |

## 8. v0.3 `run_daily.bat` 사이드카 통합 전 확인해야 할 것

v0.3로 넘어가기 전에 검토해야 할 항목:

### 8-1. 안정성 확인
- 사이드카 스크립트 2개가 **연속 7일** 정도 매일 정상 실행되는지(파일 없음/포맷 깨짐/예외 0건).
- 한 번이라도 깨지면 통합 전 원인 분석.

### 8-2. 실행 시간 영향 분석
- 두 사이드카 모두 `fetch_all_prices(use_cache=True)`를 쓰니, ②일봉 갱신 → ⑤일일 스캔 흐름에 끼우면 캐시 적중을 어디서 받는지 분석.
- 캐시 무효화 시점이 ②에 있으므로 사이드카는 ⑤·⑥ 이후 ⑦ 이전에 끼우는 것이 캐시 효율 면에서 좋다.
- 사이드카 1회 실행 시간 측정(추정 1~3분).

### 8-3. 실패 처리 정책
- 사이드카 실행 실패가 **전체 배치를 멈추면 안 된다.** ⑨ 웹 서버는 어떤 상황에서도 뜨도록.
- "사이드카 실패 → 경고만 내고 계속" 정책(⑦·⑧과 동일 톤)으로.

### 8-4. CRLF 유지 절차
- `run_daily.bat`을 편집하면 LF로 바뀌는 사고가 다시 발생하지 않도록 **변환 절차를 작업 직후에 자동 적용**.
- `git diff --ignore-cr-at-eol --stat run_daily.bat` 비어 있는지 확인 절차 명문화.

### 8-5. 단계 번호 재정렬
- 현재 9단계 → 사이드카 2개 추가 시 11단계로 늘어남.
- 모든 `[N/9]` 표시를 `[N/11]`로 일괄 수정. 실수 방지 위해 변환 스크립트 또는 표준 절차 필요.

### 8-6. 결과 동일성 검증
- 사이드카 추가 전후로 `reports`/`scan_results` 행수와 내용이 **완전 동일**한지 비교 검증.

## 결론

v0.2는 **데이터 안전성과 표현 안전성 측면에서 매우 견고하다.** 보호 원칙은 모두 지켜졌고, 사이드카 기반 보강도 graceful 처리가 잘 됐다.

남은 약점은 **사용감 측면의 두 가지**이며, v0.2.1로 작게 보정할 수 있다.

1. 홈→화면 사이의 자연 흐름이 약함 (그룹 라벨이 개발자 관점)
2. 카드 수 상한이 없어 후보가 많으면 사용자가 어디서 시작할지 흐려짐

이 두 가지만 다듬으면 v0.2는 **자동매매를 하지 않고 자기 손으로 입력하며 매일 복기하는 직장인용 보조 도구**로 충분히 자리잡을 수 있다. v0.3 `run_daily.bat` 통합은 이 단계가 안정된 다음에 들어가는 것을 권장한다.
