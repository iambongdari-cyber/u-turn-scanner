## 4. A / B / C / D 안 비교

### A안 — 현재 구조 유지
- **로직**: 변경 없음
- **장점**: 위험 0, 구현 0
- **단점**: 문제 해결 안 됨, 향후 더 길어짐
- **결정**: 기각 (문제 해결 의무 미충족)

### B안 — 3 카드 세로 1열 → 가로 3 열
- **로직**: `grid-cols-1` → `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`
- **장점**:
  - 세로 길이 모바일 ~480px → ~480px(여전)/ PC ~480px → ~160px (lg 1행)
  - 5 카드(`lg:grid-cols-5`)와 시각적 일관 (둘 다 가로 정렬)
  - 구현: 클래스 1줄
- **단점**:
  - 모바일에서는 효과 미미 (여전히 세로)
  - 카드당 폭 좁아짐 → 메트릭/이유 줄바꿈 위험
  - v0.3-15에서 세로 1열을 의도 선택했던 결정 번복
- **위험**: 중 (모바일 미해결, PC 일부 해결)

### C안 — 5+3 카드 한 영역 재배치
- **로직 후보**:
  - C-1: 8 카드 단일 그리드 (2x4 또는 1x8)
  - C-2: 5 카드 위 + 3 카드 옆 (2단 레이아웃, lg 전용)
- **장점**:
  - lg에서 8 카드 일부 한 줄
- **단점**:
  - **의미 분리 무너짐** (v0.3-16: 5 = 대표 사건, 3 = 추가 후보)
  - C-2는 모바일 불가
  - 구현 복잡, 사용자 학습 부담
- **위험**: 중상 (의미 깨짐)
- **결정**: 기각 (v0.3-16 의미 분리 정책과 충돌)

### D안 — "오늘 한 줄 요약" + 접기
- **로직 후보**:
  - **D-1**: 홈 최상단에 한 줄 요약 박스 추가 (기존 카드는 그대로 유지)
  - **D-2**: 기존 5 카드 + 3 카드 영역을 `<details>` 로 접기 가능
  - **D-1 + D-2**: 두 가지 결합 (최대 효과)
- **장점**:
  - **D-1**: 첫 시선에 핵심 정보 한눈 + 기존 카드 회귀 위험 0
  - **D-2**: 세로 길이 ↓↓ (사용자가 의식적으로 펼침)
  - 향후 추가 영역도 같은 접기 패턴으로 확장 가능
  - HTML `<details>` 표준 사용 — JS 없이 구현
- **단점**:
  - D-2는 사용자가 "어디에 정보 있지?" 학습 필요
  - D-1만 적용 시 세로 길이는 줄지 않음 (인지도만 ↑)
- **위험**: 낮음 (D-1) ~ 중 (D-2 학습 부담)

## 5. 추천안 — **D-1 (한 줄 요약 박스) 1차** + D-2/B는 후속

### 5-1. 1차 채택 = D-1
**최상단에 "오늘 한 줄 요약" 박스 추가. 기존 5 카드와 3 카드는 그대로 유지.**

#### 추천 근거
1. **위험 최저**: 새 컴포넌트 1개 추가, 기존 카드 무변경 → 회귀 0
2. **첫 화면 인지도 즉시 향상**: 사용자가 스크롤 없이 핵심 정보 인지
3. **사용자 학습 부담 0**: 새 영역만 노출, 기존 동작 그대로
4. **구현 단순**: 약 30~50 줄 추가
5. **향후 확장 친화**: D-2(접기) 또는 B(가로)는 사용자 피드백 후 결합 가능
6. **모바일·PC 모두 효과**: 한 줄 요약은 모든 디바이스에서 첫 화면 차지

### 5-2. 2차 검토 (사용자 피드백 후)
- **D-1 + D-2** (요약 + 접기): 모바일 세로 길이까지 단축
- **D-1 + B** (요약 + 3 카드 가로): PC 세로 길이 단축

→ **1단계 D-1만 적용 후 1주 사용감 관찰 → 2단계 검토** 권장.
