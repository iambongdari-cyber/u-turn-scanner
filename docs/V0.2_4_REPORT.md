## 4. `/kiwoom-helper` 보강 내용

### 데이터 로딩 (병렬)
```ts
const [reportRes, sidecar] = await Promise.all([
  supabase.from('reports')...maybeSingle(),
  loadSidecarBundle(),
]);
```
- 기존 Supabase 흐름(최신 daily report → scan_results 조회) 그대로 유지
- 사이드카는 병렬 로드 → 추가 지연 최소화

### 표 분류 컬럼 보강 (TableCell 9번째)
세로 스택 형태로 배지 표시:
1. 기존 `final_grade` 라벨(기회 후보 / 추격 위험 / 조건 부족 / 관찰) — **그대로 유지**
2. 사이드카 단계 라벨이 있으면 추가: 바닥 관찰 / U턴 시도 / U턴 확인 / 추세전환 후보 (색상별 배지)
3. 사이드카 분류 라벨이 기존 grade 라벨과 다르면 추가: 진짜 주도주 후보 / 후발주 관찰 등
4. `news_critical = true`이면 빨간 "뉴스 위험 확인 필요" 배지

### 가격 라벨 (그대로 유지)
- 돌파 확인가 (`close × (1 + upside_pct/100)`)
- 눌림 1차 (`buy1_price` = 10일선)
- 눌림 2차 (`buy2_price` = 20일선)
- 위험 기준가 (`stop_loss`)
- 추격 주의가 (`ma60 × 1.2`)

### 상단 안내 (기존 톤 유지 + 짧은 보조 안내 추가)
- 노란 박스(기존): "이 화면은 키움 자동감시주문에 직접 입력하기 전 **참고용으로 정리한 표**입니다. **자동주문 기능이 아니며**, 최종 입력과 주문 여부는 사용자가 키움에서 직접 확인해야 합니다."
- 회색 박스(신규): "v0.2 라벨(바닥 관찰 / U턴 시도 / U턴 확인 / 추세전환 후보 · 진짜 주도주 후보 / 후발주 관찰 / 기회 후보 / 추격 위험)은 바닥 U턴 후보와 주도주·후발주 분류를 **함께 참고하기 위한 보조 표시**입니다. 어떤 라벨도 매매 권유가 아닙니다."

### 하단 "사이드카 보강 컨텍스트" 섹션 (신규)
- 표 종목 중 사이드카에서 의미 있는 라벨/근거가 있는 종목만 카드 리스트로 추가 표시
- 카드 구성:
  - 종목명 + 종목코드 (기존 `/stocks/[ticker]` 링크)
  - 단계 / 분류 / 섹터 / 뉴스 위험 배지
  - **확인 근거** (emerald 칩) — `scan_dump.evidence` + `sector_dump.evidence` 합쳐서 중복 제거 후 표시
  - **조심할 점** (orange 칩) — `chase_risk_strong.reasons` 표시

### 사이드카 부재/오류 시 처리
- 둘 다 missing → 회색 작은 박스 안내 ("사이드카 분석 데이터가 아직 없습니다. `scripts/scan_dump.py` · `scripts/sector_dump.py` 실행 후 일부 라벨이 보강됩니다.")

- **모든 경우 기존 표·가격 라벨은 항상 정상 표시** → 회귀 위험 0

### 카드 헤더 배지 (스택)

### 일지 초안 박스 (신규 — 보라색 톤)

- **다음 복기 때 볼 것:** 정적 안내 — "골든크로스 경과·이격도 변화·거래대금 흐름·섹터 강도 유지 여부를 함께 점검합니다."

## 6. 사이드카 JSON 파일 없음 / 손상 시 처리 방식

`app/_lib/sidecar.ts`의 `loadSidecarBundle()`이 4가지 상태 플래그를 반환:

```ts
interface SidecarBundle {
  contexts: Map<string, SidecarTickerContext>;
  scanMissing: boolean;       // scan_dump 파일 없음
  scanError: boolean;         // scan_dump 파싱 실패
  sectorMissing: boolean;     // sector_dump 파일 없음
  sectorError: boolean;       // sector_dump 파싱 실패
  hasAny: boolean;            // 둘 중 하나라도 정상 로딩
}
```

| **둘 중 하나 missing** | 컨텍스트 맵에서 부족분만 빠지고 나머지는 정상 표시. 별도 경고 없음(조용히 생략) |

## 부록. 사용자 PC 검증 순서

cmd(프로젝트 폴더)에서:

```bat
REM 1) 사이드카 JSON 최신화 (없거나 오래된 경우)
.venv\Scripts\python.exe scripts\scan_dump.py
.venv\Scripts\python.exe scripts\sector_dump.py

REM 2) 빌드 통과 확인
npm run build

REM 3) 개발 서버 (회귀 + 보강 확인)
npm run dev
```

브라우저 `http://localhost:3000`에서:
1. `/kiwoom-helper` 진입
   - 상단 노란 박스 + 회색 v0.2 보조 안내
   - 표의 분류 셀에 단계/분류 배지가 누적되어 보이는지
   - 표 아래 "사이드카 보강 컨텍스트" 카드 섹션이 일부 종목에 대해 표시되는지
2. `/journal` 진입
   - 카드 헤더에 단계/분류 배지가 사이드카 기반으로 갱신되는지
   - "일지 초안 — 관찰·복기 보조" 보라색 박스에 4가지 항목(오늘 분류 / 확인 근거 / 조심할 점 / 다음 복기 때 볼 것)이 채워져 있는지
3. 기존 10개 화면 회귀 없음 확인
4. **(선택) graceful 빈 상태 검증** — cmd에서:
   ```bat
   ren logs\sidecar\scan_dump_latest.json _hidden1.json
   ren logs\sidecar\sector_dump_latest.json _hidden2.json
   ```
   `/kiwoom-helper`·`/journal` 새로고침 → 각 화면 상단에 "사이드카 분석 데이터가 아직 없습니다…" 회색 안내가 짧게 표시되고 기존 표/카드는 정상 → 원상복귀:
   ```bat
   ren logs\sidecar\_hidden1.json scan_dump_latest.json
   ren logs\sidecar\_hidden2.json sector_dump_latest.json
   ```

## 부록 — 화면 톤 원칙 재확인

### `/kiwoom-helper`
"이 화면은 키움 자동감시주문에 직접 입력하기 전 **참고용으로 정리한 표**입니다."

v0.2 라벨은 어디까지나 **함께 참고하기 위한 보조 표시**이며, 가격은 모두 관찰 보조 라벨입니다. 자동주문 버튼·수량 제안·주문 방식 제안은 일절 없습니다.

### `/journal`
"관찰·복기 보조" 톤 유지. 일지 초안 박스는 사용자의 판단을 대신하지 않고, **확인 근거·조심할 점·다음 복기 때 볼 것**을 자동으로 채워주는 보조 역할만 합니다. 사이드카 근거가 없을 때는 "직접 메모로 채워 주세요"라고 안내해 **사용자 본인의 판단 기록**임을 분명히 합니다.
