# U-Turn Scanner — v0.6.1 핫픽스 보고서 ("오늘의 결론 ↔ 매매계획 기록 대상" 1순위 종목명 동기화)

> **작성일:** 2026-06-13
> **선행:** `V0.6_REPORT.md`
> **문제:** `/beginner` 화면에서 §0 오늘의 결론의 자연어 안내 종목명("오늘은 시프트업 1개만 검토하세요.")과 §5 매매계획 기록 대상 카드의 1순위 종목명(NAVER)이 다르게 표시되어 사용자가 "어떤 종목이 진짜 1순위" 인지 알 수 없는 상태.

---

## 1. 원인 분석

v0.6 의 종목 선정이 **두 곳에서 서로 다른 입력으로** 호출되었습니다.

| 위치 | 시점 | 입력 | 출력 |
|---|---|---|---|
| `beginner_data.ts` → `judgeMarketRegime()` 의 `topPickName` 인자 | **서버 SSR** | `scan.candidates_bottom` (신규 후보만), `plans` 모름, `hasHoldingOrReserved = false` 가정, `regimeMode` 미적용 | "시프트업" |
| `TopBrief.tsx` → `selectTradePlanTargets()` | **클라이언트 mount 후** | 동일 후보 + localStorage 의 `plans` (보유/예약 반영), `regimeMode` 적용 | "NAVER" |

→ 가중치 계산 입력이 다르므로 결과가 어긋남. 게다가 사용자 명세 §3 "별도 추천 로직 중복 사용 금지" 도 위반.

## 2. 해결 방향

**한 곳에서 계산 → 양쪽에 동일 데이터 전달** 으로 구조 통일:

1. **서버 측 `topPickName` 전달 제거** — `beginner_data.ts` 의 `judgeMarketRegime` 호출에서 종목명 인자 빼고, `market_regime.ts` 의 `conclusionText` 는 "종목명 없는 fallback 문구" 로 빌드.
2. **CoachShell 클라이언트 컴포넌트 신규** — `/beginner` 페이지에서 §0 오늘의 결론 + §1~§4 (시장/컨디션/추천/금지) + §5 매매계획 기록 대상을 한 wrapper 안에서 렌더. `selectTradePlanTargets()` 를 **단 한 번만 호출** 하고 그 결과를 `TodayConclusion` 과 `MustSeeSection` 양쪽에 전달.
3. **TodayConclusion 클라이언트화** — CoachShell 로부터 받은 `topPickName` 으로 `buildConclusionText()` 를 다시 호출해 자연어 결론을 1순위 종목명으로 동기화.
4. **GPT 리포트도 동일 동기화** — `GptReportButton` 의 generate 안에서 `selectedNewTargets[0]?.name` 으로 `marketRegime.conclusionText` 를 한 번 더 덮어쓰기.

→ 모든 경로가 동일한 `selectTradePlanTargets()` 호출 결과의 `[0]` 을 참조. **중복 로직 0건**.

## 3. 사용자 명세 §2 fallback 문구 정리

`buildConclusionText(regime, mode, topPickName)` 의 `topPickName === null` 분기를 사용자 명세대로 변경:

| Regime | `topPickName === null` 일 때 |
|---|---|
| BULL | "오늘은 강세장 흐름이지만 매매계획 기록 대상이 없습니다.\n신규 진입보다 관망이 우선입니다." |
| NEUTRAL | **"오늘은 신규 진입보다 관망이 우선입니다."**\n"예약매수 대기 / 보유종목 점검에 집중하세요." |
| BEAR | (그대로 — 신규 진입보다 방어가 우선 안내) |
| DANGER | (그대로 — 현금 비중 최우선 안내) |
| UNKNOWN | "시장 데이터가 부족하고 매매계획 기록 대상도 없습니다.\n오늘은 신규 진입보다 관망이 우선입니다." |

→ 사용자 명세 §2 "매매계획 기록 대상이 없으면 종목명을 표시하지 말고 '오늘은 신규 진입보다 관망이 우선입니다.' 형태로 출력" 충족.

## 5. 데이터 흐름 (v0.6.1 통합)

```
[서버 SSR]
  loadBeginnerData(date)
    → judgeMarketRegime({ market, summary, sector })  // topPickName 미전달
       → regime.conclusionText = fallback 문구 ("종목명 없음 케이스")

  page.tsx
    <CoachShell regime={data.marketRegime} rows={data.rows} ... middleBoxes={...} />

[클라이언트 mount]
  CoachShell useEffect:
    plans = loadAllPlans()
    briefItems = buildAllBriefItems(rows, plans, priceMap, prevMap)
    selectedNewTargets = selectTradePlanTargets(newItems, hasHoldingOrReserved, regime.mode)
                          ↑ 단 한 번만 호출

    topPickName = selectedNewTargets[0]?.name ?? null

  렌더:
    <TodayConclusion regime={regime} topPickName={topPickName} />
      → buildConclusionText(regime.regime, regime.mode, topPickName) 재호출
      → 종목명 동기화된 conclusionText 표시
    {middleBoxes}  (§1~§4)
    <MustSeeSection selectedNewTargets={selectedNewTargets} />
      → 동일한 selectedNewTargets 사용 → 1순위 카드 = TodayConclusion 의 종목명

[GPT 리포트 생성]
  GptReportButton.generate():
    동일 buildAll() 호출 → 동일 selectedNewTargets
    regimeForReport.conclusionText = buildConclusionText(regime, mode, selectedNewTargets[0]?.name)
    buildGptReport({ ..., marketRegime: regimeForReport })
```

→ **모든 경로에서 동일 입력 → 동일 출력**. 사용자 명세 §3 충족.
