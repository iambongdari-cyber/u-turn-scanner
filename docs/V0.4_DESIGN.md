# U-Turn Scanner — v0.4 설계 보고서 (코드 미수정, 설계만)

> **작성 기준일:** 2026-06-08
> **선행 단계:** v0.3-19 (다시 볼 후보 판단 보조 카드 고도화) 완료
> **목표:** 초보 직장인 사용자가 **"오늘 뭘 봐야 하는지" 한눈에 판단** 할 수 있도록 새 "초보자 모드" 화면 도입. 3 카테고리 분류 + AI 행동 제안 + 위험도 + 가상 매매 구조 준비.

## 1. v0.4 목표

### 1-1. 핵심 변화 — "보여주기" → "판단 돕기"
기존 U-Turn Scanner는 TOP10·변화 요약·다시 볼 후보 등 **정보 노출** 중심. v0.4는 사용자 페르소나(왕초보 주린이 + 매일 장중 못 보는 직장인)에 맞춰 **행동 결정 보조** 로 전환:

| 영역 | 기존 (~v0.3-19) | v0.4 |
|---|---|---|
| 우선 답할 질문 | "오늘 무엇이 바뀌었나" | **"오늘 뭘 봐야 하나, 사야 하나 기다리나"** |
| 화면 정보 밀도 | 풍부 (5+3 카드 + 한 줄 요약) | **최소** (카테고리당 최대 3 종목) |
| 안전 안내 | "관찰 보조" | "관찰 / 분할매수 검토 / 보유 / 일부매도 / 매도 / 제외" 명시 + 항상 사용자 최종 판단 |
| 검증 가능성 | 없음 | **가상 매매 기록**으로 AI 판단 사후 검증 가능 (구조만 준비) |

### 1-2. 사용자 페르소나 (재확인)
- **왕초보 주린이** — 전문 지표 이해 어려움
- **매일 장중 못 보는 직장인** — 퇴근 후 빠른 결정 필요
- **시간 부족** — 많은 종목 검토 불가
- **위험 회피 우선** — 큰 손실 절대 회피

### 1-3. v0.4 핵심 기능 (사용자 명세)
1. 종목 **3 대 카테고리 분류** (바닥 반등 후보 / 현재 주도주 / 다음 주도주 후보)
2. **AI 행동 제안** 6 단계 (관찰 / 분할매수 검토 / 보유 / 일부매도 검토 / 매도 검토 / 제외)
3. 종목 카드 7 요소 (종목명 / 카테고리 / 행동 제안 / 한 줄 설명 / 선정 이유 ≤3 / 위험도 / 주의 문구)
4. 새 화면 — **초보자 모드** (기존 TOP10 유지 + 신규 섹션)
5. **가상 매매 구조** 준비 (DB 변경 없이 인터페이스만)
6. 안전 안내 항상 — "최종 판단은 사용자 책임"

## 5. 카테고리 분류 로직 설계

### 5-1. 3 카테고리 정의 + 데이터 매핑

| 카테고리 | 핵심 의미 | 호스트 데이터 매핑 | 호스트 수량 (오늘) |
|---|---|---|---|
| **① 바닥 반등 후보** | 크게 하락 후 바닥권에서 거래량 살아남 | `scan_dump.candidates_bottom[]` 중 `stage ∈ {'바닥 관찰', 'U턴 시도', 'U턴 확인'}` AND `value_ratio ≥ 1.5` (거래대금 회복) | 340개 → 필터 후 ~50개 추정 |
| **② 현재 주도주** | 시장에서 강한 상승 흐름, 거래대금 유지, 추세 살아있음 | `sector_dump.sectors_strong[].leaders[]` (진짜 주도주 후보) | **2개** ⚠ (부족 가능) |
| **③ 다음 주도주 후보** | 주도주는 아니지만 거래량·수급·업종 흐름 좋아짐 | `sector_dump.sectors_strong[].followers[]` (후발주 관찰) | 14개 |

### 5-2. 카테고리별 우선순위 정렬 (각 ≤3 종목)
| 카테고리 | 정렬 기준 | 안전 폴백 |
|---|---|---|
| ① 바닥 반등 후보 | `value_ratio` 내림차순 (거래대금 회복 강도) + `stage` 우선순위(U턴 확인 → U턴 시도 → 바닥 관찰) | 부족 시 그대로 표시 |
| ② 현재 주도주 | `return_20d` 내림차순 (20일 성과 강도) | **부족 시 (오늘 2개만)** → "오늘 강한 주도주 후보 부족" 안내 표시 + 가능한 만큼 표시 |
| ③ 다음 주도주 후보 | `near_high_pct` 내림차순 (전고점 근접도) + `return_20d` 보조 | 부족 시 그대로 |

### 5-3. 위험도 계산
| 위험도 | 매핑 |
|---|---|
| **낮음** | ② 현재 주도주 (추세 안정 + 작은 이격) AND `disparity_pct ≤ 15%` |
| **보통** | ③ 다음 주도주 후보 (관찰 단계) OR ② 주도주 중 `disparity_pct 15~20%` |
| **높음** | ① 바닥 반등 후보 (실패 가능성 ↑) OR `news_critical = true` OR `disparity_pct > 20%` (추격 위험) |

## 6. AI 행동 제안 로직 설계

### 6-1. 6 단계 정의 (사용자 명세)

| 행동 제안 | 의미 | 색 |
|---|---|---|
| **관찰** | 아직 진입 전, 흐름만 지켜보기 | sky |
| **분할매수 검토** | 신호 충족, 소액부터 나눠 진입 고민 | emerald |
| **보유** | 이미 보유 중인 경우 유지 | indigo |
| **일부매도 검토** | 일부 차익 실현 고민 | amber |
| **매도 검토** | 신호 약화, 매도 고민 | orange |
| **제외** | 후보권 이탈, 관심 해제 | red |

### 6-2. 행동 제안 매핑 규칙 (카테고리 × 상태)

| 카테고리 | 상태 (조건) | 행동 제안 |
|---|---|---|
| **① 바닥 반등 후보** | stage = '바닥 관찰' + 거래대금 보통 | **관찰** |
| | stage ∈ {'U턴 시도', 'U턴 확인'} + value_ratio ≥ 2.0 | **분할매수 검토** |
| | news_critical = true | **관찰** (주의 문구 강화) |
| **② 현재 주도주** | disparity_pct ≤ 15% + 추세 유지 | **보유** |
| | disparity_pct 15~20% (이격 확대) | **관찰** (보유 중이면 일부매도 검토) |
| | chase_risk 영역 (disparity_pct > 20%) | **일부매도 검토** |
| **③ 다음 주도주 후보** | followers 위치 | **관찰** |
| | followers + near_high_pct ≥ 90% | **분할매수 검토** |
| 모든 카테고리 | change_type = 'DEPARTED' OR disparity_pct < 0 (60일선 이탈) | **매도 검토** 또는 **제외** |
| | 본 사이클 데이터 부족 | **관찰** (기본값) |

### 6-3. 행동 제안 안전 안내
모든 카드에 항상 작은 회색 글씨로 다음 문구 표시:
> "이 의견은 자동 분석 결과이며 실제 투자 판단은 사용자가 최종 결정해야 합니다."

추가로 화면 상단 (영역 헤더 아래)에:
> "초보자 모드는 매수/매도 추천이 아닙니다. **위험도 '높음'은 특히 신중**하게 검토하세요."

### 6-4. 한 줄 설명 자동 생성 (`buildOneLiner`)

각 카테고리별 자연 문구:

| 카테고리 | 패턴 예시 |
|---|---|
| ① 바닥 반등 후보 | "최근 하락 후 거래량이 살아나고 있어 회복 여부를 지켜볼 종목입니다." |
| ② 현재 주도주 | "최근 20일 [N]% 상승하며 강한 흐름을 보이는 종목입니다." |
| ③ 다음 주도주 후보 | "현재 주도주를 따라가는 후발 종목으로 1~2주 관찰할 후보입니다." |

### 6-5. 선정 이유 (≤3, 사이드카 evidence 활용)

| 카테고리 | 이유 예시 |
|---|---|
| ① 바닥 반등 후보 | "60일선 근처 + U턴 검증 충족", "최근 거래대금 X배 회복", "뉴스 위험 없음" |
