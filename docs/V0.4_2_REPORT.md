# U-Turn Scanner — v0.4-2 긴급 수정 보고서 ('꼭 보세요' 기준 재정의)

> **작성일:** 2026-06-13
> **선행:** `V0.4_1_REPORT.md`
> **요청:** v0.4-1 의 `/beginner` 화면에서 "꼭 보세요 (141)" 처럼 표시되는 문제 — 사용자가 다시 골라야 하는 화면이 됨. v0.4-2 는 "오늘 실제로 행동해야 하는 종목"만 보여주는 화면으로 재정의.

---

## 1. 구현 요약

v0.4-1 까지는 "TODAY 등급 = AI 매수 + 위험 낮음·보통 + U턴 4/5 이상 + 거래대금 회복" 이었지만, 호스트 데이터(340 후보) 에서는 이 조건이 **너무 넓어** 100~150 개가 동시에 매칭됐습니다. 사용자가 본업이 우선이고 퇴근 후 10 분 안에 확인해야 하므로, 100+ 개의 카드는 "다시 고르는 화면" 이 됩니다.

v0.4-2 는 **"꼭 보세요"의 기준을 "후보 조건 충족" 에서 "오늘 실제 행동이 필요한 종목"** 으로 바꿉니다. 핵심은 신규 후보 노출을 **`selectTradePlanTargets()`** 가 선정한 **1~3 개로 엄격히 캡** 하는 것입니다. 보유/예약이 있으면 신규는 최대 1 개, 아주 강한 후보(U턴 5/5 + 위험 낮음) 가 2 개 이상일 때만 최대 3 개. 그 외 모든 후보는 화면에서 "관심 후보" 또는 "참고 후보" 접힘 영역으로 이동.

추가로 (1) "오늘 결론" 을 "오늘 할 일은 N개입니다" 형식 + 번호 매긴 액션 리스트로 변경, (2) **"오늘 할 일" 체크리스트** 영역 신규 (localStorage 저장), (3) **"오늘 신규로 볼 종목 138건"** 같은 큰 숫자 문구 전면 제거, (4) **관심/참고 후보 숫자 강조 제거** (보조 회색 작은 텍스트), (5) GPT 리포트도 행동 중심 6 섹션으로 단순화 — 신규 후보 전체 나열을 맨 아래 "참고 후보 요약" 으로 축소.

저장 구조 / 사이드카 / 스캔 산식 / 기존 5 화면은 모두 무변경.

## 3. "꼭 보세요" 기준 재정의

### 3-1. 새 기준 (사용자 명세 §1)

| 분류 | 노출 대상 |
|---|---|
| 보유종목 | 매도/일부매도/손절/목표가 근접/추가매수 판단이 필요한 종목 → MyPlansSection |
| 예약매수 대기 | 예약 유지/취소/가격 재검토가 필요한 종목 → MyPlansSection |
| 신규 후보 | `selectTradePlanTargets()` 가 선정한 **오늘 매매계획 기록 대상 1~3개만** → MustSeeSection |

신규 후보는 "후보 조건 충족" 이 아니라 **"오늘 매매계획 기록 대상으로 선정"** 된 종목만.

### 3-2. `selectTradePlanTargets()` 알고리즘 (today_brief.ts)

```
입력: 신규 후보 중 URGENT/TODAY 등급, 보유/예약 존재 여부
1. 점수: U턴 충족 × 10 + URGENT 가산 30 + 위험 낮음 8/보통 3 + 거래대금 회복 5 + 60일선 회복 3 + 이격 <5% 가산 3 + AI BUY 5
2. 정렬: 점수 내림차순
3. 분기:
   - 보유/예약 있음 → 상위 1개만
   - 아주 강한 후보(U턴 5/5 + 위험 낮음) 2개 이상 → 상위 3개
   - 그 외 → 상위 1개
4. 비어있으면 → 0개
```

### 3-3. TODAY 등급 기준 강화 (사용자 명세 §2)

| v0.4-1 | v0.4-2 |
|---|---|
| AI BUY + 위험 LOW/MED + U턴 강함 이상 + 4/5 이상 + 거래대금 회복 | + 60일선 회복 + 이격 < 12% + 추격 위험 아님 |
| 이격 ≥ 18% → HIDDEN | 이격 ≥ 15% → HIDDEN |

호스트 데이터 기준 예상 TODAY 신규: 약 0~10 건. 그 중 selectTradePlanTargets 가 1~3 개로 캡.

### 3-4. 100+ 개 노출 시 → 1~3 개로 자연스럽게 줄어드는 흐름

1. URGENT/TODAY 등급 종목이 10~20 개 잡혀도
2. selectTradePlanTargets 가 점수 기준 상위 1~3 개만 통과
3. MustSeeSection 은 그 1~3 개만 렌더
4. 나머지는 관심 후보 / 참고 후보 접힘 영역에 보존 (삭제 X)
