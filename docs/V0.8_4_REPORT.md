## 2. `buildJudgmentReport` 설명

`app/_lib/gpt_report.ts` 에 신규 export.

### 시그니처
```ts
export interface JudgmentReportInput {
  base_date: string | null;
  marketRegime?: MarketRegimeResult | null;
  marketStrength?: MarketStrength | null;
  capStyle?: CapStyle | null;
  sectorFlow?: SectorFlow | null;
  stockCharacter?: StockCharacterResult | null;
  tomorrowAction?: TomorrowAction | null;
  strategyCondition?: StrategyConditionResult | null;
  topPick?: TodayBriefItem | null;
}
export function buildJudgmentReport(input: JudgmentReportInput): string;
```

### 역할
v0.8 흐름(시장 상태 / KOSPI·KOSDAQ 강도 / 대형주·중소형주 / 업종 흐름 / 대장주 / 1순위 종목 성격 / 내일 행동)을 묶어 ChatGPT 에 그대로 붙여넣을 수 있는 6 섹션 마크다운을 만든다.

### 통합 빌더
```ts
export function buildCombinedReport(
  judgment: JudgmentReportInput,
  detailed: GptReportInput,
): string;
```
- 1순위: `buildJudgmentReport` (v0.8 판단 리포트, 6 섹션)
- 구분선 + 헤더
- 2순위: `buildGptReport` (기존 v0.7 상세 행동 리포트, 0~8 섹션) — "부록: 기존 상세 행동 리포트"

기존 `buildGptReport` 는 **삭제하지 않고** 그대로 유지. 다른 코드에서 직접 부르고 싶다면 계속 사용 가능.

## 3. 리포트 6 섹션 구조

```
# U턴스캐너 오늘의 판단 리포트
> 생성일
> 개인 기록용 AI 판단입니다.
> 자동매매가 아니며 실제 주문은 사용자가 키움에서 직접 입력합니다.
> 최종 판단은 사용자 본인 책임입니다.

## 1. 오늘 장 요약
- 오늘 시장은 보합장 62점 입니다.
- KOSPI 강도 / KOSDAQ 강도 / 상대강도
- 대형주·중소형주 흐름

## 2. 돈이 들어온 곳
- 오늘 강한 업종 TOP 3
- 가장 뚜렷한 주도 업종
- 업종별 점수 + 20일 수익률 + 주도 표시
- 대장주 후보 (준대장주 포함 안내)

## 3. 오늘의 1순위 종목
- 종목명/티커
- 5등급 성격 (주도주 추종 / 후발주 진입 / 개별 U턴 / 끝물 추격 위험 / 관망)
- 위험도 + 행동 가능 여부 + 판단 요약 + 근거

## 4. U턴스캐너 판단
- 왜 이 종목을 볼 수 있는지 (why_picked)
- 왜 조심해야 하는지 (이격/위험/성격)
- 시장 흐름과 맞는지
- 업종 흐름과 맞는지
- 전략 컨디션과 맞는지

## 5. 내일 행동 지시
- 신규 진입 가능 여부 / 최대 종목 수 / 매매 강도
- 우선 종목 + 예약매수 가능 여부
- 내일 해야 할 행동 (tomorrowAction.summaryLines)
- 금지 행동 (tomorrowAction.mustNotDo)

## 6. ChatGPT에게 요청
- "내가 직장인 초보 투자자라는 점을 고려해서..." 5문항 체크리스트
  (사용자 명세 §4 그대로)

---

# 부록: 기존 상세 행동 리포트
(기존 v0.7 buildGptReport 결과)
```

## 6. 데이터 fallback 처리

`buildJudgmentReport` 는 어떤 입력이 빠져도 throw 하지 않고 보수 문구로 처리한다.

| 누락 입력 | 출력 처리 |
| --- | --- |
| `marketRegime` 없음 | §1: "- 시장 판단 데이터가 부족합니다." |
| `marketStrength` 없음 / insufficient | §1: "- KOSPI/KOSDAQ 세부 흐름 데이터가 부족합니다." 또는 `strength.narrative` 그대로 |
| `capStyle` 없음 | §1 의 대형주/중소형주 줄 자체를 생략 |
| `sectorFlow` 없음 | §2: "- 업종 흐름 데이터가 부족합니다." |
| `sectorFlow.topThree` 비어 있음 | §2: `narrative` 그대로 + `insufficient` 안내 |
| `stockCharacter` 없음 / `topPick.row` null | §3: "- 오늘 1순위 종목이 없어 신규 진입보다 관망이 우선입니다." / "- 1순위 종목 성격 판단이 부족합니다." |
| `tomorrowAction` 없음 | §5: "- 내일 행동 지시 데이터가 부족합니다." + 손절가 원칙 안내 |
| `strategyCondition` 없음 | §4 마지막 항목: "전략 컨디션 데이터 부족 (보유/예약 기록 없음)" |

§6 (ChatGPT 에게 요청) 은 입력과 무관하게 **항상 동일 문구** 출력.

## 8. 보호 원칙 준수 여부

| 원칙 | 준수 방식 |
| --- | --- |
| 자동매매 / 키움 주문 연동 / 실제 매수·매도 버튼 금지 | 추가 없음. 리포트 생성/복사 한정. |
| Supabase write 추가 금지 | 없음. 모든 계산 클라이언트/SSR 메모리 안. |
| 추천 종목 무작정 증가 | §3 은 1순위 1종목만, §5 는 `tomorrowAction.maxNewCount` 그대로. |
| 화면 복잡화 금지 | 버튼/문구/섹션 제목만 변경. 새 박스 없음. |
| 손절가 없는 매수 금지 | §4·§5 모두 "손절가 없는 매수 금지" 그대로 유지. |
| 위험구간/전략 컨디션 위험에서 신규 진입 금지 | tomorrowAction 자체가 강제 차단. 리포트도 그 결과를 그대로 노출. |
| 하루 볼 종목 수 제한 | tomorrowAction.maxNewCount 그대로 표시. |
| 1순위 종목도 끝물 추격이면 제외 | §3 에서 성격이 `LATE_CHASE_RISK`/`WATCH_ONLY` 이면 `isActionable=false` 그대로 노출, §4 에서 "내일 신규 진입에서 제외 권장" 명시. |
| 최종 판단은 사용자 본인 | 상단 면책 + §6 ChatGPT 요청 5문항으로 강제 재검토. |
| GPT에게 다시 물어볼 수 있어야 함 | §6 5문항 그대로. 버튼명도 그 행동을 그대로 표현. |
| 모바일 별도 페이지 `/beginner/gpt-report` 유지 | 경로/구조 변경 없음. SSR/CSR 동일 동작. |
| GPT 리포트 구조 변경 금지 (기존 v0.7 부분) | 기존 `buildGptReport` 무변경. 단지 위에 신규 판단 리포트가 추가되었을 뿐. |
| GPT 버튼명 변경 금지 (이전 버전 한정) | v0.8-4 에서 사용자가 명시적으로 라벨 변경을 요청한 단계이므로 적용. |

## 9. 테스트 방법

호스트:

```
npm run build
npm run dev
```

`/beginner` 접속 후:

1. 화면 맨 아래 섹션 제목이 **"💬 GPT에게 다시 물어보기"** 로 바뀌었는지.
2. PC: 버튼 라벨 **"💬 GPT에게 다시 물어보기"** 확인.
3. PC: 버튼 클릭 → 같은 카드 안에서 인라인 펼침 → textarea 안 본문 최상단이 **"# U턴스캐너 오늘의 판단 리포트"** 로 시작하는지.
4. 본문 안에 다음 6 섹션 헤더가 있는지:
   - `## 1. 오늘 장 요약`
   - `## 2. 돈이 들어온 곳`
   - `## 3. 오늘의 1순위 종목`
   - `## 4. U턴스캐너 판단`
   - `## 5. 내일 행동 지시`
   - `## 6. ChatGPT에게 요청`
5. 본문 중간에 `# 부록: 기존 상세 행동 리포트` 가 있고, 그 아래 기존 0~8 섹션이 그대로 붙어 있는지.
6. [자동 복사 시도] / [전체 선택] 모두 정상 동작.
7. 모바일 폭(viewport <768px) 으로 줄여서 본 뒤 모바일 링크 `💬 GPT에게 다시 물어보기` 클릭 → `/beginner/gpt-report` 로 이동, 페이지 상단 제목도 동일 라벨.
8. `/beginner/gpt-report` 본문 최상단도 `# U턴스캐너 오늘의 판단 리포트` 로 시작.
9. 기존 매매계획 기록/예약/체결/매도완료 기능이 그대로 동작.
10. 시장 데이터가 부족한 날짜(`?date=` 로 과거 빈 날짜) 에 진입해도 빌드/런타임 에러 없이 "데이터가 부족합니다" 안내로 fallback 되는지.

### 샌드박스 검증 제약
프로젝트 mount 캐시 stale 이슈로 샌드박스 측 `tsc --noEmit` 결과는 신뢰할 수 없음 (이전 v0.8-3 단계에서도 동일). 호스트에서 `npm run build` 통과 여부로 최종 확인 부탁드립니다. Read tool 로 확인한 호스트 측 파일은 모두 정상 구조입니다.
