# U-Turn Scanner — v0.3-18 / hotfix 가격 업데이트 404 안전 보정 보고서

> **작성 기준일:** 2026-06-08
> **이슈:** `run_daily.bat` [2/12] Price update 단계에서 `urllib.error.HTTPError: HTTP Error 404: Not Found` 발생 (pandas io common.py urlopen 경유)
> **결과:** `scripts/load_stocks.py` 단일 파일 안전 보정. 외부 데이터 소스(KRX/네이버 등) 변경에 대응. TOP10/스캔/백테스트/JSON 구조 모두 무변경.

### 1-4. 진단 결론
**가장 가능성 큰 원인**: `fdr.StockListing(market)` 가 KRX/네이버 등 외부 사이트 페이지 구조 변경으로 **HTTP 404** 발생 → `fetch_universe`가 try/except 없이 호출되므로 → main 전체 중단 → run_daily.bat 의 `[ERROR] Price update step failed` → `goto :end` 트리거.

`FinanceDataReader`는 KRX/네이버 페이지를 백엔드로 사용 (load_stocks.py line 5~6 주석에 명시) → 외부 사이트가 URL 변경하면 fdr 라이브러리 사용자 측에서 즉시 영향.

**종목별 fail은 이미 보호됨**: `_fetch_and_store` (line 421~430)의 try/except로 한 종목 실패해도 전체 진행 중단 안 됨 — 사용자 요구사항 4 "실패한 종목 1개 때문에 전체 중단되지 않도록 WARN 처리"는 **이미 충족 중**.

## 2. 적용한 보정 (3 곳)

### 2-1. `fetch_universe()` 에 try/except + WARN + 빈 리스트 반환

```python
def fetch_universe(market: str) -> list[dict]:
    """...
    v0.3-18 hotfix:
      fdr.StockListing 은 KRX/네이버 페이지 구조 변경 시 HTTP 404 등으로 raise 될 수 있다.
      그 경우 원래는 main 전체 중단이었지만, 이제는 WARN 출력 + 빈 리스트 반환만 한다.
      호출자(main)가 prices-only 모드이면 DB stocks 테이블 fallback 으로 일봉 갱신을 계속 진행한다.
      → 분석/필터/적재 로직(스캔/TOP10/백테스트)에는 영향 0.
    """
    print(f"[목록] {market} 종목 가져오는 중 (FinanceDataReader)…")
    try:
        df = fdr.StockListing(market)
    except Exception as e:
        print(f"[WARN] FinanceDataReader StockListing({market}) 실패: {type(e).__name__}: {e}")
        print( "       → 외부 데이터 소스(KRX/네이버 등) 페이지 구조 변경 가능성.")
        print( "       → prices-only 모드면 DB stocks 테이블 fallback 으로 진행.")
        return []
    ...
    if not code_col or not name_col:
        print(f"[WARN] StockListing 컬럼 인식 실패. 실제 컬럼: {cols}")
        print( "       → 외부 사이트 컬럼명 변경 가능성. WARN 후 빈 리스트 반환.")
        return []
```
- 기존 `sys.exit(...)` 대신 **WARN + 빈 리스트** → main 전체 중단 안 됨
- 예외 종류와 상세 메시지 출력 → 사용자가 정확한 에러 진단 가능

def fetch_universe_from_db() -> list[dict]:

    """
    print("[fallback] DB stocks 테이블에서 종목 목록 보강 중…")
    ...

### 2-3. `main()` 에 universe 빈 시 fallback 분기

```python
markets = ['KOSPI', 'KOSDAQ'] if args.market == 'ALL' else [args.market]
universe: list[dict] = []
for m in markets:
    universe.extend(fetch_universe(m))

# v0.3-18 hotfix: fdr.StockListing 이 외부 사이트 변경(HTTP 404 등)으로 모두 실패해
# universe 가 비어있는 경우, prices-only 모드면 DB stocks 테이블에서 ticker/name 보강.
# → 그날 신규 상장 종목은 빠질 수 있지만 기존 종목 일봉 갱신은 막히지 않음.
# stocks-only 모드(=stocks 테이블을 새로 채우려는 경우)에는 fallback 적용하지 않는다.
if not universe and args.prices_only:
    print("[WARN] FinanceDataReader 종목 목록이 비어 있음. DB stocks 테이블 fallback 시도.")
    universe = fetch_universe_from_db()
    if not universe:
        print("[ERROR] DB stocks 테이블에서도 종목을 가져오지 못해 prices 적재 단계 진행 불가.")
        sys.exit(2)
```

#### 행동 매트릭스
| `fdr.StockListing` 결과 | 모드 | 동작 |
|---|---|---|
| 정상 | 모든 모드 | 기존 그대로 |
| 실패 (예: 404) | `--prices-only` (= run_daily.bat [2/12]) | DB stocks fallback → 일봉 갱신 계속 |
| 실패 | `--stocks-only` | universe 비어있어도 fallback 안 함 → 빠른 종료 (의도) |
| 실패 | 기본 (stocks + prices 모두) | universe 비어 → load_stocks 단계는 0건 적재 + DB fallback 없음 |

→ **run_daily.bat [2/12]는 `--prices-only` 모드라 정상 동작 보장** ✓
