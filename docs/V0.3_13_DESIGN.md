# U-Turn Scanner — v0.3-13 설계 보고서 (코드 미수정, 설계만)

> **작성 기준일:** 2026-06-05
> **선행 단계:** v0.3-12 홈 변화 카드 → `/changes?focus=` 링크 연결 (구현 완료)
> **목표:** v0.3-12 이후 실사용에서 드러난 개선 후보 3종을 평가하고, **저위험·고사용성** 우선순위로 v0.3-13 작업 1건을 추천한다. 본 문서는 **설계 보고서**로, 코드 수정은 동반하지 않는다.

---

## 1. 배경

v0.3-12에서 홈 박스의 4 카드를 클릭하면 `/changes?focus=...` 로 이동하고 해당 카드가 indigo ring 으로 강조된다. 그러나 실제 사용 흐름에서 다음 한계가 관찰된다:

- **한계 A — 이탈/섹터 변화는 홈에 없음**
  - 사용자 명세 4 focus 중 `out`(이탈)·`sector`(섹터변화)는 홈 박스에 직접 트리거가 없어, 사용자가 의도적으로 URL을 치거나 `/changes` 본문을 둘러봐야만 인지 가능.
- **한계 B — 강조 위치까지 스크롤 부담**
  - `/changes?focus=new` 등으로 진입해도 페이지가 상단부터 시작되므로, 강조된 카드를 보려면 사용자가 직접 스크롤해야 한다.
  - 강조는 시각적으로만 표시되고, 자동 위치 점프가 없어 "한 번의 클릭"이 "클릭 + 스크롤 탐색"이 되는 비효율.

본 보고서는 위 한계를 해소할 3 후보를 평가한다.

## 4. v0.3-13 추천 — **후보 3 (자동 스크롤 + 강조 개선)**

### 추천 이유

1. **데이터·JSON·산식 변경 0건** — 보호 원칙 100% 준수, 가장 저위험.
2. **기존 디자인 무변경** — 4 카드 그리드 그대로, 모바일/태블릿/데스크톱 반응형 회귀 위험 없음.
3. **사용자 체감 즉시** — v0.3-12에서 "클릭은 가능해졌지만 스크롤이 필요"한 한계가 즉시 해소. 진짜 "한 번의 클릭"으로 강조 위치 도달.
4. **후속 후보와 의존성 없음** — 후보 1(이탈)·후보 2(섹터)는 v0.3-13 이후 독립적으로 진행 가능. 자동 스크롤은 이미 v0.3-12가 만든 focus 인프라를 그대로 활용.
5. **구현 단순성** — 클라이언트 wrapper 1개(~30줄) + 기존 카드에 `id` 5개 부착. PR 리뷰 부담 최소.

### 다른 후보 처리 전략

- **후보 1 (이탈 카드)**: v0.3-14 또는 v0.3-15 에 별도 진행 권장. 그리드 재설계 시 모바일 가독성 검증 필요. v0.3-13(자동 스크롤) 이후 진행해도 충돌 없음.
- **후보 2 (섹터 변화 카드)**: 사이드카에 의미 있는 `SECTOR_CHANGE` 건수가 누적될 때까지 **보류 권장**. 현 시점 데이터(0건)에서는 빈 카드만 노출되어 정보 밀도가 저하된다. 향후 사이드카 정의가 변경되거나 실제 발생 빈도가 늘면 재검토.

### 5-3. FocusScroller 동작 의사 코드

```tsx
'use client';
import { useEffect } from 'react';

export function FocusScroller({ focus }: { focus: string | null }) {
  useEffect(() => {
    if (!focus) return;
    const el = document.getElementById(`focus-${focus}`);
    if (!el) return;
    // 짧은 지연 후 스크롤 (서버 렌더 직후 layout 안정화)
    const t = setTimeout(() => {
      el.scrollIntoView({ behavior: 'smooth', block: 'center' });
    }, 50);
    return () => clearTimeout(t);
  }, [focus]);
  return null;
}
```

## 7. 위험 분석

### 7-1. 자동 스크롤 부작용 위험
- **위험**: 페이지 진입 직후 강제 스크롤로 사용자가 헤더(비교 기준 박스 등)를 못 볼 수 있음.
- **완화**: `block: 'center'` 옵션으로 카드가 뷰포트 중앙에 오게 하되, 상단 헤더가 일부 잘려도 사용자가 위로 스크롤하면 즉시 확인 가능. 또한 카드 강조(ring)가 그대로 남아 있어 도착 위치 인식 명확.

### 7-2. 모바일 동작 위험
- **위험**: 모바일에서 `scrollIntoView({ behavior: 'smooth' })` 가 일부 구형 브라우저에서 즉시 점프하거나 무시될 수 있음.
- **완화**: 폴리필 불필요한 표준 API. iOS Safari/Chrome/Edge 최신 버전 모두 지원. 미지원 브라우저에서는 점프(jump) 만 발생해도 동작은 정상.

### 7-3. SSR 환경 위험
- **위험**: 서버 컴포넌트에서 `document.getElementById` 호출 시 ReferenceError.
- **완화**: `'use client'` 선언 + `useEffect` 안에서만 호출. SSR 무관.

### 7-4. 사용자 인식 위험
- **위험**: 자동 스크롤이 너무 빨라 사용자가 "어디서 어디로 점프했는지" 인지 못 할 수 있음.
- **완화**: `behavior: 'smooth'` 로 부드러운 스크롤 + 카드 ring 강조가 그대로 남아 있어 도착 위치 시각적으로 명확.
