## 2. 배경

### 2-1. 현재 3 카드 한계 (v0.3-15/16)
- 종목명 + 메트릭 + 현재단계 + 선정 이유 표시
- 사용자가 "이 종목 어떻게 봐야 하지?"라는 **판단**까지 가려면 추가 화면 진입 필요
- "강한 후보"이지만 어제 대비 변화 방향을 한눈에 인지 어려움

### 2-2. v0.3-19 목표
사용자 명세대로:
1. **유지 이유** — 왜 이 카드에 픽되었는지 (v0.3-11 reason 강화 + 변화 맥락)
2. **어제 대비 변화** — 직전 스냅샷 대비 무엇이 바뀌었는지
3. **판정** — "관심 강화 / 관심 유지 / 주의 / 제외 검토" 4단계로 명시
4. **상태 뱃지** — 카드 우상단에 4단계 컬러 뱃지 (🟢🔵🟡🔴)
5. **정렬** — 판정 우선순위 순으로 표시

→ **종목 나열 → 판단 보조 카드** 로 의미 전환.

## 3. 판정 4단계 정의 (사용자 명세)

### 3-1. 사용자 명세 기준 (원안)
| 판정 | 뱃지 | 사용자 명세 기준 |
|---|---|---|
| 🟢 **관심 강화** | green | 상대강도 상승 · 20일 성과 상승 · 섹터 순위 상승 |
| 🔵 **관심 유지** | blue | 변화 미미 |
| 🟡 **주의** | amber | 상대강도 하락 · 20일 성과 하락 |
| 🔴 **제외 검토** | red | 20일선 이탈 · 후보 조건 상실 |

### 3-2. 호스트 데이터 가용성과의 매핑 문제
사용자 명세의 "상대강도 / 20일 성과 / 섹터 순위" 는 종목 단위 데이터를 요구하나, 호스트 사이드카에서는:
- `sector_dump.sectors_strong/weak[].market_relative_strength` — **섹터 단위** (종목 단위 X)
- `sector_dump.sectors_strong[].leaders/followers/...[].return_20d` — 종목 단위, 그러나 **강한/약한 섹터 종목만** 매칭
- 일반 섹터(중립) 종목은 매칭 0

호스트 검증 결과 (현재 3 카드 종목 NAVER/평화산업/유진테크 → sector_dump 매칭 0건).

→ **사용자 명세 원안 그대로는 호스트 데이터로 일부 종목만 판정 가능**. 다른 종목은 "데이터 부족 → 관심 유지" 기본값으로 처리할 수도 있으나 정확도 한계.

### 3-3. 실현 가능한 매핑 (호스트 데이터 활용)
| 판정 | 호스트 데이터 매핑 (change_dump + scan_dump) |
|---|---|
| 🟢 **관심 강화** | `score_delta > 0` AND `rank_delta < 0` (점수 상승 + 순위 개선 동시) |
| 🔵 **관심 유지** | 위 어디에도 안 걸리는 중립 또는 `score_delta > 0` 만 OR `rank_delta < 0` 만 (둘 중 하나만 좋음) |
| 🟡 **주의** | `score_delta < 0` OR `rank_delta > 0` (점수 또는 순위 하나라도 악화) |
| 🔴 **제외 검토** | `change_type === 'DEPARTED'` OR (scan_dump 에서 `disparity_pct < 0` & `days_below_ma60_60d ≥ 임계`) OR `today_rank == null` |

#### 정확도 vs 단순성
- 사용자 명세 정밀한 "상대강도 변화"를 위해서는 어제 sector_dump 까지 비교해야 (v0.3-6 daily snapshot 활용)
- 그러나 본 단계는 **확인 우선순위 보조** 영역이므로 score/rank delta 근사가 합리적

### 4-1. 데이터 충분성 평가
| 판정 기준 | 데이터 가용성 |
|---|---|
| rank_delta / score_delta | **100%** (모든 종목, change_dump) |

### 4-2. 결론
- 기본 판정: **change_dump의 rank_delta/score_delta** 로 가능 ✓
- 제외 검토 정밀화: scan_dump의 60일선 이탈 활용 가능 (수록 종목 한정)
- 상대강도/20일 성과: 현재 사이드카만으로는 부정확 → 사용자 명세 원안을 위해서는 v0.3-20 이상에서 사이드카 확장 필요

## 5. 판정 로직 옵션 비교

### 옵션 A — 단순 (change_dump만)
- **로직**: rank_delta/score_delta만으로 판정
- **장점**: 추가 fetch 0건, 단순, 100% 종목 적용
- **단점**: 사용자 명세 "상대강도/20일선 이탈" 정확 반영 안 됨

### 옵션 B — 부분 보강 (change_dump + scan_dump)
- **로직**: 옵션 A + scan_dump의 disparity_pct / days_below_ma60_60d 로 "제외 검토" 정밀화
- **장점**: 60일선 이탈 정확 판정 가능
- **단점**: scan_dump_latest.json 1회 추가 fetch (이미 v0.3-7의 일부 화면이 fetch)
- **데이터 적용률**: candidates_bottom 수록 종목만 (~80%)

### 옵션 C — 정밀 (사이드카 확장 필요)
- **로직**: 종목별 상대강도 + 20일 성과 까지 정확 계산
- **장점**: 사용자 명세 원안 100% 반영
- **단점**: **`compare_snapshots.py` 또는 `sector_dump.py` 수정 필요** → 보호 원칙 위반
- **결정**: **기각** (보호 원칙 "sidecar JSON 구조 변경 금지" 위반)

### 비교표
| 옵션 | 추가 fetch | 정확도 | 종목 적용률 | 보호 원칙 | 위험 |
|---|---|---|---|---|---|
| **A. 단순** | 0건 | 중 | 100% | ✓ | **최저** |
| **B. 부분 보강** | scan_dump 1건 | 중상 | 100% (제외 검토만 80%) | ✓ | 낮음 |
| C. 정밀 | 사이드카 확장 | 높음 | 100% | ✗ (위반) | 중상 |

### 추천: **옵션 A + B 부분 보강** (1차)
- 1차: 옵션 A 로직 적용 (rank/score delta 만)
- 2차 보강: scan_dump의 60일선 이탈만 추가 활용 → "제외 검토" 정밀화
- 사용자 명세 "상대강도/20일 성과/섹터 순위" 는 약식으로 score/rank delta 로 근사 — 안내 문구로 명시

## 6. 추천 판정 알고리즘 (의사 코드)

```ts
type Judgement = 'STRONG' | 'KEEP' | 'CAUTION' | 'EXCLUDE';

function judgeRow(
  row: ChangeRowLite,
  scanLookup?: Map<string, ScanCandidate>  // scan_dump.candidates_bottom by ticker
): Judgement {
  // 1) 제외 검토 우선 (가장 강한 부정 신호)
  if (row.change_type === 'DEPARTED') return 'EXCLUDE';
  if (row.today_rank == null && row.yesterday_rank != null) return 'EXCLUDE';

  // scan_dump 보강 — 60일선 이탈 (disparity_pct < 0 또는 days_below_ma60_60d > 임계)
  const scan = scanLookup?.get(row.ticker);
  if (scan && scan.disparity_pct != null && scan.disparity_pct < 0) return 'EXCLUDE';

  // 2) 관심 강화 (양쪽 모두 좋음)
  const scoreUp = (row.score_delta ?? 0) > 0;
  const rankUp = (row.rank_delta ?? 0) < 0;
  if (scoreUp && rankUp) return 'STRONG';

  // 3) 주의 (양쪽 또는 한쪽 악화)
  const scoreDown = (row.score_delta ?? 0) < -0.5;  // 임계 0.5
  const rankDown = (row.rank_delta ?? 0) > 0;
  if (scoreDown || rankDown) return 'CAUTION';

  // 4) 그 외 = 관심 유지
  return 'KEEP';
}
```

### 판정 우선순위 (정렬)
```ts
const ORDER = { STRONG: 0, KEEP: 1, CAUTION: 2, EXCLUDE: 3 };
cards.sort((a, b) => ORDER[a.judgement] - ORDER[b.judgement]);
```

## 8. 정렬 로직

### 8-1. 사용자 명세 정렬
```
관심 강화 → 관심 유지 → 주의 → 제외 검토
```

### 8-2. 구현 방식
v0.3-15에서 3 후보는 `topConsistent` / `topMomentum` / `topUTurnStrong` 로 픽됨. 본 단계에서:
1. 3 후보 각각 판정 계산
2. 판정 우선순위로 재정렬
3. UI 표시 순서 = 판정 순서

예: NAVER(주의) / 평화산업(관심 강화) / 유진테크(관심 유지) → **평화산업 → 유진테크 → NAVER** 순서로 표시.

### 8-3. ① / ② / ③ 라벨 처리
- 옵션 A: 라벨 고정 (NAVER 가 1번이어도 라벨은 "① 강세 지속" 유지)
- 옵션 B: 정렬 후 라벨 재할당 ("① 강세 지속" 카드가 두 번째로 가면 라벨 변경)

**추천 옵션 A** — 라벨은 픽 기준(강세 지속 / 다방면 개선 / U턴 시도 강화)을 의미하므로 변경 안 함.
