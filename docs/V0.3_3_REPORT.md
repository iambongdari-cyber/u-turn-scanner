# U-Turn Scanner — v0.3-3 사이드카 화면 UX 보강 보고서

> **작성 기준일:** 2026-06-03
> **선행 커밋:** v0.3-2 `b200b4f`
> **목표:** 사이드카(`scan_dump_latest.json`, `sector_dump_latest.json`) JSON 결과를 화면에서 더 쉽게 해석할 수 있도록 UX를 보강한다. **분석 로직 변경은 없다.** 표시/해석 보조 UI만 강화한다.

---

## 1. 작업 목적

v0.3-2에서 `run_daily.bat` 안에 사이드카 2종이 자동 통합되어, 매일 `logs/sidecar/*.json`이 생성된다. 그러나 화면(`/bottom-watch`·`/leaders`·`/kiwoom-helper`·`/journal`)에서:

- 단계/분류 라벨이 단순 배지로만 표시되어, 사용자가 라벨 의미를 다시 떠올려야 했다.
- 상단에 통합 카운트 요약이 부족해, 오늘의 "추격 위험"이 몇 종목인지 한 눈에 보기 어려웠다.
- 일지 초안이 "분류 + 근거 + 조심할 점" 위주여서, "내일 다시 볼 조건"이나 "추격하지 말아야 할 이유"가 명시되지 않았다.
- "자동주문/자동매수와 무관"하다는 안내가 키움 화면 상단 1줄에만 있어서 약했다.

v0.3-3은 이 4개 화면의 **표시/해석 보조 UI**만 강화한다. 사이드카 JSON 구조·DB·TOP10 산식·run_daily 절차는 그대로 둔다.

## 3. 화면별 변경 내용 (상세)

### 3-1. `app/_lib/sidecar.ts` — 헬퍼 라이브러리 보강

**기존:** 데이터 로딩(`loadSidecarBundle`)과 배지 클래스(`stageBadgeClass`, `classificationBadgeClass`)만 제공.

**추가:**
- `LabelDisplay` 타입: `{ icon, short, desc, caution }` — 라벨 1개에 표시용 메타 4종.
- `STAGE_DISPLAY` 사전: 바닥 관찰 / U턴 시도 / U턴 확인 / 추세전환 후보 4개에 대해 아이콘·한 줄 해석·설명·주의 문구.
- `CLASSIFICATION_DISPLAY` 사전: 진짜 주도주 후보 / 후발주 관찰 / 기회 후보 / 추격 위험 / 보유자 대응 / 조건 부족 6개.
- `STAGE_ORDER`, `CLASSIFICATION_ORDER`: 화면별 순서 일치용 상수.
- `getStageDisplay(stage)`, `getClassificationDisplay(label)`: 안전 조회(없으면 중립 라벨).
- `summarizeSidecarCounts(bundle)`: 단계/분류/뉴스/추격위험 카운트 합산.
- **`buildJournalDraft(input): JournalDraft`** — 일지 초안 4섹션 문장 생성:
  - `why` ("왜 떴는지"): 단계·분류·섹터·근거·GC경과 조합 + "관찰·복기 보조 표시이며 매매 권유가 아닙니다" 꼬리표.
  - `caution` ("조심할 점"): 뉴스 위험 + 추격 위험 사유 + 이격 임계 경고 + 단계별 주의 자동 합성.
  - `next` ("내일 다시 볼 조건"): 단계별·분류별 체크 항목 자동 합성(예: U턴 시도 → "골든크로스 유지 + 종가가 60일선 위 유지").
  - `noChase` ("추격하지 말아야 할 이유"): 분류 = "추격 위험"이거나 chase_risk_reasons가 있거나 이격 ≥18%일 때만 생성. "신규 진입은 추격 위험" 명시 + "보유 중이라면 본인의 손절·청산 원칙" 안내. 매수/매도 지시 표현 미포함.

**문구 원칙 자동 검증:** 헬퍼 내 모든 문구를 "관찰 후보 / 복기 보조 / 확인 필요 / 추격 위험 / 내일 다시 볼 조건" 표현으로 작성. "매수하세요 / 매도하세요 / 확정 상승 / 반드시 매수" 등 단정 표현은 포함하지 않는다(상세 §5 금지어 검사 결과).

### 3-2. `/bottom-watch` — 바닥 U턴 후보

**기존:** 단계별 카드 + 거래대금/이격 등 지표만 표시.

**추가:**
- 단계 섹션 헤더에 컬러 배지 + 아이콘 + 짧은 한 줄 해석(`short`)을 함께 표기. 예: `🌱 바닥 관찰 — 바닥권 + U턴 검증 충족, 골든크로스는 아직`.
- 헤더 아래에 "**다음 확인**: 단기선(10일) 상향 돌파 여부…" 한 줄 도움말 추가(`caution` 사용).
- 종목 카드의 단계 라벨을 흐린 회색에서 단계별 컬러(`stageBadgeClass`) + 아이콘으로 강조. `title` 속성에 자세한 설명을 hover로 노출.
- 카드 본문 윗 부분에 단계 + 짧은 해석 한 줄 보조 표시.
- 기존 "전체 바닥 후보 · 단계별 카운트 5칸" 요약은 유지.

### 3-3. `/leaders` — 주도주·후발주

**기존:** 강한 섹터 + 약한 섹터 + 4분류(주도주/후발주/기회/추격위험) 카드. 추격 위험은 일반 분류와 동일한 톤으로 표시.

**추가:**
- 상단 4칸 요약(강한 섹터/약한 섹터/전체 산출/시장 흐름) 아래에 **"전 섹터 합산 라벨 요약"** 박스 추가:
  - 🥇 진짜 주도주 후보 합산
  - 🥈 후발주 관찰 합산
  - 🎯 기회 후보 합산
  - ⚠️ 추격 위험 합산 (ring-2 + orange 강조 + `warn` flag)
- 추격 위험 카운트가 1 이상이면 박스 하단에 경고 멘트 자동 표시: "신규 진입 시 추격 위험이 큽니다. 매수/매도 지시가 아닌 경고 라벨이며, 보유 중일 때의 대응은 본인의 원칙을 따르세요."
- 섹터 내 `SubSection`도 분류명 옆에 한 줄 해석 추가. 추격 위험은 별도 박스(`border-orange-200 bg-orange-50`) + 경고 한 줄 자동 표시.

**원칙:** 추격 위험을 "팔라"가 아니라 "신규 진입은 위험"으로 표현. 매도 지시 톤은 사용하지 않는다.

### 3-4. `/kiwoom-helper` — 키움 자동감시 참고표

**기존:** 상단 안내문 1줄 + 표 + 라벨 1줄 설명. "자동주문 기능 아님"은 짧게만 명시.

**추가:**
- 상단 안내문 보강:
  - "키움의 **자동감시·관심종목 등록** 시 손으로 입력할 가격을 참고용으로 정리한 표"
  - "**자동주문/자동매수 기능과 무관**하며, **키움 API 연동도 없음**"
  - "최종 입력과 주문 여부는 사용자가 **키움 HTS/MTS에서 직접 확인하고 결정**"
- **8라벨 의미 빠른 참조표**(접이식 `<details>`) 추가:
  - 단계 4개(바닥 관찰 / U턴 시도 / U턴 확인 / 추세전환 후보) · 분류 4개(진짜 주도주 후보 / 후발주 관찰 / 기회 후보 / 추격 위험).
  - 각 라벨에 컬러 배지 + 아이콘 + 한 줄 해석.
  - 끝에 "어떤 라벨도 매매 권유가 아닙니다" 명시.
- 표 본문, 사이드카 보강 컨텍스트 섹션, 가격 라벨 안내(`돌파 확인가` 등)는 무변경.

### 3-5. `/journal` — 매매일지 초안

**기존:** 일지 초안 박스 = "오늘 분류 / 확인 근거 / 조심할 점 / 다음 복기 때 볼 것" 4행, 단순 라벨 나열.

**변경:** `buildJournalDraft`로 자동 생성된 자연스러운 문장 기반 4섹션 카드:
- **① 왜 떴는지** (emerald 톤): 단계·분류·섹터·GC경과·근거 갯수를 한 문장으로 합성 + 근거 칩.
- **② 조심할 점** (amber 톤): 뉴스 위험 → 추격 위험 → 이격 경고 → 단계별 주의를 자동 합성.
- **③ 내일 다시 볼 조건** (sky 톤): 단계·분류별 체크리스트 자동 생성. 예: "단기선(10일) 상향 돌파 여부 · 섹터 강도 유지 + 전고점 근접도".
- **④ 추격하지 말아야 할 이유** (orange 톤, ring): 분류 = "추격 위험"이거나 이격 ≥18%일 때만 노출. 사유 + "신규 진입은 추격 위험" + "매수/매도 지시 아님" 꼬리표.

**원칙:** 모든 문장은 사용자가 직접 판단할 수 있도록 보조 정보를 제공하는 톤. "사세요/파세요" 표현 0건.

### 5-5. 화면 graceful 처리 (JSON 부재 시)

`app/_lib/sidecar.ts`의 `loadSidecarBundle`은 v0.2-4 단계부터 다음을 보장한다:
- 파일이 없으면 `{scanMissing: true}` / `{sectorMissing: true}` 분기로 빈 컨텍스트 반환.
- JSON 파싱 실패 시 `{scanError: true}` 등으로 안내 메시지.
- 두 파일 모두 부재해도 빈 `contexts` Map을 반환해 `Map.get(...)`이 안전하게 `undefined` → 화면 분기로 흘러감.

각 화면(`/bottom-watch`, `/leaders`)도 자체 `loadDump`에서 `missing` / `parse_error` 분기를 별도로 유지. `/kiwoom-helper`, `/journal`은 사이드카가 없어도 DB 데이터만으로 정상 렌더(사이드카 컨텍스트는 보강용).

v0.3-3 추가 헬퍼(`getStageDisplay`, `getClassificationDisplay`, `buildJournalDraft`)는 모두 `null` 입력에 대해 중립 결과를 반환하도록 작성 — JSON 부재로 사이드카 컨텍스트가 없을 때도 화면이 깨지지 않는다.
