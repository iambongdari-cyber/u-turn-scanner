## 3. TradePlan 저장 구조 변경

### 3-1. 신규 필드 4 개 (모두 옵셔널)

```ts
interface TradePlan {
  // ... (기존 25 필드 그대로)

  // v0.7 신규
  closed_at_price: number | null;       // 실제 종료가 (사용자 입력)
  closed_pnl_pct: number | null;        // 수익률 % (자동 계산 또는 사용자 수정)
  closed_at_date: string | null;        // 종료일 (YYYY-MM-DD)
  close_memo: string | null;            // 메모
}
```

### 3-2. 기존 plans 호환성
- 모든 필드 옵셔널 → 기존 v0.6.1 까지 저장된 plans 도 정상 로드
- 전략 컨디션 계산 시 4 필드 중 `closed_pnl_pct` 가 `null` 이면 그 plan 은 집계에서 제외 (= 매도완료 했지만 결과 미입력 종목)
- `trade_storage.ts` 의 type guard 만 옵셔널 처리 (기존 `loadAllPlans()` 의 검증 로직 그대로)

### 3-3. 마이그레이션 0건
새 필드는 옵셔널이므로 기존 localStorage 데이터를 강제 재기록할 필요 없음. 자연스럽게 신규 매도완료 시점부터 누적.

## 4. 전략 컨디션 실계산 알고리즘

### 4-1. 입력 집계
```ts
const closedWithResult = plans
  .filter(p => p.status === 'CLOSED' && p.closed_pnl_pct != null)
  .sort((a, b) => (b.closed_at_date ?? '').localeCompare(a.closed_at_date ?? ''))
  .slice(0, WINDOW_SIZE);  // 최근 20회
```

### 4-2. 데이터 부족 분기
| `closedWithResult.length` | 상태 |
|---|---|
| 0 | DATA_INSUFFICIENT (v0.6.1 과 동일 안내) |
| 1~4 | DATA_INSUFFICIENT (5건 미만은 통계적으로 부족) |
| 5~19 | **계산 진행** (단, "최근 20건 중 N건만 누적" 안내 추가) |
| 20 이상 | **계산 진행** (목표 충족) |

### 4-3. 계산식
```ts
const wins = closedWithResult.filter(p => p.closed_pnl_pct! > 0);
const losses = closedWithResult.filter(p => p.closed_pnl_pct! <= 0);

const winRate = wins.length / closedWithResult.length * 100;
const avgGainPct = wins.length > 0
  ? wins.reduce((s, p) => s + p.closed_pnl_pct!, 0) / wins.length
  : 0;
const avgLossPct = losses.length > 0
  ? losses.reduce((s, p) => s + p.closed_pnl_pct!, 0) / losses.length
  : 0;

// 기대수익 = 승률 × 평균수익 + (1-승률) × 평균손실
//   (avgLossPct 는 이미 음수이므로 직접 합)
const expectedReturnPct = (winRate / 100) * avgGainPct + ((100 - winRate) / 100) * avgLossPct;
```

### 4-4. 등급 매핑 (5 단계)

| 승률 | 등급 | 라벨 | 색상 |
|---|---|---|---|
| ≥ 70% | EXCELLENT | 매우 좋음 | emerald |
| 60~69% | GOOD | 좋음 | sky |
| 50~59% | AVERAGE | 보통 | slate |
| 40~49% | CAUTION | 주의 | amber |
| < 40% | DANGER | 위험 | red |

추가 보정 — **승률은 좋아도 기대수익이 음수면 CAUTION 으로 강등**:
```ts
if (state === 'GOOD' || state === 'AVERAGE') {
  if (expectedReturnPct < 0) state = 'CAUTION';
}
```

### 4-5. 코치 안내 (advice)

| 등급 | advice |
|---|---|
| EXCELLENT | 현재 전략이 매우 잘 작동하고 있습니다. 현 모드 유지 + 진입 강도 살짝 상향 가능. |
| GOOD | 전략이 잘 작동 중. 시장 모드 추천대로 진행. |
| AVERAGE | 평균 수준. 손절 원칙을 더 엄격하게 — 평균손실 폭을 줄이는 게 우선. |
| CAUTION | 승률 또는 기대수익이 흔들립니다. 신규 진입 강도 하향, 보유종목 점검 우선. |
| DANGER | 전략이 작동하지 않는 구간. 신규 진입 보류 + 최근 손실 종목 패턴 회고 필요. |

## 5. 전략 컨디션 → 종목 선정 영향

### 5-1. `selectTradePlanTargets()` 가 컨디션 인자 추가

```ts

  newItems: TodayBriefItem[],

  // 위험구간 (HOLD_CASH) 은 그대로 0개

  if (conditionState === 'DANGER') return [];

  // ... 기존 모드별 가중치 계산 ...

  // v0.7 신규: 컨디션 기반 추가 감점
  if (conditionState === 'CAUTION') score -= 15;        // 신규 후보 전체 감점
  if (conditionState === 'EXCELLENT') {
    // 강세장 + EXCELLENT → 캡 1 → 2 까지 확대 검토
    // (단, 보합장은 그대로 1개 — 1순위만 원칙 유지)
  }

  // ... 점수 < 0 자동 제외 + 캡 적용 ...
}
```

### 5-2. 시장 모드 × 컨디션 매트릭스

| 시장 모드 \ 컨디션 | EXCELLENT | GOOD | AVERAGE | CAUTION | DANGER |
|---|---|---|---|---|---|
| **공격 (BULL)** | 최대 3 | 최대 3 | 최대 2 | 최대 1 | **0** |
| **선별 (NEUTRAL)** | 최대 1 | 최대 1 | 최대 1 | 최대 1 (+감점) | **0** |
| **방어 (BEAR)** | 최대 1 | 최대 1 | 최대 1 | **0** | **0** |
| **관망 (DANGER)** | 0 | 0 | 0 | 0 | 0 |

→ 컨디션이 시장 모드와 함께 자연스럽게 진입 강도를 조절. 사용자 직관에 부합 — "전략이 잘 먹히고 있으면 좀 더 가도 되고, 흔들리면 줄여야" 와 일치.

## 10. 호스트 데이터 시뮬레이션 (가상 시나리오)

### 10-1. 시나리오 A — 신규 사용자 (CLOSED 0건)
- StrategyConditionBox: 데이터 부족 + "0건 / 목표 20건"
- 컨디션 → 종목 선정 영향: 없음 (conditionState undefined 면 기존 모드만 적용)
- GPT 리포트 §2: 데이터 부족 안내

### 10-2. 시나리오 B — 누적 14건, 승률 64%, 평균수익 +8.2% / 평균손실 -4.1%
- 기대수익 = 0.643 × 8.2 + 0.357 × (-4.1) = 5.27 - 1.46 = +3.81%
- 상태: GOOD (좋음, sky 색)
- advice: "전략이 잘 작동 중. 시장 모드 추천대로 진행."
- 종목 선정 영향: 점수 그대로 (감점 없음)

### 10-3. 시나리오 C — 누적 18건, 승률 45%, 평균수익 +5% / 평균손실 -6%
- 기대수익 = 0.45 × 5 + 0.55 × (-6) = 2.25 - 3.3 = **-1.05%**
- 1차 분류: 승률 45% → CAUTION
- 보정 분기: GOOD/AVERAGE 가 아니므로 그대로 CAUTION
- advice: "승률 또는 기대수익이 흔들립니다. 신규 진입 강도 하향, 보유종목 점검 우선."
- 종목 선정 영향: **신규 후보 -15 감점** → 보합장에서도 결국 0~1개

### 10-4. 시나리오 D — 누적 20건, 승률 35%
- 상태: DANGER (위험)
- 종목 선정 영향: 시장 모드 무관 **신규 0개** (selectTradePlanTargets 시작부에서 차단)
- 사용자가 화면을 보면 "오늘은 신규 진입보다 관망이 우선입니다." 자연어 결론 + 매매계획 기록 대상 0개 — **위험구간(HOLD_CASH) 시장 모드와 동일한 효과**

## 11. 결론

**v0.7 채택안:** **§2 전략 컨디션이 v0.6 의 "카드 자리" 에서 v0.7 의 "실숫자" 로 진화.** 매도완료 진입 흐름에 **CloseTradeModal** 신규 (실제 종료가 + 수익률 자동/수정 + 종료일 + 메모) — TradePlan 에 옵셔널 4 필드 추가 (`closed_at_price` `closed_pnl_pct` `closed_at_date` `close_memo`), 기존 plans 호환 (마이그레이션 0). `evaluateStrategyCondition()` 가 최근 20건 CLOSED 만 집계해 **승률·평균수익·평균손실·기대수익·등급 5단계 (매우 좋음/좋음/보통/주의/위험)** 산출. 승률은 좋아도 기대수익 음수면 CAUTION 강등 보정. **컨디션이 종목 선정에 영향** — DANGER 면 시장 모드 무관 신규 0개, CAUTION 이면 -15 감점, EXCELLENT 면 강세장에서 캡 확대.
