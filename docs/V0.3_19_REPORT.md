## 1. 작업 목적

v0.3-15/16에서 3 카드는 강세 지속 / 다방면 개선 / U턴 시도 강화 라벨로 종목을 보여주지만, 사용자가 "이 종목 어떻게 봐야 하지?" 라는 **판단**까지 가려면 추가 화면 진입 필요.

v0.3-19는 사용자 명세대로:
1. 판정 4단계 뱃지 추가
2. 어제 대비 변화 한 줄 표시
3. 유지 이유 (기존 reason) 유지
4. 판정 한 줄 설명 추가
5. 정렬 (개선중 → 유지중 → 약화중 → 제외 검토)

→ **종목 나열 → 판단 보조 카드** 의미 전환.

### 3-2. `loadScanDumpForJudge()` 헬퍼 신규

```ts
async function loadScanDumpForJudge(): Promise<Map<string, ScanCandidateLite> | null> {
  ...
  try {
    const buf = await readFile(filePath, 'utf-8');
    const d = JSON.parse(buf) as ScanDumpLite;
    const map = new Map<string, ScanCandidateLite>();
    for (const r of (d.candidates_bottom ?? [])) {
      if (r && typeof r.ticker === 'string') map.set(r.ticker, r);
    }
    return map;
  } catch {
    return null;  // 실패해도 전체 화면 중단 금지 (사용자 명세 그대로)
  }
}
```

- `Map<string, ScanCandidateLite>` 반환 — ticker O(1) 조회
- **fetch 실패해도 null 반환 → change_dump 만으로 판정 진행** (사용자 요구사항 3 충족)

### 3-4. `judgeRow()` 판정 함수

사용자 명세 로직 그대로:

```ts
function judgeRow(row, scanLookup) {
  // 1) 제외 검토 우선
  if (row.change_type === 'DEPARTED') return 'EXCLUDE_REVIEW';
  if (row.today_rank == null && row.yesterday_rank != null) return 'EXCLUDE_REVIEW';
  const scan = scanLookup?.get(row.ticker);
  if (scan && scan.disparity_pct < 0) return 'EXCLUDE_REVIEW';  // 60일선 이탈

  // 2) 개선중 — 점수 상승 + 순위 개선 동시
  if (row.score_delta > 0 && row.rank_delta < 0) return 'IMPROVING';

  // 3) 약화중 — 한쪽이라도 명확히 악화
  if (row.score_delta <= -0.5 || row.rank_delta > 0) return 'WEAKENING';

  // 4) 그 외 — 유지중
  return 'KEEPING';
}
```

### 3-5. `buildChangeNote()` / `buildJudgementNote()` 헬퍼

- `buildChangeNote(row)` → "순위 ▲11계단 / 점수 +5.0" 같은 자연 문구
- `buildJudgementNote(judgement, row)` → 판정별 한 줄 설명 (관찰 보조 표현만)

각 판정 한 줄 예시:
- IMPROVING: "순위·점수 모두 개선 — 관심 강화 신호로 다시 확인할 후보."
- KEEPING: "변화가 크지 않거나 한쪽만 개선 — 기존 관찰 흐름 유지 권장."
- WEAKENING: "순위 악화 — 추가 확인 필요 (매도 권유 아님, 복기 보조)."
- EXCLUDE_REVIEW: "오늘 후보권에서 이탈 — 제외 여부 다시 점검 (매도 권유 아님)."
