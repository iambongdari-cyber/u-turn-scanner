## 4. `/bottom-watch` 화면 기능 요약

### 데이터 소스
- **오직 `logs/sidecar/scan_dump_latest.json`만 사용** (Supabase 미사용)

- `path.join(process.cwd(), 'logs', 'sidecar', 'scan_dump_latest.json')`

### 화면 구성

**1) 상단**
- `←` 홈 링크
- 제목: **바닥 U턴 후보**
- 설명: "바닥권에서 U턴 가능성을 보이는 종목을 단계별로 관찰합니다. 관찰·복기 보조용이며 매매 권유가 아닙니다."
- 메타 표시: 기준일(`base_date`) · 생성시각(`generated_at`) · 시장 흐름 배지(`market.flow` — 강세/중립/약세 색상 구분)

**2) 요약 카드 (5개 그리드)**
- 전체 바닥 후보 수 (`summary.n_candidates_bottom`)
- 바닥 관찰 (`summary.stage_counts['바닥 관찰']`)
- U턴 시도
- U턴 확인
- 추세전환 후보

**3) 단계별 섹션 (4개)** — `candidates_bottom`을 `stage` 필드로 그룹핑

| 섹션 | 아이콘 | 설명 |
|------|--------|------|
| 바닥 관찰 | 🌱 | 종가가 60일선 위에 있고 U턴 검증(최근 60일 중 60일선 아래 ≥10일)을 충족하지만, 아직 골든크로스가 감지되지 않은 종목 |
| U턴 시도 | 🔄 | 최근 0~1거래일 사이에 10일선이 60일선을 상향 돌파한 종목 |
| U턴 확인 | ✅ | 2~5거래일 전 골든크로스가 발생해 U턴이 자리잡아 가는 종목 |
| 추세전환 후보 | 📈 | 6거래일 이상 전에 골든크로스가 발생해 추세가 자리잡힌 종목 |

**4) 종목 카드 항목**
- 상단: **종목명** + 종목코드 + 단계 배지 + 분류 배지 + 뉴스 위험 배지(조건부)
  - 분류 배지는 `final_grade_from_run_scan` → 기회 후보 / 추격 위험 / 조건 부족 / 관찰 보조
  - `news_critical === true`일 때 **"뉴스 위험 확인 필요"** 빨간 배지 (중립 문구)
- 섹터 표시 (있을 때)
- 수치 그리드 (2~3열 반응형, 모두 tabular-nums)
  - 종가 (`close`)
  - 60일선 (`ma60`)
  - 이격도 (`disparity_pct`) — 부호 포함 `+/−`
  - 60일 중 아래 일수 (`days_below_ma60_60d`)
  - 거래대금 회복 (`value_ratio`, "X.X배" 표시)
  - 20일 평균 거래대금 (`avg_value_20_eok`, "X.X억")
- **근거 라벨 칩** (`evidence` 배열) — emerald 칩으로 모두 표시
  - 예: "U턴 검증 충족(60일 중 아래 22일)", "거래대금 회복 (2.3배)", "후행스팬 정상", "종가 60일선 위" 등
- 우하단 **"종목 상세 →"** 링크 + 종목명 클릭 — 둘 다 기존 `/stocks/[ticker]`로 이동

**5) 하단 박스 안내**
- "**바닥에서 많이 빠진 종목**을 추천하는 화면이 아닙니다. **바닥(U턴 검증) + 거래대금 회복 + 추세 전환 + 근거**가 함께 나타나는 종목을 단계별로 정리한 **관찰·복기 보조** 화면입니다."
- "어떤 표시도 매매 권유가 아니며, 최종 판단은 사용자 본인이 합니다. 뉴스 위험은 별도 `확인 필요` 표시로 안내합니다."

## 5. JSON 파일 부재 / 손상 시 처리 방식

`loadDump()`가 3가지 `LoadResult` 상태를 반환하고 페이지가 분기:

```typescript
type LoadResult =
  | { status: 'ok'; data: DumpData }
  | { status: 'missing' }
  | { status: 'parse_error'; message: string };
```

### 케이스별 처리

| 케이스 | 트리거 | 표시 |
|--------|--------|------|
| **파일 없음** | `fs.readFile` → `ENOENT` 등 | 노란 안내 박스(`bg-amber-50`)<br>"아직 바닥 U턴 후보 데이터가 없습니다. 먼저 `scripts/scan_dump.py`를 실행해 사이드카 JSON을 생성해 주세요." |
| **JSON 파싱 실패** | `JSON.parse` 예외 | 빨간 안내 박스(`bg-red-50`)<br>"바닥 U턴 후보 데이터를 읽는 중 문제가 발생했습니다. `scan_dump_latest.json` 파일을 다시 생성해 주세요." |
| **정상** | 파싱 성공 | 본 화면 정상 표시 |

세 케이스 모두 페이지가 **절대 깨지지 않고** 친절한 안내로 graceful 처리됨. `try/catch`로 화면 중단 방지.

## 부록 — 화면 톤 원칙 재확인

이 화면은 **"바닥에서 많이 빠진 종목"을 추천하는 화면이 아닙니다.**

반드시 **"바닥(U턴 검증) + 거래대금 회복 + 추세 전환 + 근거"** 가 함께 나타나는 종목을 단계별로 정리한 **관찰·복기 보조** 화면이라는 톤을 유지합니다.

각 종목 카드의 `evidence` 라벨(녹색 칩)이 그 근거를 한눈에 보여주며, 어떤 표시도 매매 권유가 아닙니다.
