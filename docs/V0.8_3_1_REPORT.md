# V0.8-3.1 보고서 — sector_names.ts 매핑 보완

작성일: 2026-06-14
대상 범위: v0.8-3.1 (업종 코드 → 한국어 업종명 매핑 보완)

## 1. 확인한 데이터 위치

### 코드 체계 출처
`scripts/load_sectors.py` 헤더 코멘트:
> DART company API로 종목별 업종코드(induty_code)를 가져와 stocks.sector 에 저장.
> induty_code는 한국표준산업분류(KSIC) 5자리. 앞 2자리(대분류)를 sector로 사용.

따라서 사이드카에 들어 있는 두 자리 숫자(`'14'`, `'22'`, `'33'` 등)는 **KSIC 2자리 대분류 코드** 다. 이 사실을 매핑의 출발점으로 삼았다.

### 종목 증거 출처
`logs/sidecar/sector_dump_latest.json` 의 `sectors_strong[*].leaders / followers / chase_risk` 와 `sectors_weak[*]` 의 동일 필드를 코드별로 펼쳐 종목을 확인.

호스트 데이터에 등장한 코드 (16개):
`'11', '14', '16', '17', '22', '23', '31', '32', '33', '45', '50', '65', '66', '70', '72', '90'`

각 코드에 종목명+티커가 들어 있는 경우 그 종목들의 실제 업종을 확인해 KSIC 표준과 교차검증.

## 3. 매핑하지 않은 코드와 이유

| 코드 | 미매핑 사유 |
| --- | --- |
| `'16'` | 호스트 사이드카에 종목 정보 없음 (n=5, leaders/followers/opportunities/chase_risk 모두 비어 있음). KSIC 16(목재·나무제품)으로 추정되나 직접 검증 불가 → fallback 유지. |
| `'23'` | 호스트 종목이 티씨케이·원익QnC(반도체 부품), 자연과환경 등 혼합. KSIC 23(비금속광물)에 부합하지 않는 종목이 섞여 있어 라벨 결정 보류 → fallback 유지. |
| `'45'` | 호스트 데이터에 종목 정보 없음 → fallback 유지. |
| `'50'` | 호스트 데이터에 종목 정보 없음 → fallback 유지. |

사용자 명세 §3 "확실하지 않은 코드는 잘못 추정하지 말고 업종 코드 N 유지" 원칙을 그대로 따랐다.

## 4. 화면 변경 예시

`/beginner` → "🌊 내일 한눈에 보기" → 자세히 보기 → "💰 돈이 들어온 곳"

**기존**
```
오늘 강한 업종은 업종 코드 14, 업종 코드 33, 업종 코드 22 입니다.
· 업종 코드 14    점수 95 · 20일 +81.4%
· 업종 코드 33    점수 78 · 20일 +32.4%
· 업종 코드 22    점수 60 · 20일 +10.7%
```

**변경 후**
```
오늘 강한 업종은 의복·패션, 기타 제조, 타이어·고무·플라스틱 입니다.
· 의복·패션              점수 95 · 20일 +81.4%
· 기타 제조              점수 78 · 20일 +32.4%
· 타이어·고무·플라스틱    점수 60 · 20일 +10.7%
```

미매핑 코드가 TOP 3 에 들어오면 그 코드만 그대로 노출:
```
오늘 강한 업종은 의복·패션, 업종 코드 23, 타이어·고무·플라스틱 입니다.
```

대장주 판단 영역에서도 동일하게 한국어 라벨 노출 (sector_flow 가 `LeaderStock.sectorLabel` 에 `getSectorLabel(sector)` 결과를 미리 박아 둠).

1순위 종목 성격 영역의 "주도 업종 일치", "주도 업종 안 후발 종목" 안내문에 들어가는 업종명도 자동으로 한국어로 바뀐다.

## 5. 기존 기능 영향 없음 확인

| 영역 | 영향 |
| --- | --- |
| 업종 점수 계산 (`sector_flow.ts`) | 무영향. 점수 산식 무변경. |
| 대장주 판단 (`sectorFlow.leadersBySector`) | 무영향. `getSectorLabel` 만 다른 문자열을 반환할 뿐 로직 동일. |
| 1순위 종목 성격 분류 (`stock_character.ts`) | 무영향. `topSectorInfo.sectorLabel` 만 다른 문자열로 노출. |
| 내일 행동 (`tomorrow_action.ts`) | 무영향. |
| TodayConclusion / MustSeeSection / GPT 리포트 | 무영향. 업종 코드를 직접 다루지 않음. |
| TradePlan 저장 구조 / 사이드카 JSON | 무영향. |
| 모바일 GPT 리포트 페이지 (`/beginner/gpt-report`) | 무영향. |

`getSectorLabel` 의 호출 흐름은 동일하며 출력 문자열만 바뀐다. 동일 입력 → 동일 출력의 순수 함수이므로 SSR/CSR 양쪽에서 동일하게 동작.

## 7. 테스트 방법

호스트:

```
npm run build
npm run dev
```

`/beginner` 에서 다음을 확인:

1. **"🌊 내일 한눈에 보기" 카드 → 자세히 보기 → "💰 돈이 들어온 곳"**
   호스트 데이터에 코드 `14, 33, 22` 가 TOP 3 로 들어가 있으므로
   `의복·패션`, `기타 제조`, `타이어·고무·플라스틱` 으로 표시되는지.
2. **미확인 코드 fallback** — 사이드카가 갱신되어 `23` 이나 `16` 같은 미매핑 코드가 TOP 3 에 들어오면 `업종 코드 23` 처럼 그대로 노출되는지.
3. **🏆 대장주 판단** 영역의 sector 헤더(예: `보험: 코리안리, ...`)가 한국어로 나오는지.
4. **🎯 1순위 종목 성격** 의 narrative 안 업종명도 한국어로 바뀌었는지.
5. **기존 기능 동일 유지** — 1순위 종목 변동 없음, 내일 행동/금지 행동/매매계획 카드 변동 없음.
6. 미매핑 코드가 들어와도 빌드/런타임 에러가 나지 않는지 (fallback regex 정상 동작).
