## 3. 사고 원인 분석

### 증상
`run_sidecar.bat` 실행 중 화면에 다음 한 줄이 섞여 출력됨:
```
'�글' is not recognized as an internal or external command
```

### 원인
`run_sidecar.bat`은 `chcp 65001 >nul`(UTF-8 코드페이지)를 사용하지만, **cmd가 배치 파일의 본문 일부를 명령어로 잘못 파싱**하면서 한글 바이트가 손상된 문자열(`�글`)로 표시된 것으로 보인다. 가능한 원인:
- 일부 한글 문자열이 cmd 토크나이저에 의해 첫 단어로 분리되어 "command"로 해석됨
- `chcp 65001`이 적용되기 전 cmd 파서가 한글 바이트를 다른 인코딩으로 해석
- BOM·CRLF 정규화 과정에서 미세한 바이트 깨짐

### 영향 범위
- **기능적 영향 0:** 사이드카 2종 실행은 정상 성공, JSON 2개 모두 정상 생성됨
- **사용자 신뢰 손상:** 정상 동작 중에 "is not recognized" 메시지가 보이면 사용자가 실패로 오인할 수 있음
- **장기 위험:** 위치/언어에 따라 동작이 달라질 수 있으므로, 안정 운영을 위해 한글을 제거하는 것이 안전

### 보호 측면
- `run_daily.bat`은 한글 echo가 더 많지만, **해당 사고는 보고되지 않았음**. `run_sidecar.bat`만 특이하게 발생한 이유는 추가 조사 필요(추정: 특정 줄의 첫 글자 한글 + 조사 결합 부분에서 토큰화 사고).
- 이번 핫픽스는 **`run_sidecar.bat`에 한정**해서 한글을 제거하는 안전한 접근만 사용. `run_daily.bat`은 보호 원칙대로 손대지 않음.

## 7. 사용자 PC 검증 순서

cmd(프로젝트 폴더)에서:

```bat
REM 1) CRLF 정규화 (1회 무조건)
.venv\Scripts\python.exe -c "d=open('run_sidecar.bat','rb').read().replace(b'\r\n',b'\n').replace(b'\n',b'\r\n'); open('run_sidecar.bat','wb').write(d)"

REM 2) CRLF 검증 (lone LF가 0이어야 함)
.venv\Scripts\python.exe -c "d=open('run_sidecar.bat','rb').read(); print('CRLF:', d.count(b'\r\n'), 'lone LF:', d.count(b'\n')-d.count(b'\r\n'))"

REM 3) 한글 잔류 0건 확인 (선택)
findstr /R /C:"[가-힣]" run_sidecar.bat
REM 위 명령에서 매칭 줄이 한 줄도 나오지 않아야 통과

REM 4) 더블클릭 또는 cmd에서 실행
run_sidecar.bat
```

### 기대 결과
- (2) `CRLF: ~77, lone LF: 0`
- (3) 매칭 줄 없음
- (4) 실행 시:
  - 더 이상 `'�글' is not recognized as an internal or external command` 메시지가 **출력되지 않음**
  - 헤더 → `[1/2] scan_dump.py` → 사이드카 실행 → `[2/2] sector_dump.py` → 사이드카 실행 → `Final file check`(두 JSON `: exists` 또는 `: missing`) → `Done` 블록 → `Done. Press any key to exit.` → `pause`에서 멈춤
- 사이드카 2종 모두 성공 시 `logs\sidecar\scan_dump_latest.json`·`logs\sidecar\sector_dump_latest.json`이 최신 timestamp로 갱신됨

### 만약 더 다른 깨진 메시지가 나오면
- 즉시 해당 메시지 한 줄을 그대로 기록 후 추가 핫픽스 검토
- `run_daily.bat`이 한글로 정상 동작하는 환경이므로 본질적 한글 깨짐은 아니며, 특정 줄 또는 cmd 토큰화 사고로 좁혀 분석 가능
