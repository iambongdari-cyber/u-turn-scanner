## 1. 현재 데이터로 장세 판단이 가능한지

**결론: 가능합니다.** v0.5 1단계는 신규 fetch 없이 기존 사이드카만으로 충분합니다.

### 1-1. 사이드카 안 즉시 활용 가능한 시장 지표

호스트 데이터 확인 (`logs/sidecar/scan_dump_latest.json`, `sector_dump_latest.json`):

| 위치 | 키 | 값 예시 (2026-06-13 기준) | 의미 |
|---|---|---|---|
| `scan_dump.market.flow` | flow | `"중립 흐름"` | 사이드카가 이미 산출한 시장 흐름 (강세/중립/약세) |
| `scan_dump.market.kospi_above_ma60` | boolean | `true` | 코스피 종가가 60일선 위인지 |
| `scan_dump.market.kosdaq_above_ma60` | boolean | `false` | 코스닥 종가가 60일선 위인지 |
| `scan_dump.market.kospi_20d_return` | number | `3.56` | 코스피 20일 수익률 (%) |
| `scan_dump.market.kosdaq_20d_return` | number | `-12.56` | 코스닥 20일 수익률 (%) |
| `sector_dump.market_flow` | string | `"중립 흐름"` | scan 과 동일 값 |
| `sector_dump.market_avg_20d_return` | number | `-4.5` | KOSPI/KOSDAQ 평균 |
| `sector_dump.sectors_strong[]` | array | 길이 N | 강한 섹터 수 + 각 섹터 20d 수익률 |
| `sector_dump.sectors_weak[]` | array | 길이 N | 약한 섹터 수 |
| `scan_dump.summary.stage_counts` | dict | `{'U턴 시도': N, ...}` | 4 단계 분포 |
| `scan_dump.summary.n_chase_risk_strong` | int | 추격 위험 종목 수 | 시장 과열도 1 지표 |
| `scan_dump.summary.n_critical_in_bottom` | int | 뉴스 위험 종목 수 | 시장 불안 1 지표 |
| `scan_dump.summary.n_candidates_bottom` | int | 바닥 후보 총수 | 시장 회복 시점 1 지표 |

→ KOSPI/KOSDAQ 의 가격 위치 + 추세 + 섹터 분포 + 후보 분포까지 모두 사이드카 안에 이미 존재. **신규 fetch 0건으로 v0.5 1단계 구현 가능**.

## 2. 가능한 경우 어떤 데이터로 판단하는지

### 2-1. v0.5 1단계 판단 알고리즘

**MarketRegime 5 단계 분류**:

| Regime | 라벨 | 한국어 | 전략 모드 |
|---|---|---|---|
| `STRONG_BULL` | 강세장 | 강세장 | 공격 |
| `MILD_BULL` | 약한 강세 | 강세장 (약함) | 공격 (보수적) |
| `NEUTRAL` | 보합장 | 보합장 | 선별 |
| `MILD_BEAR` | 약한 약세 | 약세장 (약함) | 방어 + 짧은 반등 |
| `STRONG_BEAR` | 약세장 | 약세장 | 방어 + 짧은 반등 |
| `UNKNOWN` | 판단 보류 | 판단 보류 | 보합장 가정 |

### 2-2. 판단 입력 신호 5종

#### S1. 사이드카 market_flow (가중 5)
- "강세 흐름" → +5
- "약세 흐름" → -5
- "중립 흐름" 또는 없음 → 0

#### S2. KOSPI 60일선 위치 (가중 2)
- `kospi_above_ma60 === true` → +2
- `kospi_above_ma60 === false` → -2

#### S3. KOSDAQ 60일선 위치 (가중 2)
- `kosdaq_above_ma60 === true` → +2
- `kosdaq_above_ma60 === false` → -2

#### S4. KOSPI 20일 수익률 (가중 가변)
- `>= +5%` → +3
- `>= +2%` → +1
- `<= -5%` → -3
- `<= -2%` → -1
- 그 외 → 0

#### S5. KOSDAQ 20일 수익률 (가중 가변)
- 동일 임계로 ±3 / ±1 / 0

#### S6. (보조) 강한 섹터 vs 약한 섹터 비율 (가중 가변)
- `len(sectors_strong) - len(sectors_weak) >= 3` → +1
- `len(sectors_weak) - len(sectors_strong) >= 3` → -1
- 그 외 → 0

#### S7. (보조) 추격 위험 종목 비율 (가중 1)
- `n_chase_risk_strong >= 40` → -1 (과열 경고)
- `n_chase_risk_strong == 0` → +0 (중립)
- 그 외 → 0

### 2-3. 합산 → Regime

총점 범위 (최소 -16 ~ 최대 +16):

| 총점 | Regime |
|---|---|
| `>= +9` | STRONG_BULL |
| `+4 ~ +8` | MILD_BULL |
| `-3 ~ +3` | NEUTRAL |
| `-8 ~ -4` | MILD_BEAR |
| `<= -9` | STRONG_BEAR |
| (데이터 없음) | UNKNOWN |

### 2-4. 호스트 데이터 시뮬레이션 (2026-06-13)

```
S1 market_flow "중립 흐름":           0
S2 kospi_above_ma60 true:            +2
S3 kosdaq_above_ma60 false:          -2
S4 kospi_20d_return +3.56%:          +1
S5 kosdaq_20d_return -12.56%:        -3
S6 sectors_strong vs sectors_weak:   (확인 필요)
S7 추격 위험 비율:                    (확인 필요)
─────────────────────────────────
총점:                                 -2 (보조 제외)
→ NEUTRAL (보합장) — 전략 모드: 선별
```

→ 사용자가 "지금 보합장" 으로 느끼는 시장 상태와 일치. 알고리즘 1차 검증 OK.

### 2-5. 시그널 사유 (reasons) — UI/GPT 노출용

각 점수 기여 항목을 자연어로:
- "사이드카 시장 흐름: 중립"
- "KOSPI 60일선 위 (+)"
- "KOSDAQ 60일선 아래 (-)"
- "KOSPI 20일 +3.6%"
- "KOSDAQ 20일 -12.6%"

## 3. 부족한 데이터가 무엇인지

### 3-1. v0.5 1단계로 충분 (신규 fetch 0건)
위 7개 시그널만으로도 사용자 명세의 강세/보합/약세 3 단계 + 약한 강세/약한 약세 보조 분류까지 가능. **v0.5 에서는 추가 데이터 fetch 불필요**.

### 3-2. v0.6 이후 추가 가능한 데이터

| 추가 데이터 | 효과 | 구현 비용 |
|---|---|---|
| **KOSPI/KOSDAQ 지수 OHLCV 일봉 일별 저장** | 5/10/20/60일선 + 추세 + 변동성 정밀 산출 → 약세 초기 / 강세 후기 등 더 세밀한 분류 | FinanceDataReader 'KS11', 'KQ11' 일봉 fetch + scripts/load_market_index.py 신규 + 사이드카 키 확장 |
| **거래대금 총합 (KOSPI/KOSDAQ 일별)** | 시장 거래대금 추세 → 강세 확인 / 약세 이탈 | 동일 스크립트 확장 |
| **VKOSPI (변동성 지수)** | 공포/탐욕 정도 측정 → 약세장 초기 진입 신호 | 별도 fetch (가능 여부 검증 필요) |
| **외인/기관 매매 동향** | 수급 주체 흐름 → 주도주 후보 정밀화 | KRX 별도 fetch (실시간 외 일별 발표는 EOD 사용 가능) |
| **섹터 ETF 가격 추세** | sectors_strong/weak 보강 | 별도 fetch |
| **사용자 보유 비중 / 현금 비중** | "현금 비중 유지" 같은 안내의 개인화 | 사용자 입력 + localStorage |

→ v0.6 이후 우선순위: ①KOSPI/KOSDAQ 일봉 → ②거래대금 총합 → ③외인/기관 → 나머지.
