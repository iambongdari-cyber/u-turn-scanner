## 1. 작업 목적

v0.3-12 에서 홈 4 카드 클릭으로 `/changes?focus=...` 진입 + ring 강조까지는 구현됐다. 그러나 페이지가 상단부터 시작되므로 강조된 카드를 보려면 사용자가 직접 스크롤해야 했다 (설계 §1 한계 B).

v0.3-13은 **클라이언트 wrapper 1개** + **카드 5개에 `id` 부착**만으로 클릭 즉시 강조 위치로 자동 점프하게 만든다. 데이터·JSON·산식·DB·`run_daily.bat` 모두 무변경.

## 3. 카드 id 매핑 (설계 §5-2 그대로)

| focus 키 | 부착 id | 강조 대상 카드 |
|---|---|---|
| `new` | `focus-new` | KeyChangeHighlights NEW (단일 카드, 상단) |
| `up` | `focus-up` | KeyChangeHighlights RANK_UP |
| `down` | `focus-down` | KeyChangeHighlights RANK_DOWN |
| `score` | `focus-score` | KeyChangeHighlights SCORE_UP |
| `out` | `focus-out` | QuickTopCards DEPARTED (KeyChangeHighlights에 없으므로 하단 QuickCards) |
| `sector` | (없음) | 강조 매핑 없음 (현 시점 데이터 0건, 향후 확장용) |

> **이중 매칭 시 우선순위**: `new`/`up`/`down` 의 경우 KeyChangeHighlights(상단)과 QuickTopCards(하단) 양쪽에 같은 variant가 있지만, id는 **KeyChangeHighlights 한쪽에만 부여**해 자동 스크롤 대상이 명확. ring 강조는 v0.3-12 그대로 양쪽 모두 적용.

## 4. 동작 흐름

1. 사용자가 홈 `MiniHighlight` 카드 헤더(v0.3-12) 클릭
2. 브라우저가 `/changes?focus=<key>` 로 이동
3. `ChangesPage`(서버) → `normalizeFocus(searchParams.focus)` 로 화이트리스트 검증 → `focus` 변수
4. 서버 렌더링 결과에 `<FocusScroller focus={focus} />` 포함 (출력 없음)
5. 클라이언트 hydration 후 `FocusScroller` 의 `useEffect` 실행
6. 50ms 지연(레이아웃 안정화) → `document.getElementById('focus-<key>')` → `scrollIntoView({ behavior: 'smooth', block: 'center' })`
7. 사용자 화면이 해당 카드를 뷰포트 중앙으로 부드럽게 스크롤
8. ring 강조(v0.3-12)가 그대로 보이므로 도착 위치 시각적으로 명확

### 안전 분기
- `focus` 가 null (URL에 ?focus 없음) → useEffect 즉시 return → 스크롤 0
- `focus` 가 화이트리스트 밖 (`?focus=foo`) → 클라이언트 측에서도 한 번 더 차단 → 스크롤 0
- `document.getElementById(...)` 가 null (id 부재) → `el?.scrollIntoView` 가 안전하게 단락 → 에러 0
- 구형 브라우저 `scrollIntoView` 옵션 미지원 → try/catch 안에서 옵션 없이 폴백
