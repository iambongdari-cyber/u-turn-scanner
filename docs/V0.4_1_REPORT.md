> **작성일:** 2026-06-13

## 1. 구현 요약

v0.4 의 `/beginner` 화면은 기능은 모두 정상이었지만, 실제 사용 시 후보가 너무 많이 보이고 사용자가 "뭘 해야 할지" 직접 다시 골라야 했습니다. v0.4-1 은 화면 전체를 **"후보 목록"** 에서 **"오늘 해야 할 투자 행동을 지시해주는 화면"** 으로 재정의합니다.

핵심 변화 5가지:

1. **확인 필요도 5 등급** (`URGENT` / `TODAY` / `INTEREST` / `LATER` / `HIDDEN`) — 종목마다 "오늘 확인해야 할 이유" 를 기준으로 자동 계산
2. **오늘 결론 영역** — 자연어로 "오늘은 X 만 확인하면 됩니다" 형태의 핵심 요약 + 카운트 4 줄
3. **꼭 보세요 영역** — URGENT/TODAY 등급 종목만 노출, 개수 제한 없음 (1 개면 1 개, 10 개면 10 개)
4. **지시형 카드** — "왜 봐야 하나 / 이대로 하세요 / 기록하세요" 3 단 구조 + 색상 분리 (긴급=빨강 / 오늘=노랑 / 관심=파랑)
5. **전체 후보 기본 접힘** — 3 카테고리 후보는 `[참고 후보 펼치기]` 버튼 안에 격납 (삭제 X)

GPT 리포트도 같은 원칙으로 재작성 — 기존 "전체 후보 나열" 에서 "오늘 결론 → 꼭 확인할 종목 → 하지 말 행동 → 기록 액션" 순 행동 중심 8 섹션으로 전환했습니다.

저장 구조 / 사이드카 / 스캔 산식 / 기존 5 화면은 모두 무변경. localStorage 키 `tradePlans` 유지.

## 3. 오늘 결론 영역 구현 내용

`buildTodayBrief(items)` (today_brief.ts) 가 `TodayBriefItem[]` 을 받아 자연어 헤드라인 + 4 줄 bullets + 하지 말 행동을 생성합니다.

### 헤드라인 분기 (우선순위 순)
1. **긴급 ≥ 1** → `"긴급 확인 N건 — 종목명 · ... 외"`
2. **신규+예약+보유 = 0** → `"오늘은 꼭 확인할 종목이 없습니다."`
3. **신규 0 + 보유 0 + 예약 ≥ 1** → `"오늘은 예약매수 대기 N건 점검만 하면 됩니다."`
4. **신규 0 + 보유 ≥ 1** → `"오늘은 신규 매매보다 보유종목 N건 점검이 우선입니다."`
5. **신규 ≥ 1 + 보유 0 + 예약 0** → `"오늘 신규로 볼 종목: 종목명 외 N건"`
6. 그 외 → `"오늘은 신규 X건, 보유 Y건, 예약 Z건을 확인하면 됩니다."`

### 4 줄 bullets
- 오늘 신규로 볼 종목: 종목명 · ... 외 N건 (총 N건) / 없음
- 해야 할 행동: 매매 계획 기록 후 키움 예약매수 검토 (신규 ≥ 1일 때)
- 예약매수 대기 확인: ... / 없음
- 보유종목 점검: ... / 없음
- 오늘 하지 말아야 할 행동: 후보 전체를 훑지 말고, 꼭 볼 종목만 확인

### 하지 말아야 할 행동 (사용자 명세 §10)
기본 3 줄 + 보유 종목이 있으면 2 줄 추가:
- 후보 전체를 훑으며 충동 매수하지 않기
- AI 판단이 관찰인 종목은 매매계획만 보류
- 손절가 없이 예약매수 넣지 않기
- (보유 종목 ≥ 1) 보유종목이 있는데 신규 후보를 과하게 늘리지 않기
- (보유 종목 ≥ 1) 보유종목 추가매수는 눌림 전까지 금지

표시 위치: `TodayConclusion` 컴포넌트 안 `🚫 오늘 하지 말아야 할 행동` 빨강 박스.

## 4. 꼭 보세요 영역 구현 내용

`MustSeeSection` 은 전체 `briefItems` 에서 다음 조건을 만족하는 종목만 표시합니다:
- `kind === 'NEW_CANDIDATE'` (신규 후보)
- `level === 'URGENT'` 또는 `level === 'TODAY'`

(예약/보유 종목은 `MyPlansSection` 에서 별도 표시 — 자연스럽게 섹션 분리)

### 카드 구성 (지시형 3 단)
각 카드는 `DirectiveCard` 공통 컴포넌트로 다음 영역을 렌더:
- **상단**: 종목명 + AI 판단 뱃지 + 확인 필요도 뱃지
- **왜 봐야 하나**: U턴 N/5 / 위험 낮음·보통 / 거래대금 회복 / AI 판단 변화 사유 등 (`buildDirective` 가 계산)
- **이대로 하세요**: `매매 계획 기록 → 1차 예약매수가 확인 → 키움 예약매수는 직접 입력` (체크박스 형식)
- **기록하세요**: `<TradePlanButton row={row} />` (28 필드 폼 모달 진입)
- **하단**: 안내 문구 "개인 기록용 AI 판단입니다."

### 색상
- URGENT: `border-red-300 bg-red-50/30` (빨강)
- TODAY: `border-amber-300 bg-amber-50/30` (노랑)
- INTEREST: `border-sky-300 bg-sky-50/30` (파랑, 관심 확인 후보 섹션에서 사용)

### 개수 제한 없음
사용자 명세대로 1 개면 1 개, 10 개면 10 개 표시. 꼭 봐야 할 종목이 없으면 `"✅ 오늘 꼭 확인할 신규 후보는 없습니다."` 표시.

## 5. 확인 필요도 등급 계산 기준 (today_brief.ts)

`computeUrgency(input)` 가 3 가지 분기로 평가합니다.

### 5-1. 예약매수 대기 (RESERVED)
| 조건 | 등급 | 사유 |
|---|---|---|
| 현재가 ≤ 손절가 | **URGENT** | 손절 기준가 이탈 — 예약 취소 검토 |
| 현재가 > 1차 예약가 +5% | **URGENT** | 현재가가 1차 예약가 대비 멀어짐 |
| 그 외 | **TODAY** | 예약가 근처 — 유지 확인 |

### 5-2. 보유 (FIRST_FILLED / SECOND_FILLED / HOLDING / PARTIAL_SOLD)
| 조건 | 등급 | 사유 |
|---|---|---|
| 현재가 ≤ 손절가 | **URGENT** | 손절 기준가 이탈 — 매도 검토 |
| 현재가 ≥ 목표가 | **URGENT** | 목표 매도가 도달 — 일부매도 검토 |
| 손절가 3% 이내 근접 | **URGENT** | 손절 기준가 근접 |
| 목표가 3% 이내 근접 | **URGENT** | 목표 매도가 근접 |
| AI 판단 == PARTIAL_SELL / SELL | **URGENT** | AI 판단이 매도 신호 |
| 추가매수 4/4 | **TODAY** | 추가매수 조건 충족 — 눌림 관찰 |
| 그 외 | **TODAY** | 보유 종목 — 일일 점검 |

### 5-3. 신규 후보 (NEW_CANDIDATE)
| 조건 (위에서 아래로 우선) | 등급 |
|---|---|
| AI 판단 == EXCLUDE | **HIDDEN** |
| 위험 == HIGH + U턴 ≤ 2/5 | **HIDDEN** |
| 이격 ≥ 18% | **HIDDEN** |
| 어제 EXCLUDE/WATCH → 오늘 BUY (강하게 개선) | **URGENT** |
| 어제 WATCH → 오늘 BUY (개선) | **URGENT** |
| AI BUY + 위험 LOW/MED + U턴 강함 이상 + 4/5 이상 + 거래대금 회복 | **TODAY** |
| AI WATCH + U턴 관찰 이상 + 3/5 이상 | **INTEREST** |
| 그 외 (2/5 이하 또는 약함) | **LATER** |

각 등급에는 사유 배열 `reasons` 가 따라옵니다 — 카드 / GPT 리포트에서 그대로 표시.

## 6. 전체 후보 접힘 처리 방식

`CollapsibleCandidates` 클라이언트 컴포넌트가 두 개의 독립 펼침 영역을 관리합니다:

### 6-1. 관심 확인 후보 (`INTEREST` 등급만)
- **기본 접힘** (useState 초기값 `false`)
- 버튼: `[관심 확인 펼치기] / [접기]`
- 펼치면 `CategoryCard` 그리드로 표시 (2 열)
- 비어있으면 "관심 확인 후보 없음." 표시

### 6-2. 참고 후보 전체 (3 카테고리 통합)
- **기본 접힘** (useState 초기값 `false`)
- 버튼: `[참고 후보 펼치기] / [접기]`
- 펼치면 3 카테고리 (바닥 U턴 / 현재 주도주 / 후발 강세) 를 각자 헤더 + `CategoryCard` 그리드로 표시
- HIDDEN 등급은 미포함 (page.tsx 에서 사전 필터)
- 비어있으면 "해당 카테고리 후보 없음." 표시

### 6-3. 데이터 보존
사용자 명세 §7 "후보를 삭제하는 것이 아니라 기본 화면에서 접어두는 것" 원칙대로 LATER/INTEREST 등급도 그대로 표시 가능. HIDDEN 만 기본 화면에서 미렌더 (EXCLUDE/추격 위험 등 행동 이유 없는 종목).

## 7. GPT 리포트 변경 내용

기존 v0.4 GPT 리포트는 "신규 후보 / 예약매수 / 보유 / 근접 / 판단 변경 / 오늘 행동 / 변경 이력 / 추가매수" 8 섹션이었으나, v0.4-1 에서는 **행동 중심** 으로 재작성:

| § | 신규 v0.4-1 섹션 | 내용 |
|---|---|---|
| 1 | 오늘 결론 | `brief.primaryHeadline` + 4 줄 bullets |
| 2 | 꼭 확인할 종목 | URGENT + TODAY 통합 — 종목별 한 줄 액션 + 사유 |
| 3 | 오늘 하지 말아야 할 행동 | `brief.dontDo` 3~5 줄 |
| 4 | 예약매수 대기 종목 | 상세 (예약가/현재가/AI 판단/오늘 행동) |
| 5 | 보유종목 점검 | 상세 (평균매수가/수익률/목표가/손절가/근접 경고) |
| 6 | 기록해야 할 것 | "○○○ 매매 계획 기록" / "○○○ 보유 판단 유지" 형식 |
| 7 | 관심 확인 후보 요약 | INTEREST 등급 종목 한 줄씩 (최대 10 + 외 N건) |
| 8 | 전체 후보 요약 | 총 N건 / 분포 / 안 봐도 되는 후보 N건 |

마크다운 예시:
```markdown

오늘은 신규 매매보다 보유종목 1건 점검이 우선입니다.
```

호스트 사이드카 (340 개 후보) 가정 시 분류:
- URGENT 신규: 보통 0~5 건 (이격 18% 미만 + AI 판단 변화 시)
- TODAY 신규: 보통 5~20 건 (BUY + U턴 4/5 이상)
- INTEREST 신규: 보통 50~100 건 (WATCH + 3/5 이상)
- LATER + HIDDEN: 약 200~250 건 → 기본 접힘

→ 사용자 명세대로 "꼭 봐야 할 종목만" 화면 상단에 표시 ✓

### 9-3. 빌드 검증 (격리 환경)
샌드박스 mount stale 로 인해 sandbox 안에서 직접 `tsc --noEmit` 결과는 "잘린 파일" 로 인한 오류만 발생. Read tool 로 호스트 파일 끝부분 확인 결과 모든 파일이 정상 종료 (`page.tsx` 185 줄, `gpt_report.ts` 정상 마감 등).

호스트 파일들 자체에는 타입 오류 없음을 import/export 시그니처 검증으로 확인.
