→ 사용자에게는 동일한 버튼/링크 1개만 보이고, 화면 폭에 따라 동작 방식이 자동 분기.

## 4. Tailwind CSS 분기 방식 선택 이유

| 방식 | 장점 | 단점 |
|---|---|---|
| **CSS Tailwind (`md:hidden` / `hidden md:block`)** ← v0.7.5 채택 | SSR 즉시 결정 / JS 비활성도 동작 / 화면 크기 변경 시 자동 반영 | 두 컴포넌트 모두 마운트됨 (성능 영향 미미) |
| JS `window.innerWidth` 분기 (useEffect) | 정확한 환경 판단 | SSR 시 hydration mismatch 가능 / 화면 회전/리사이즈 처리 추가 필요 |
| userAgent 기반 분기 (서버 헤더) | 단순 | iPad 등 경계 디바이스 오분류 / 데스크톱 좁은 창 미고려 |

→ 사용자 명세 §"CSS로 모바일/PC 버튼을 나누어도 됨" 의 추천 구조 그대로 채택.

### 4-1. Tailwind md 브레이크포인트
- `md`: `768px` (기본값)
- 폭 ≥ 768px → PC 버튼 노출, 모바일 Link 숨김
- 폭 < 768px → 모바일 Link 노출, PC 버튼 숨김

## 5. 동작 매트릭스

| 환경 | 폭 | 노출 entry | 클릭 시 동작 |
|---|---|---|---|
| 데스크톱 PC | ≥ 768px | PC Button (인라인) | 같은 카드 안 인라인 펼침 (v0.7.3 4 phase state machine) |
| 좁은 PC 창 (예: 700px) | < 768px | 모바일 Link | `/beginner/gpt-report` 페이지 이동 |
| 태블릿 가로 (iPad 가로) | ≥ 768px | PC Button | 인라인 펼침 |
| 태블릿 세로 (iPad 세로) | ~768px 부근 | 폭에 따라 | (768 이상이면 PC, 미만이면 모바일) |
| 모바일 Chrome / Safari | < 768px | 모바일 Link | `/beginner/gpt-report` 페이지 이동 (v0.7.4 안정 흐름) |
| 모바일 in-app 브라우저 | < 768px | 모바일 Link | 페이지 이동 정상 |
| PWA standalone | 폭에 따라 | 자동 분기 | 정상 |

→ **사용자가 의식하지 않아도 환경에 맞는 UX 자동 적용**. PC 좁은 창에서 일시적으로 모바일 흐름 (별도 페이지) 으로 전환되더라도 본문 표시는 정상.

## 7. 테스트 시나리오

### 7-4. 모바일 in-app 브라우저
