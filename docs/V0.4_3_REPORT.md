# U-Turn Scanner — v0.4-3 구현 보고서 (지난 투자판단 리스트/보기)

> **작성일:** 2026-06-13
> **선행:** `V0.4_2_REPORT.md`
> **요청:** `/beginner` 화면의 "놓친 리포트" 영역을 단순 날짜 목록에서 **클릭 가능한 "지난 투자판단 보기"** 로 확장. 어제 또는 못 본 날짜의 `/beginner` 화면을 다시 볼 수 있게.

## 1. 구현 요약

기존 "놓친 리포트" 는 `logs/sidecar/daily/scan_dump_YYYY-MM-DD.json` 의 날짜와 후보 수만 표시했고, 클릭이 불가능해 사용자가 과거 투자판단을 다시 확인할 수 없었습니다.

v0.4-3 은 (1) `/beginner` 페이지가 URL `?date=YYYY-MM-DD` 쿼리 파라미터를 받아 해당 날짜의 `daily/scan_dump_*.json` + `daily/sector_dump_*.json` 을 로드하도록 확장, (2) 섹션명을 **"지난 투자판단"** 으로 변경하고 각 날짜에 **[보기]** 버튼을 추가, (3) 날짜별 확인 상태를 `beginner_seen_dates: { "YYYY-MM-DD": true }` localStorage 키로 누적 저장, (4) 기존 `beginner_last_seen_date` 단일 키는 자동 마이그레이션 + 병행 갱신, (5) 지난 판단 보기 모드에서는 헤더에 **"📜 지난 투자판단을 보고 있습니다"** 안내 박스와 `최신으로 돌아가기` 링크 노출, (6) GPT 리포트 생성도 선택 날짜 (`data.base_date`) 기준으로 자동 반영.

저장 구조 / 스캔 산식 / 키움 API / Supabase write / 사이드카 JSON 구조 / 기존 5 화면 모두 무변경.

## 3. 지난 투자판단 리스트 구현 내용

### 3-1. 데이터 소스
`logs/sidecar/daily/scan_dump_YYYY-MM-DD.json` 의 전체 목록을 날짜 내림차순으로 정렬하여 최근 30개까지 로드. 화면에서는 상위 14개 노출, 나머지는 "외 N건 (최근 14개만 표시)" 으로 안내.

### 3-2. 행 구성

```
2026-06-12              지난 투자판단 보기   [보기]
후보 430개 · 미확인

2026-06-08              지난 투자판단 보기   [보기]
후보 340개 · 확인 완료

2026-06-05              지난 투자판단 보기   [보기]
후보 280개 · 미확인 · 현재 보고 있음 (amber 배경)
```

표시 항목 (사용자 명세 §5):
- **날짜** (`YYYY-MM-DD`)
- **후보 수** (`scan_dump.candidates_bottom.length`)
- **확인 상태** (`beginner_seen_dates[date] ? '확인 완료' : '미확인'`)
- **보기 버튼** (`<Link href="/beginner?date=YYYY-MM-DD">`)
- **현재 보고 있음** 마커 (effectiveDate === r.date 일 때)

### 3-3. 상단 헤더
```
📂 지난 투자판단              [오늘 확인 완료]
못 본 날이나 어제의 투자판단을 다시 확인합니다.
```

`[오늘 확인 완료]` 버튼은 effectiveDate (= 현재 보고 있는 날짜) 를 자동으로 확인 완료 처리. 지난 판단 보기 모드에서도 동작 — 그 날짜를 본 것으로 표시.

## 4. `/beginner?date=YYYY-MM-DD` 동작 방식

### 4-1. URL 파싱 (사용자 명세 §3)

```ts
const sp = (await searchParams) ?? {};
const rawDate = typeof sp.date === 'string' ? sp.date : undefined;
const requestedDate = rawDate && /^\d{4}-\d{2}-\d{2}$/.test(rawDate) ? rawDate : undefined;
```

- 형식 불일치 (`?date=invalid`) → `undefined` 로 떨어져 최신 latest 사용 (안전)
- 형식 일치 → 해당 날짜로 daily 폴더 조회

### 4-2. 데이터 로드 분기

| 매개변수 | scan_dump 위치 | sector_dump 위치 |
|---|---|---|
| `date === undefined` | `logs/sidecar/scan_dump_latest.json` | `logs/sidecar/sector_dump_latest.json` |
| `date === 'YYYY-MM-DD'` | `logs/sidecar/daily/scan_dump_YYYY-MM-DD.json` | `logs/sidecar/daily/sector_dump_YYYY-MM-DD.json` 우선, 없으면 그보다 이전 가장 가까운 sector_dump 로 fallback |

호스트 데이터에서 `scan_dump_2026-06-02.json` 은 있지만 `sector_dump_2026-06-02.json` 은 없는 경우 → `sector_dump_2026-06-03.json`... 중 `date <= 2026-06-02` 인 가장 큰 날짜 sector 파일을 찾음 (이 경우엔 없으므로 sector 없이 진행, 카테고리 분류는 fallback 으로 BOTTOM_UTURN).

### 4-3. 이전 판단 비교 (어제 → 오늘 AI 판단 변화)

`loadPreviousScanRows(date?)` — date 가 주어지면 그보다 **이전** 가장 가까운 scan_dump 파일을 로드, 없으면 최신 - 1 사용. 이로써 v0.4-2 의 "어제 EXCLUDE/WATCH → 오늘 BUY (강하게 개선)" URGENT 판정 로직이 과거 날짜 보기에서도 자연스럽게 작동.

### 4-4. 헤더 안내 (사용자 명세 §4)

지난 판단 모드 (`isPastView === true`) 일 때:

```
📊 오늘의 투자판단                    [기준일: 2026-06-08] (amber 강조)
퇴근 후 10분, 오늘 해야 할 행동만 보여드립니다.

┌──────────────────────────────────────────────────────────┐
│ 📜 지난 투자판단을 보고 있습니다.                          │
│ 현재 날짜가 아니라 선택한 기준일(2026-06-08)의 스냅샷입니다.│
│ 최신(2026-06-12)으로 돌아가기 →                            │
└──────────────────────────────────────────────────────────┘
```

기준일 표시는 amber 박스로 강조해서 사용자가 "현재 날짜가 아님" 을 한눈에 인식하도록 함.

### 4-5. 데이터 없음 케이스
요청 날짜의 scan_dump 가 없으면:
```
2026-06-30 사이드카 데이터 없음
해당 날짜의 scan_dump_2026-06-30.json 파일이 없거나 비어있습니다.
다른 날짜를 선택하거나 최신 투자판단으로 돌아가세요.
```

## 5. 확인 완료 저장 구조

### 5-1. 새 저장 키 (사용자 명세 §6)

```ts
const SEEN_DATES_KEY = 'beginner_seen_dates';

// 형태
{
  "2026-06-12": true,
  "2026-06-08": true,
  "2026-06-05": true
}
```

### 5-2. 기존 키 마이그레이션

기존 v0.4 / v0.4-1 / v0.4-2 까지 사용한 `beginner_last_seen_date` (단일 문자열) 키는:
- mount 시 자동 읽어서 `seenDates[legacy] = true` 로 변환
- `setItem` 시 두 키 모두 갱신 (다른 화면이 깨지지 않게 병행)

```ts
const legacy = window.localStorage.getItem(LEGACY_LAST_SEEN_KEY);
if (legacy && !parsed[legacy]) {
  parsed = { ...parsed, [legacy]: true };
  window.localStorage.setItem(SEEN_DATES_KEY, JSON.stringify(parsed));
}
```

### 5-3. 확인 완료 트리거

| 동작 | 효과 |
|---|---|
| `[보기]` 클릭 | 해당 날짜 → `seenDates[date] = true` |
| `[오늘 확인 완료]` 클릭 | `effectiveDate` (현재 보고 있는 날짜) → `seenDates[effectiveDate] = true` |
| 두 동작 모두 | `beginner_last_seen_date` 도 동일하게 갱신 (병행) |

## 6. GPT 리포트 날짜 기준 반영 (사용자 명세 §8)

`GptReportButton` 에 전달되는 `base_date` prop 은 `page.tsx` 에서 `data.base_date` 를 그대로 넘기므로, `?date=2026-06-08` 모드에서는 자동으로 `2026-06-08` 기준의 마크다운이 생성됩니다.

```ts
// page.tsx 안
<GptReportButton
  base_date={data.base_date}   // ← 선택 날짜의 base_date (또는 fallback)
  rows={data.rows}              // ← 선택 날짜의 후보 행
  priceByTicker={priceByTicker} // ← 선택 날짜의 close (priceByTicker)
  previousJudgementByTicker={previousJudgementByTicker}
                                // ← 선택 날짜의 직전 scan 의 AI 판단
/>
```

리포트 헤더에는 `> 생성일: 2026-06-08 — 개인 기록용 AI 판단입니다.` 로 노출. GPT 영역 위에 별도 안내도 추가:
```
지난 판단 모드: "2026-06-08 기준 투자판단 리포트를 생성합니다."
최신 모드:     "ChatGPT 에게 그대로 붙여넣어 상담받을 수 있는 행동 중심 마크다운 리포트를 생성합니다."
```
