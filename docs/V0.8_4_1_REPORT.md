## 2. 화면 순서 변경

### 기존 (v0.8-4)
```
📋 오늘의 결론          ← TodayConclusion
📊 오늘 시장 상태       ← MarketRegimeBox
🧭 전략 컨디션          ← StrategyConditionBox
🌊 내일 한눈에 보기     ← MarketFlowBox  (중복: NAVER 1개만 보세요)
📝 매매계획 기록하기    ← MustSeeSection
🔔 내 예약매수 대기 / 📦 내 보유종목 점검
🔍 관심 후보 / 📚 참고 후보
📂 지난 투자판단
💬 GPT에게 다시 물어보기
```

### 변경 후 (v0.8-4.1) — 사용자 명세 §변경 후 화면 순서 그대로
```
1. 🌊 내일 한눈에 보기     ← MarketFlowBox  (핵심 카드, 화면 최상단)
2. 📊 오늘 시장 상태       ← MarketRegimeBox (보조)
3. 🧭 전략 컨디션          ← StrategyConditionBox (보조)
4. 📝 매매계획 기록하기    ← MustSeeSection
5. 🔔 내 예약매수 대기
6. 📦 내 보유종목 점검
7. 🔍 관심 후보
8. 📚 참고 후보
9. 📂 지난 투자판단
10. 💬 GPT에게 다시 물어보기
```

화면 첫 번째 핵심 카드(MarketFlowBox)가 사용자 명세 §목표의 3가지를 모두 말한다:

1. **오늘 장은 이랬어요** — 🌊 오늘 장 요약 (regime + KOSPI/KOSDAQ + 대형주/중소형주 + 💡 핵심 문장)
2. **내일은 이렇게 하세요** — 🎯 내일 행동 (canEnterNew / maxNewCount / summaryLines)
3. **이것은 하지 마세요** — 🚫 금지 행동 (mustNotDo)

## 3. 흡수한 문구

TodayConclusion 의 콘텐츠 중 MarketFlowBox 에 없던 것은 다음 4개:

| TodayConclusion 항목 | 처리 |
| --- | --- |
| 💡 `corePhrase` (핵심 문장 한 줄) | **MarketFlowBox 의 "🌊 오늘 장 요약" 박스 마지막 줄에 흡수** |
| 오늘의 태도 (`attitude`) | MarketRegimeBox 에 이미 노출됨 → 흡수 불필요 |
| 전략 모드 (`modeLabel`) | MarketRegimeBox 에 이미 노출됨 → 흡수 불필요 |
| `conclusionText` 자연어 2~3줄 | MarketFlowBox 의 todayLines (regime/KOSPI·KOSDAQ/capStyle narrative) 와 정보 중복 → 흡수 불필요 |

MarketFlowBox 의 "오늘 장 요약" 박스 안에 추가된 코드:

```tsx
{marketRegime.corePhrase && (
  <div className="mt-2 rounded-md border border-indigo-200 bg-white/80 px-2.5 py-1.5 text-[12px] font-medium text-indigo-800">
    💡 {marketRegime.corePhrase}
  </div>
)}
```

## 4. CoachShell 변경 요약

```tsx
// v0.8-4.1 변경 후 render 구조
return (
  <>
    {regime && marketStrength && capStyle && tomorrowAction && (
      <MarketFlowBox ... />          // ← 최상단
    )}
    {middleBoxes}                    // ← MarketRegimeBox + StrategyConditionBox
    <MustSeeSection ... />
  </>
);
```

- `TodayConclusion` import + render 제거.
- 컴포넌트 파일은 그대로 보존 — 다른 파일에서 import 하지 않음을 확인했고, 향후 회귀/재사용 시 즉시 복구 가능.

## 5. 데이터 부족 케이스 fallback

`MarketFlowBox` 는 4개 prop(`regime`, `marketStrength`, `capStyle`, `tomorrowAction`)이 모두 있을 때만 렌더된다. 데이터 부족 케이스에는 화면이 비어 보이지 않는가?

- 그 경우에도 바로 아래 `middleBoxes` 의 **MarketRegimeBox 가 "데이터 부족" fallback 안내를 노출** 한다 (v0.5 이래 동일).
- 즉 데이터 부족 케이스에는 MarketRegimeBox 가 자동으로 화면 첫 카드가 되어 자연스럽게 보인다.
- TodayConclusion 의 `null regime` fallback ("시장 상태 판단에 필요한 데이터가 부족합니다") 도 MarketRegimeBox 가 동일하게 보여주므로 중복.

## 8. 테스트 방법

호스트:

```
npm run build
npm run dev
```

`/beginner` 접근 후:

1. 화면 최상단이 **🌊 내일 한눈에 보기** 카드인지 (이전의 📋 오늘의 결론 카드는 더 이상 안 보임).
2. 🌊 카드 안에 다음 3 가지가 한 번에 보이는지:
   - 🌊 오늘 장 요약 (오늘 장 한 줄 + KOSPI/KOSDAQ + 대형주/중소형주 + 💡 핵심 문장)
   - 🎯 내일 행동 (1순위 종목 1 줄 + maxNewCount)
   - 🚫 금지 행동
3. 그 다음 순서대로 📊 오늘 시장 상태 → 🧭 전략 컨디션 → 📝 매매계획 기록하기 → 🔔 예약매수 → 📦 보유종목 → 🔍 관심 후보 → 📚 참고 후보 → 📂 지난 투자판단 → 💬 GPT에게 다시 물어보기.
4. 1순위 종목명이 🌊 카드와 📝 카드에서 **동일** 한지 (예: NAVER ↔ NAVER).
5. 데이터가 부족한 날짜(`?date=` 로 과거 빈 날짜)에 진입해도 빌드/런타임 에러 없이 MarketRegimeBox 의 "데이터 부족" fallback 이 자연스럽게 첫 카드 역할.
6. 매매계획 기록 / 예약매수 / 체결 / 매도완료 / GPT에게 다시 물어보기 기능 모두 정상.

### 샌드박스 검증 제약
이전 단계와 동일하게 mount 캐시 stale 이슈로 `tsc --noEmit` 신뢰 불가. 호스트 측 `npm run build` 통과로 최종 확인 부탁드립니다. Read tool 로 확인한 호스트 파일은 모두 정상 구조이며, `topPickName` 변수는 CoachShell 안에 이미 선언되어 있어 MarketFlowBox prop 전달이 안전합니다.
