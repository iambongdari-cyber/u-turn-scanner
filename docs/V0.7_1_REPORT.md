# U-Turn Scanner — v0.7.1 핫픽스 보고서 (모바일 GPT 리포트 복사)

> **작성일:** 2026-06-13
> **선행:** `V0.7_REPORT.md`
> **문제:** PC 에서는 GPT 상담용 리포트 복사가 정상이지만, 모바일 브라우저에서는 `[GPT 상담용 리포트 복사]` 버튼이 동작하지 않거나 복사 여부를 확인하기 어려움.

---

## 1. 원인 분석

`navigator.clipboard.writeText` 는 **secure context** (HTTPS 또는 localhost) 에서만 동작. 모바일에서 HTTP 로 접근하거나 일부 in-app 브라우저에서는 호출이 실패. 기존 코드의 fallback (`document.execCommand('copy')`) 도 iOS Safari 에서 다음 조건을 충족해야 동작:
1. textarea 가 화면 안에 렌더 (화면 밖 좌표는 실패)
2. `readonly` 속성 명시 (자동 키보드 방지)
3. `selection range` 명시적 설정 (`document.createRange()` + `selectNodeContents`)
4. `setSelectionRange(0, length)` 호출

기존 핸들러는 (1)(3)(4) 미충족으로 iOS Safari 에서 실패. 게다가 실패 시 사용자에게 알리는 메시지가 없어서 "복사 됐는지 안 됐는지" 알 수 없었음.

## 2. 수정 내용

### 2-1. 복사 로직 강화 (3 단계)

#### 1단계: `navigator.clipboard.writeText`
```ts
if (navigator?.clipboard?.writeText) {
  await navigator.clipboard.writeText(markdown);
  setCopyStatus('success');
  return;
}
```
- secure context (HTTPS / localhost) 에서 성공
- 실패 시 → 2단계로

#### 2단계: textarea + selection range fallback (iOS Safari 호환)

```ts
const ta = document.createElement('textarea');
ta.value = markdown;
ta.setAttribute('readonly', '');                // iOS 키보드 방지
ta.style.position = 'fixed';
ta.style.top = '0';                              // 화면 안 좌표 (iOS Safari 필수)
ta.style.left = '0';
ta.style.width = '1px';
ta.style.height = '1px';
ta.style.opacity = '0';                          // 시각적으로 숨김
document.body.appendChild(ta);

ta.focus();
ta.select();

// iOS Safari 호환 — selection range 명시
const range = document.createRange();
range.selectNodeContents(ta);
const selection = window.getSelection();
selection?.removeAllRanges();
selection?.addRange(range);
ta.setSelectionRange(0, ta.value.length);

const ok = document.execCommand('copy');
document.body.removeChild(ta);
```

핵심 차이 (기존 → v0.7.1):
| 항목 | 기존 | v0.7.1 |
|---|---|---|
| textarea 위치 | 기본 (body 끝, 화면 밖) | **fixed 0,0 + 1×1px + opacity 0** (화면 안 보이지 않게) |
| readonly 속성 | 없음 | **`setAttribute('readonly', '')`** (iOS 키보드 방지) |
| selection range | `select()` 만 | **`createRange + selectNodeContents + addRange + setSelectionRange`** |
| 키보드 포커스 | 없음 | **`ta.focus()` 명시** |

#### 3단계: 모달 안 pre 영역에서 직접 복사 (최후 안전망)
- 자동 복사 실패 시 모달 안 리포트 전문의 텍스트를 **자동 선택** 처리 (`preRef.current` 의 contents 를 `selectNodeContents`)
- 사용자에게 "아래 내용을 길게 눌러 직접 복사해주세요." 안내
- 모달 안 `<pre>` 영역에 `user-select: text` + `cursor: text` 적용 → 모바일에서 길게 눌러 [복사] 메뉴 호출 가능

### 2-2. 성공/실패 메시지 명확화

| 상태 | 버튼 라벨 | 안내 메시지 |
|---|---|---|
| `idle` | "클립보드에 복사" | (없음) |
| `success` | "✓ 복사됨" | 초록 박스 — **"✓ GPT 상담용 리포트를 복사했습니다."** |
| `fail` | "↻ 다시 시도" | 노란 박스 — **"⚠ 자동 복사에 실패했습니다. 아래 내용을 길게 눌러 직접 복사해주세요."** + 부가 안내 ("텍스트가 미리 선택되어 있습니다 — 휴대폰에서 길게 눌러 [복사] 또는 PC 에서 Ctrl/Cmd + C") |

`success` / `fail` 상태는 3.5초 후 자동으로 `idle` 로 돌아감 (`fail` 도 자동 reset — 사용자가 다시 시도할 수 있게).

### 2-3. fallback 실패 시 리포트 전문 표시 (모달 안)

기존에도 모달 안 `<pre>` 에 markdown 전문이 표시되었지만, fallback 실패 시 사용자가 그것을 인지하고 직접 복사 가능해야 하므로:
- pre 영역에 노란 테두리 + 노란 배경 강조 (`fail` 상태일 때만)
- 자동으로 텍스트 선택 (선택된 영역 시각적 강조)
- pre 가 보이는 위치로 스크롤 (`scrollIntoView({ behavior: 'smooth' })`)
- 모바일에서 길게 눌러 [복사] 메뉴 호출 가능
