# U-Turn Scanner — v0.7.2 핫픽스 보고서 (모바일 GPT 리포트 보기/복사 재핫픽스)

> **작성일:** 2026-06-13
> **선행:** `V0.7_1_REPORT.md`
> **문제:** v0.7.1 의 fallback 강화에도 불구하고 모바일 브라우저에서 [GPT 상담용 리포트 복사] 버튼 클릭 후 복사 성공/실패 여부와 리포트 본문이 사용자에게 확실히 보이지 않음. 자동 복사에만 의존하는 UX 가 모바일에서 신뢰할 수 없음.

---

## 1. 방향 전환

v0.7.1 까지는 "자동 복사 성공" 이 기본 UX 였고 실패 시 안내가 노출되는 구조였습니다. v0.7.2 는 **"리포트 본문 표시" 가 기본 UX 이고 자동 복사는 보조 기능** 으로 역할을 뒤집습니다.

| 항목 | v0.7.1 | v0.7.2 |
|---|---|---|
| 버튼 라벨 | "GPT 상담용 리포트 복사" | **"GPT 상담용 리포트 보기/복사"** |
| 버튼 클릭 동작 | 모달 + 즉시 자동 복사 시도 | **모달 + 본문 표시만** (자동 복사 시도 X) |
| 자동 복사 시도 | 클릭 즉시 (사용자 선택권 없음) | **모달 안 [자동 복사 시도] 버튼** 사용자 선택 |
| 전체 선택 기능 | 자동 복사 실패 시에만 (숨김) | **[전체 선택] 별도 버튼** 항상 노출 |
| 본문 가독성 | 작은 폰트 (text-xs ≈ 12px) | **13~14px** (sm: 14px) + leading-relaxed + 카드 박스 |
| 모바일 모달 크기 | `max-w-3xl` 일반 | **모바일 풀 너비 + 100vh 가까이** (`sm:` 분기로 PC 는 기존 유지) |
| 안내 노출 시점 | 실패 시에만 | **항상 노출** ("자동 복사가 안 되는 환경에서도 본문을 길게 눌러 직접 복사할 수 있습니다.") |

핵심: **자동 복사가 실패해도 사용자는 화면의 본문을 항상 직접 복사할 수 있다.** "복사 됐는지 안 됐는지 모르겠다" 케이스 자체를 제거.

## 2. 수정 내용

### 2-1. 버튼 라벨 변경
- 기존: `💬 GPT 상담용 리포트 복사`
- 변경: **`💬 GPT 상담용 리포트 보기/복사`**

→ 버튼 클릭 시 "복사" 가 자동으로 일어난다는 인상 대신, "리포트를 본 뒤 복사할 수 있다" 는 흐름을 라벨에서 명시.

### 2-2. 버튼 클릭 흐름

```ts
handleOpen() {
  // 1. 리포트 마크다운 생성 (v0.7 그대로)
  // 2. setMarkdown(md)
  // 3. setOpen(true)        ← 모달 열림
  // 4. setCopyStatus('idle')
  //    ※ 자동 복사 시도하지 않음 — 사용자가 모달 안에서 직접 선택
}
```

### 2-3. 모달 구성 (3 영역)

#### (A) 헤더 — 타이틀 + 닫기 + 2 버튼 + 상태 메시지

```
┌─────────────────────────────────────────────┐
│ GPT 상담용 리포트                    [닫기]  │
│ 아래 본문을 ChatGPT 에 붙여넣어 상담받을 수    │
│ 있습니다.                                    │
│                                              │
│ [ 자동 복사 시도 ]  [ 전체 선택 ]           │
│                                              │
│ (성공/실패 메시지 박스 — 색상 분기)         │
│                                              │
│ ※ 자동 복사가 안 되는 환경에서도 아래 본문을  │
│   길게 눌러(모바일) 또는 마우스로 드래그(PC)  │
│   하여 직접 복사할 수 있습니다.              │
└─────────────────────────────────────────────┘
```

#### (B) 본문 — 항상 표시되는 마크다운 (스크롤 가능)

```html
<pre
  className="whitespace-pre-wrap break-words rounded-md border border-slate-200 bg-slate-50 p-3
             font-mono text-[13px] leading-relaxed text-slate-800 sm:text-[14px]"
  style={{
    userSelect: 'text', WebkitUserSelect: 'text', cursor: 'text',
    whiteSpace: 'pre-wrap', wordBreak: 'break-word',
  }}
>
  {markdown}
</pre>
```

핵심 가독성 강화:
- **`text-[13px]`** 모바일 / `sm:text-[14px]` PC (사용자 명세 §5)
- `leading-relaxed` 줄 간격
- `whitespace-pre-wrap` + `wordBreak: break-word` 줄바꿈 보존 + 긴 단어 줄바꿈
- `userSelect: text` + `WebkitUserSelect: text` 모바일 길게 눌러 [복사] 가능
- 카드 박스 (border + bg-slate-50) 로 본문 영역 시각적 분리

#### (C) 푸터 — 추가 안내

```
💡 본문 영역을 길게 눌러서 [복사] 메뉴로 직접 복사할 수도 있습니다.
```

스크롤이 길어 헤더의 안내를 못 보고 본문 끝까지 내려간 사용자가 다시 안내를 볼 수 있게 푸터에도 노출.

### 2-4. [자동 복사 시도] 동작 (v0.7.1 fallback 그대로 + 사용자 트리거)

```ts
handleAutoCopy() {
  // 1) navigator.clipboard.writeText
  try { await navigator.clipboard.writeText(markdown); → 'success'; return; }
  // 2) textarea fallback (iOS Safari 호환 — readonly, fixed 0,0 1x1, selection range)
  // 3) 둘 다 실패 → setCopyStatus('fail') + selectAllReportText() 자동 호출
}
```

성공 시 초록 박스: **`✓ GPT 상담용 리포트를 복사했습니다.`** (3.5초 후 사라짐)

실패 시 노란 박스: **`⚠ 자동 복사에 실패했습니다. 아래 내용을 길게 눌러 복사해주세요.`** + 자동으로 본문 텍스트 선택 + 스크롤

### 2-5. [전체 선택] 동작 (사용자 명세 §4)

```ts
selectAllReportText() {
  // 1) preRef.current 의 contents 를 range 로 강제 선택
  const range = document.createRange();
  range.selectNodeContents(preRef.current);
  window.getSelection().addRange(range);

  // 2) 본문이 보이는 위치로 스크롤
  preRef.current.scrollIntoView({ behavior: 'smooth' });

  // 3) userAgent 기반 안내 분기
  const isMobile = /Android|iPhone|iPad|iPod|Mobile/i.test(navigator.userAgent);
  setSelectedHint(
    isMobile
      ? '✋ 텍스트가 선택되었습니다. 길게 눌러 [복사] 를 선택하세요.'
      : '⌨ 텍스트가 선택되었습니다. Ctrl + C (Mac: ⌘ + C) 로 복사하세요.'
  );
}
```

[전체 선택] 은 자동 복사 시도와 무관하게 사용자가 명시적으로 호출 가능. **모바일에서 자동 복사가 실패할 것을 미리 알고 처음부터 [전체 선택] → 길게 눌러 [복사] 로 해결할 수 있는 명확한 경로** 를 제공.

### 2-6. 모바일 풀스크린 모달 (사용자 명세 §5)

```html
<!-- 컨테이너: 모바일은 inset 풀 + items-stretch, PC 는 items-center + p-4 -->
<div className="fixed inset-0 z-50 flex items-stretch justify-center bg-black/40 p-2 sm:items-center sm:p-4">
  <!-- 모달: 모바일은 max-h-[100vh] (헤더부터 화면 끝까지) -->
  <div className="flex max-h-[100vh] w-full max-w-3xl flex-col rounded-lg bg-white shadow-xl sm:max-h-[90vh]">
    ...
  </div>
</div>
```

- 모바일: `inset-0 p-2 items-stretch` + `max-h-[100vh]` → 거의 풀스크린
- PC: `items-center p-4` + `max-h-[90vh] max-w-3xl` → 기존 중앙 정렬

## 4. 동작 매트릭스

### 4-1. 모바일 (Android Chrome / iOS Safari) 흐름

   - **(C)** 본문 영역을 처음부터 길게 눌러 [복사] (헤더/푸터의 항시 안내로 이미 알고 있음)

1. 사용자 [GPT 상담용 리포트 보기/복사] 클릭

3. 동일한 3 가지 선택지:
   - (A) [자동 복사 시도] → clipboard API 즉시 성공
