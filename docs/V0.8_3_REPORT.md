## 2. `stock_character.ts` 설명

`classifyStockCharacter(input)` 한 개 진입점.

### 입력
- `row: BeginnerRow | null` — 1순위 종목 행. null 가능.
- `regime: MarketRegime` — v0.6 4단계 enum.
- `conditionState: ConditionStateLite` — v0.7 전략 컨디션 (DATA_INSUFFICIENT / EXCELLENT / GOOD / AVERAGE / CAUTION / DANGER).
- `sectorFlow: SectorFlow | null` — v0.8-2 업종 흐름 + 대장주 정보.

### 출력 (`StockCharacterResult`)
- `character`: 5등급 enum
- `label`: 한글 라벨
- `narrative`: 사용자용 1~2문장 설명
- `reasoning`: 분류 근거 칩 배열
- `isActionable`: 내일 행동 대상인지 여부 (LATE_CHASE_RISK / WATCH_ONLY → false)
- `riskLevel`: LOW / MEDIUM / HIGH

### 외부 의존
- `judgeRow(row)` (`./beginner`) — U턴 통과 갯수, risk 등 활용.
- `MarketRegime`, `SectorFlow` 타입.
- 컨디션 enum은 strategy_condition 의존을 피하려고 string union 로컬 선언.

## 3. 5등급 분류 기준 (우선순위 분기)

평가 순서가 곧 우선순위. 한 등급에 해당되면 즉시 반환.

1. **`row === null`** → `WATCH_ONLY` (HIGH).
2. **`regime === 'DANGER'`** → `WATCH_ONLY` (HIGH). 시장 위험구간이면 어떤 종목이든 관망.
3. **`conditionState === 'DANGER'`** → `WATCH_ONLY` (HIGH). 전략 컨디션 위험이면 관망.
4. **`disparity_pct >= 15`** → `LATE_CHASE_RISK` (HIGH). 이격 과다.
5. **종목이 `sectorFlow.leadersBySector` 에 포함** → `LEADING_FOLLOW` (LOW/MEDIUM). 주도(또는 강한) 업종의 대장주. 준대장주(QUASI_LEADER) 포함.
6. **종목 sector 가 `sectorFlow.topThree` 에 포함** → `LATE_ENTRY` (MEDIUM). 강한 업종의 후발주.
7. **U턴 4/5 이상 또는 (거래대금 회복 + 60일선 위)** → `INDIVIDUAL_UTURN` (MEDIUM). 시장 흐름과 완전히 맞지는 않지만 개별 U턴 자체는 좋은 케이스.
8. **`value_ratio >= 8`** → `LATE_CHASE_RISK` (HIGH). 거래대금 단기 과열.
9. **그 외** → `WATCH_ONLY` (HIGH).

> 사용자 명세 §4 의 "주도주 추종 → 후발주 진입 → 개별 U턴 종목 → 끝물 추격 위험 → 관망 대상" 우선순위를 그대로 따른다. 단, `DANGER`/이격 과다처럼 절대 안전선이 있는 경우는 분류보다 먼저 컷오프한다.

## 4. `MarketFlowBox` 변경 내용

### Props 추가
```ts
stockCharacter?: StockCharacterResult | null;
topPickName?: string | null;
```

### 기본 영역 (3단 카드)
- **변경 없음.** 기존 "🌊 오늘 장 요약 / 🎯 내일 행동 / 🚫 금지 행동" 구조 그대로.

### 자세히 보기 (`<details>`) 안 추가 영역
대장주 판단 블록 다음, 마지막 항목으로:

```
🎯 1순위 종목 성격
{topPickName} — [등급 뱃지]  위험 보통
{narrative}
[근거 칩들]
※ 이 성격은 내일 신규 진입 대상에서 제외됩니다. (isActionable=false 때만)
```

- 뱃지 색상은 `CHARACTER_BADGE_CLASS` 매핑.
- 근거 칩은 `reasoning[]` 을 작은 회색 ring 칩으로.
- `isActionable === false` 면 빨간 안내 한 줄 추가 — "끝물 추격이면 1순위라도 제외" 보호 원칙을 화면에 명시.

## 5. `tomorrow_action.ts` 변경 내용

`BuildTomorrowActionInput` 에 `stockCharacter?: StockCharacterLite | null` 옵셔널 인자 추가.

분기 우선순위:
1. **`stockCharacter === 'LATE_CHASE_RISK'`** → 강제 `canEnterNew=false`, `maxNewCount=0`, intensity=NONE. 1순위라도 끝물 추격이면 신규 진입 자체를 막는다.
2. **`stockCharacter === 'WATCH_ONLY'`** → topPickName 무효화 (`effectiveTopPickName = null`). 1순위 없는 것으로 취급해 기존 분기 (보유/예약 점검 위주) 로 흘림.
3. **`stockCharacter ∈ {LATE_ENTRY, INDIVIDUAL_UTURN}` && `regime === BULL`** → 정상 BULL 분기 대신 최대 1종목 LIGHT 로 톤다운.
4. 그 외는 기존 BULL/NEUTRAL/BEAR/DANGER 분기를 유지하되, 내부에서 `topPickName` 을 직접 쓰던 모든 자리를 `effectiveTopPickName` 으로 치환.

stockCharacter 가 null 이면 동작은 v0.8-2 와 완전히 동일.

## 6. 데이터 fallback 처리

- `row == null` → WATCH_ONLY 로 안전하게 처리.
- `sectorFlow == null` → leaders / topThree 검사 모두 false 처리. 5/6 등급이 안 나오고 7→9 흐름으로 빠짐.
- `sectorFlow.insufficient === true` 라도 별도 분기 안 둠. 이미 sectorFlow 내부에서 topThree/leaders 가 비어 들어오므로 자연스럽게 INDIVIDUAL_UTURN / WATCH_ONLY 로 빠진다.
- `disparity_pct == null`, `value_ratio == null` → 해당 컷오프 통과 (LATE_CHASE_RISK 로 잘못 분류하지 않음).
- 전략 컨디션 `DATA_INSUFFICIENT` → DANGER 가 아니므로 WATCH_ONLY 자동 처리 안 함. 일반 분기로 진행 (사용자 명세상 데이터 부족만으로 컷오프하지 않음).

## 9. 테스트 방법

호스트에서:

```
npm run build
npm run dev
```

`/beginner` 접근 후:

1. 메인 3단 카드(🌊 오늘 장 요약 / 🎯 내일 행동 / 🚫 금지 행동) 가 기존과 동일하게 보이는지.
2. "자세히 보기" 펼침 → 마지막에 "🎯 1순위 종목 성격" 영역이 표시되는지.
3. 1순위 종목명 → 등급 뱃지 → 위험 라벨 한 줄.
4. 그 아래 한 줄 narrative.
5. 근거 칩들이 작게 한 줄로.
6. 시장 위험구간이거나 컨디션 위험인 날 → `관망 대상` 으로 표시되고 "내일 신규 진입 대상에서 제외" 빨간 안내 노출.
7. 이격 +15% 이상 종목이 1순위가 되면 `끝물 추격 위험` 으로 표시되고 내일 행동 카드의 maxNewCount 가 0 으로 표시되는지.
8. 1순위가 주도 업종 대장주 명단에 들어 있으면 `주도주 추종` 으로 표시되는지 (`sectorFlow.leadersBySector` 확인).
9. 1순위 sector 가 topThree 에 있는데 대장주 명단엔 없으면 `후발주 진입`.
10. 1순위 sector 가 topThree 밖인데 U턴 4/5 이상이거나 거래대금 회복 + 60일선 위면 `개별 U턴 종목`.

### 자동 검증 포인트

- 빌드 통과 시 import 매칭 OK.
- `classifyStockCharacter` 는 순수 함수 — input 동일하면 output 동일.
- 동기화: `selectedNewTargets[0]` 이 변하면 stockCharacter 도 useEffect deps (`sectorFlow`, `rows`) 에 따라 같이 재계산.
