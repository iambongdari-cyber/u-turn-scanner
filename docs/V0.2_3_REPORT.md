## 4. `/leaders` 화면 기능 요약

### 데이터 소스
- **오직 `logs/sidecar/sector_dump_latest.json`만 사용** (Supabase 미사용)
- 서버 컴포넌트에서 `fs/promises`의 `readFile`로 직접 읽음
- `path.join(process.cwd(), 'logs', 'sidecar', 'sector_dump_latest.json')`

### 화면 구성

**1) 상단**
- `←` 홈 링크
- 제목: **주도주·후발주**
- 설명: "강한 섹터 안에서 진짜 주도주 후보와 후발주 관찰 종목을 구분합니다. 관찰·복기 보조용이며 매매 권유가 아닙니다."
- 메타 표시: **시장 흐름**(색상 배지) · KOSPI 20일 수익률 · KOSDAQ 20일 수익률 · 시장 평균 20일 수익률 · 생성시각

**2) 요약 카드 (4개 그리드)**
- 강한 섹터 수 (`summary.n_sectors_strong`)
- 약한 섹터 수 (`summary.n_sectors_weak`)
- 전체 산출 종목 수 (`summary.n_stocks_with_metrics`)
- 시장 흐름 배지 카드

**3) 강한 섹터 카드 (sectors_strong 배열)**
각 섹터 카드 헤더:
- 섹터명
- 종목 수 (`n_stocks`)
- 섹터 20일 수익률 (`sector_20d_return`) 배지
- 시장 대비 상대강도 (`market_relative_strength`) 배지

분류 카운트 배지 (한 줄):
- 🥇 진짜 주도주 후보 N
- 🥈 후발주 관찰 N
- 🎯 기회 후보 N
- ⚠️ 추격 위험 N
- 보유자 대응 N (있을 때)
- 조건 부족 N (있을 때)

**4) 섹터 카드 내부 4개 분류 섹션**

| 분류 | 아이콘 | 색상 | 설명(섹션 헤더 아래 표시) |
|------|--------|------|--------------------------|
| 진짜 주도주 후보 | 🥇 | amber | "같은 섹터 안에서 60일선 위 + 전고점 근접 + 거래대금 임계 충족 + 이격 한계 내 종목" |
| 후발주 관찰 | 🥈 | sky | "같은 섹터 강세에서 위를 따라가는 종목(전고점 70~90% 부근)" |
| 기회 후보 | 🎯 | emerald | "60일선 위에서 거래대금 임계는 충족하지만 주도주·후발주 기준에는 미달" |
| 추격 위험 | ⚠️ | orange | "이격 +20% 이상 — 추가 진입은 추격 위험 영역" |

**5) 각 종목 표시 항목 (MemberRow)**
- 종목명 + 종목코드 (클릭 시 기존 `/stocks/[ticker]`로 이동)
- 배지 그룹 (tabular-nums, ring 처리):
  - 20일 수익률 (`return_20d`, 부호 포함)
  - 전고점 근접도 (`near_high_pct`)
  - 20일 평균 거래대금 (`value_20d_eok`, "X.X억")
  - 이격도 (`disparity_pct`, 부호 포함)
  - 60일선 위/아래 (`above_ma60`, 위=초록·아래=주황 배지)
- **`evidence` 라벨이 있으면** emerald 칩으로 모두 표시 (현재 sector_dump 출력엔 미포함, 향후 확장 시 자동 표시)
- 우하단 "종목 상세 →" 링크

**6) 약한 섹터 보조 섹션 (sectors_weak)**
- `<details>` 네이티브 접힘 요소로 처리 — 기본 접힌 상태
- 헤더: "약한 섹터 보조 보기 N개 — 조건 부족 / 보유자 대응 참고용"
- 펼치면 섹터별 한 줄 요약(섹터명 · 섹터 20일 수익률 · 상대강도 · 종목 수 · 조건 부족/보유자 대응 카운트)
- 카드보다 작은 톤 — 신규 관심 후보가 아닌 **참고용**임을 시각적으로 약화

**7) 하단 톤 안내 박스**
- "본 화면은 '오늘 살 종목'을 추천하는 화면이 아닙니다."
- "강한 섹터 안에서 돈의 흐름을 확인하고, 주도주와 후발주를 구분하기 위한 관찰·복기 보조 화면입니다."
- "어떤 표시도 매매 권유가 아니며, 최종 판단은 사용자 본인이 합니다."

## 5. JSON 파일 부재 / 손상 시 처리 방식

`/bottom-watch`와 동일한 패턴의 `LoadResult` 3분기:

```typescript
type LoadResult =
  | { status: 'ok'; data: DumpData }
  | { status: 'missing' }
  | { status: 'parse_error'; message: string };
```

| 케이스 | 트리거 | 표시 |
|--------|--------|------|
| **파일 없음** | `fs.readFile` 예외(ENOENT 등) | 노란 안내 박스 — "아직 주도주·후발주 데이터가 없습니다. 먼저 `scripts/sector_dump.py`를 실행해 사이드카 JSON을 생성해 주세요." |
| **JSON 파싱 실패** | `JSON.parse` 예외 | 빨간 안내 박스 — "주도주·후발주 데이터를 읽는 중 문제가 발생했습니다. `sector_dump_latest.json` 파일을 다시 생성해 주세요." |
| **정상** | 파싱 성공 | 본 화면 정상 표시 |

세 케이스 모두 페이지가 절대 깨지지 않고 graceful 응답.

## 부록 — 화면 톤 원칙 재확인

이 화면은 **"오늘 살 종목"을 추천하는 화면이 아닙니다.**

반드시 **"강한 섹터 안에서 돈의 흐름을 확인하고, 주도주와 후발주를 구분하기 위한 관찰·복기 보조 화면"** 이라는 톤을 유지합니다.

- 강한 섹터 카드는 강조하되, 카드 안의 분류는 4가지 모두 동등하게 노출(주도주만 강조하지 않음 — 후발주·기회·추격 위험을 함께 봐야 의미가 있음).
- 약한 섹터는 `<details>` 접힘으로 작게 처리해, **신규 진입 후보가 아니라 보유자 대응·조건 부족 참고용**임을 시각적으로 명확히.
- 어떤 표시도 매매 권유가 아니며, 가격을 제시하거나 시점을 권하지 않습니다.
