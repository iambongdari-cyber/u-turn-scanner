> **작성 기준일:** 2026-06-03
> **선행 커밋:** v0.3-5 `99031c8`

## 1. 작업 목적

v0.3-5까지 홈 카드는 "오늘"의 사이드카 latest만 보여줄 수 있었다. "어제 대비 변화"(예: U턴 확인 어제 25 → 오늘 30, 강한 섹터 출현/이탈) 를 보여주려면 **어제 데이터가 같은 디스크에 보존**되어 있어야 한다.

이번 v0.3-6은:
1. 별도 스크립트 `scripts/archive_sidecar.py`로 latest 두 파일을 `logs/sidecar/daily/`에 복사.
2. `run_sidecar.bat` (2→3 단계) 및 `run_daily.bat` (11→12 단계)에 **WARN-only 단계**로 통합.
3. 기존 분석/필터/JSON 구조는 일체 손대지 않는다(단순 복사).

이 단계가 안정적으로 매일 쌓이면, v0.3-7에서 어제 스냅샷을 읽어 홈에 변화량을 표시할 수 있다.

## 3. 실행 흐름

### `run_sidecar.bat` (단독 사이드카 재생성용)
```
[1/3] scan_dump.py        → logs/sidecar/scan_dump_latest.json
[2/3] sector_dump.py      → logs/sidecar/sector_dump_latest.json
[3/3] archive_sidecar.py  → logs/sidecar/daily/scan_dump_<date>.json
                          → logs/sidecar/daily/sector_dump_<date>.json
Final file check
Done: SCAN_STATE / SECTOR_STATE / ARCHIVE_STATE
```

### `run_daily.bat` (전체 일일 파이프라인)
```
[1/12] Refreshing stock master
[2/12] Updating daily prices
[3/12] Updating market indices
[4/12] Updating news risks
[5/12] Running DAILY scan
[6/12] Running WEEKLY scan
[7/12] scan_dump sidecar              (WARN-only)
```

## 4. 생성 파일 구조

작업 후 `logs/sidecar/` 트리:
```
logs/sidecar/
├── scan_dump_latest.json          (v0.2-1부터 존재, 무변경)
├── sector_dump_latest.json        (v0.2-1부터 존재, 무변경)
└── daily/                         ← v0.3-6 신규
    ├── scan_dump_2026-06-02.json
    ├── scan_dump_2026-06-03.json
    ├── sector_dump_2026-06-02.json
    └── sector_dump_2026-06-03.json
    (매일 2개씩 누적)
```

**파일명 규칙**: `<prefix>_<YYYY-MM-DD>.json`
- `<prefix>` ∈ {`scan_dump`, `sector_dump`}
- `<YYYY-MM-DD>` 날짜 결정 우선순위(둘 다 KST 기준):
  1. JSON 내부 `base_date` (스캔 사이드카는 이 키가 존재 — v0.3-5 §부록 참조)
  2. latest 파일의 mtime을 KST로 변환한 날짜
  3. 위 둘 다 실패 시 오늘 KST 날짜

**실제 호스트 검증 결과** (작업 시점, 2026-06-03):
```
$ python3 scripts/archive_sidecar.py
[archive_sidecar] scan snapshot saved: logs/sidecar/daily/scan_dump_2026-06-02.json
[archive_sidecar] sector snapshot saved: logs/sidecar/daily/sector_dump_2026-06-03.json
[archive_sidecar] done
exit code: 0
```
- scan은 JSON 내부 `base_date=2026-06-02` 그대로 사용 ✓
- sector는 `base_date` 키 없어서 mtime KST=2026-06-03 사용 ✓ (graceful fallback)

## 5. 덮어쓰기 정책

| 정책 | 동작 |
|------|------|
| 같은 날짜 파일 이미 존재 | **덮어쓴다** (`shutil.copy2`) |
| 이유 | 하루에 `run_daily.bat`를 여러 번 돌릴 수 있으므로, **latest와 daily snapshot이 일치하는 것**이 비교 화면 일관성에 안전 |
| 부작용 | 같은 날짜의 직전 실행본은 사라짐 — 단, latest와 항상 일치 보장 |

이 정책은 v0.3-7 비교 화면이 "오늘 (latest) vs 어제 (daily)"을 비교할 때 **latest와 daily의 같은 날짜 파일이 절대 어긋나지 않게** 하기 위함이다. 직전 실행본 보존이 필요해지면 v0.3-6+에서 timestamp suffix 정책으로 분리 검토.

## 6. WARN-only 실패 처리

`archive_sidecar.py`는 **어떤 경우에도 종료 코드 0**을 반환한다.

### 코드 차원 보증
- `archive_one()` 내부에서 모든 예외를 `try/except`로 가로채고 `[WARN] … failed: <reason>` 출력 후 `False` 반환.
- `main()`은 두 파일 결과와 무관하게 `print('[archive_sidecar] done')` + `sys.exit(0)`.

### 배치 차원 보증
- `run_sidecar.bat [3/3]`, `run_daily.bat [9/12]` 모두 다음 패턴:
```bat
if errorlevel 1 (
    echo [WARN] archive_sidecar failed. Continue to ...
    set "ARCHIVE_STATE=failed-continue"   :: run_sidecar.bat
    echo   [9] archive sidecar: failed-continue>>"%LOGFILE%"   :: run_daily.bat
) else (
    set "ARCHIVE_STATE=ok"                :: run_sidecar.bat
    echo   [9] archive sidecar: ok>>"%LOGFILE%"   :: run_daily.bat
)
```
- **`goto :end` 호출 0건** — 자동 검증으로 `[9/12]~[10/12]` 사이 매칭 0건 확인.
- archive 실패해도 백테스트/알림/웹서버는 정상 진행.

### Python 단독 검증 결과
| 시나리오 | 결과 |
|---|---|
| 둘 다 정상 | `scan snapshot saved` + `sector snapshot saved` + exit 0 ✓ |
| 둘 다 부재 | `[WARN] scan_dump_latest.json missing, skipped` + `[WARN] sector_dump_latest.json missing, skipped` + exit 0 ✓ |
| 한쪽만 부재 | 다른 하나는 정상 복사 + exit 0 ✓ |
