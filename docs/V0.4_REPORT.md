# U-Turn Scanner — v0.4 구현 보고서 (오늘의 투자판단)

> **작성일:** 2026-06-13
> **기준 문서:** `V0.4_DESIGN_REVISED_5.md`
> **요청:** 사용자의 실제 매매 흐름(키움 예약매수 → 일상 → 체결 → 보유관리 → 매도가 재계산 → 추가매수 검토)을 기록하고 이어주는 "개인 투자 리더 화면" 구현.

---

## 1. 구현 요약

v0.4 의 핵심은 단순 종목 추천기가 아니라, **사용자의 실제 매매 흐름을 기록하고 이어주는 개인 투자 리더 화면** 구현입니다. `/beginner` 한 화면에 (1) 오늘의 1픽 (2) 내 예약매수 대기 (3) 내 보유종목 점검 (4)~(6) 3 카테고리 후보 (7) 놓친 리포트 (8) GPT 리포트 복사 — 총 8 영역을 순서대로 노출해, 퇴근 후 10분 안에 오늘 해야 할 행동을 확인할 수 있게 했습니다.

핵심 데이터 구조는 `TradePlan` 28 필드 (식별 3 + 매매계획 8 + AI 판단 2 + 상태/체결 9 + 채점 스냅샷 1 + 변경 이력 2 + 추가매수 체크 1 + 메모 1 + 타임스탬프 2) 입니다. 8 단계 매매 상태 (`관찰중 / 예약매수 대기 / 1차 체결 / 2차 체결 / 보유중 / 일부매도 / 매도완료 / 취소`) + 7 라벨 AI 판단 (`관찰 / 매수 / 보유 / 일부매도 / 매도 / 제외 / 추가매수 대기`) + 목표가·손절가 변경 이력 + 추가매수 4 조건 자동 평가까지 모두 한 인터페이스 안에서 다뤄집니다.

데이터 저장은 **localStorage 키 `tradePlans`** 만 사용 — Supabase write 0건, 키움 API 0건, 자동매매 0건, 실제 주문 버튼 0건. 사이드카 JSON 구조 / 기존 5 화면 / 스캔 산식 / Python 스크립트 모두 무변경.

## 8. 보유종목 점검 흐름

```
[Day 1 → Day N /beginner 진입]
  - "📦 내 보유종목 점검" 섹션에 표시
  - 평균매수가 자동 계산 (calculateAvgBuyPrice — 1차/2차 단순 평균)
  - 현재 수익률 = (현재가 - 평균매수가) / 평균매수가 × 100
  - buildHoldingOpinion(plan, currentPrice, add_buy_check):
    · 현재가 ≥ 목표가 → 일부매도 (AI 판단)
    · 현재가 ≤ 손절가 → 매도
    · add_buy_check.passed_count ≥ 4 → 추가매수 대기
    · 그 외 → 보유

[목표가/손절가 변경]
  - [수정] 버튼 → PriceChangeModal
  - 변경 이유 필수 (빈 칸이면 저장 거부)
  - 추천 이유 칩 12 개 (상향/하향 × 목표가/손절가)
  - target_change_history / stop_loss_change_history 에 누적
  - 카드 안 "변경 이력" 영역에 최근 3 개 표시

[추가매수 검토 — AddBuyCheckBox]
  - ① 1차 매수가 위 유지 — 자동 (currentPrice ≥ first_buy_price)
  - ② 거래량 급감 없이 눌림 — 자동 (value_ratio ≥ 0.7)
  - ③ 60일선 지지선 이탈 없음 — 자동 (currentPrice ≥ ma60 × 0.97)
  - ④ 총 투자금 한도 초과 없음 — 사용자 직접 토글
  - 4/4 → 추가매수 검토 가능
  - 2~3/4 → 추가매수 대기
  - 0~1/4 → 추가매수 금지
  - 평가 결과 자동 저장 (saveAddBuyCheck)

[2차 매수 진입]
  - [2차 체결 추가] 클릭 → 실제 2차 체결가 입력
  - status: HOLDING → SECOND_FILLED → HOLDING (자동 분류)
  - 평균매수가 재계산

[일부 매도]
```
